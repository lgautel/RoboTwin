# 面向教师与家长的小学教育与儿童心理发展 RSI 顾问系统选型与改造方案

> 分析日期:2026-10-13。
> 本文基于以下材料的综合分析:
> - [`rsi_analyz1.markdown`](./rsi_analyz1.markdown):通用 RSI 领域对比分析(44+ 项工作,第三版)
> - [`rsi_edu_analyz1.markdown`](./rsi_edu_analyz1.markdown):RSI 在儿童教育与心理发展领域的对比分析(20+ 项工作)
> - [`rsi_edu_solu1.markdown`](./rsi_edu_solu1.markdown):面向儿童的 RSI 教育系统方案(作为对比参照)

> 本文的目的是:从上述报告覆盖的 50+ 项工作中,选出 1-3 项作为基础,设计一个面向**教师与家长**(而非直接面向儿童)的 RSI 顾问系统,覆盖**小学教育**与**儿童心理发展**两个维度。
>
> 核心约束:**系统不直接面对儿童**。用户是教师和家长,系统为他们提供教学策略建议和儿童心理发展指导。

## 1. 场景定义:为什么"面向教师/家长"是一个根本不同的问题

### 1.1 与 rsi_edu_solu1(面向儿童)的关键区别

[`rsi_edu_solu1.markdown`](./rsi_edu_solu1.markdown) 选了 GEPA + DeepTutor + PedagogicalRL,构建一个直接面向 6-12 岁儿童的自适应导师系统。本文的场景从根本上不同:

| 维度 | rsi_edu_solu1(面向儿童) | 本文(面向教师/家长) |
|---|---|---|
| **直接用户** | 6-12 岁小学生 | 教师和家长(成人) |
| **系统角色** | 自适应导师:直接教孩子 | 顾问:帮成人更好地教育和理解孩子 |
| **优化对象** | 面向儿童的教学提示和脚手架 | 面向成人的教学策略文档和心理发展指导 |
| **谁来验证** | 需要独立安全评估器 + 教师监督 | 教师/家长本身就是天然的人在回路验证者 |
| **语言复杂度** | 必须按年级硬限制(1-2 年级不超过 3 句) | 无限制——成人能处理复杂文本 |
| **情感依赖风险** | 关键风险(UNICEF 2026 警告) | 系统层面不适用(成人不会对顾问工具产生儿童式情感依赖) |
| **LLM 评审偏差** | 高风险(LLM 偏好"更长更复杂"= 对儿童有害) | 风险较低(对成人来说更详细的建议可能确实更好) |
| **安全模型** | 直接暴露:系统输出直接到达儿童 | 间接影响:错误建议经由成人传递才影响儿童 |
| **RSI 机制可用范围** | 保守(儿童安全约束限制了优化空间) | 可以更积极地探索(成人能判断建议质量) |
| **平台需求** | 需要完整自适应导师平台(DeepTutor) | 不需要——标准顾问工具即可,无需导师平台 |
| **模型训练需求** | 需要 RL 训练教学模型(PedagogicalRL) | 不需要——系统不直接教学生,不需要教学行为训练 |

**关键推论**:rsi_edu_solu1 之所以选 3 项工作(引擎 + 平台 + 训练方法),是因为需要构建一个完整的面向儿童的产品。本文的场景不需要自适应导师平台,也不需要训练面向学生的教学模型。需要的只是两件事:
1. 一个能持续改进教学/心理建议质量的**自改进引擎**。
2. 一个能防止建议质量退化的**质量门控机制**。

### 1.2 用户画像:小学教师与家长

#### 教师

- **专业需求**:分层教学策略(同一班级不同水平的学生怎么教)、课程对齐(建议必须与课标匹配)、课堂管理中的心理干预(学生情绪问题在课堂中如何处理)、特殊需求学生的识别与初步支持。
- **时间约束**:忙碌,需要**可操作的具体建议**而非学术论述。
- **信息偏好**:重视同行经验和证据支持,但对长篇理论缺乏耐心。
- **验证能力**:有专业判断力,能评估教学建议的合理性;对心理发展领域的判断力因培训背景而差异较大。

#### 家长

- **专业需求**:家庭学习辅导方法(如何帮孩子做作业而不是替孩子做)、行为问题应对(孩子拒绝做作业、社交困难、注意力问题)、发展里程碑理解(孩子的行为是否在正常范围内)、何时寻求专业帮助。
- **时间约束**:碎片化,通常在遇到具体问题时才使用系统。
- **信息偏好**:需要通俗易懂但有依据的建议,对"每个孩子不同"这类空洞回答缺乏耐心。
- **验证能力**:对教育和心理学的专业判断力有限,但对自己孩子的行为有第一手观察。

#### 两者的共同点

- 都是**成人**,能处理复杂信息,能对建议质量做判断。
- 都是**间接影响者**——系统的建议通过他们的行动才作用于儿童。
- 都希望系统**越来越了解他们的具体情境**(班级情况、家庭状况),给出更有针对性的建议。

### 1.3 系统功能需求

| 维度 | 子维度 | 面向教师的功能 | 面向家长的功能 |
|---|---|---|---|
| 教育 | 教学策略 | 分层教学方案、差异化教学设计、形成性评估方法 | 家庭学习辅导方法、作业陪伴策略、学习习惯培养 |
| 教育 | 学科指导 | 各学科常见概念误解及纠正策略、教学资源推荐 | 如何解释某个知识点、如何判断孩子是否真正理解 |
| 心理 | 情绪与社交 | 课堂情绪事件的即时处理、同伴关系问题的干预 | 孩子情绪爆发的应对、社交困难的家庭支持 |
| 心理 | 认知发展 | 不同年龄段的认知特征与对应教学方式 | 发展里程碑参照、何时该担心何时不必担心 |
| 心理 | 问题识别 | 学习障碍、注意力缺陷、焦虑等的早期信号识别 | 行为问题的可能原因分析、是否需要专业评估 |
| 沟通 | 家校协作 | 如何与家长沟通孩子的问题 | 如何与教师有效沟通 |

### 1.4 安全约束重新定义:间接影响模型

与 rsi_edu_solu1 的直接暴露模型不同,本系统的安全模型是**间接影响**:

```
系统 → 建议 → 教师/家长 → 行动 → 儿童
```

**影响链中教师/家长是天然的安全缓冲**:他们会用自己的判断过滤不合理的建议,不会机械地执行系统的每一条指示。但这不意味着安全问题消失——而是安全问题的性质发生了变化:

1. **核心风险不再是"不当输出直接到达儿童"**,而是**"错误建议被成人采纳后间接伤害儿童"**。例如:建议家长对孩子的焦虑"别在意,长大就好了"——这条建议本身对成人无害,但如果被采纳可能延误干预。

2. **不需要**:语言复杂度控制、情感依赖预防(系统级)、儿童专用安全评估器(KIDBench 等)、单次交互时长限制。

3. **仍然需要**:
   - **证据锚定**:建议必须有发展心理学和教育研究的证据支持,不能给出"听起来有道理但无依据"的建议。
   - **保护类别**:某些建议类别必须固定、不可被自改进修改——疑似虐待/忽视时必须建议寻求专业帮助、心理危机时必须建议立即干预、不得建议替代医学诊断或治疗。
   - **不确定性透明**:系统必须明确告知建议的确定程度,不能把推测性建议包装成确定性结论。
   - **转介机制**:当问题超出系统能力范围时,明确建议寻求专业人员(心理咨询师、特殊教育教师、医生)。

4. **SIC-Agents 的消融警告仍然适用**(见教育报告 [SIC-Agents 分析](./rsi_edu_analyz1.markdown)):去掉领域课程指导后,自改进让系统"更流畅"但侵蚀关键行为。在本场景中,这意味着:没有教育心理学原则约束的自改进,可能让建议"听起来更专业"但偏离循证实践。间接影响模型下,这种漂移更难被察觉——因为成人用户可能被"更专业的语气"说服而采纳错误建议。

### 1.5 自改进的对象:教学策略与心理支持知识文档

明确列出系统中**被自改进回路优化**的东西:

| 类别 | 示例 | 形式 |
|---|---|---|
| 教学策略文档 | "帮助 8 岁学生理解分数:通过具体操作物建立直观理解的 5 步引导法" | 300-2000 token 的结构化文本 |
| 心理发展指导文档 | "识别和应对小学生考试焦虑:给教师的 7 条循证建议" | 结构化文本,含文献引用 |
| 情境应对剧本 | "当家长报告孩子拒绝做作业时:诊断问题、分析可能原因、推荐分步应对" | 决策树 + 文本 |
| 发展里程碑参照 | "6-7 岁社交情绪发展的正常范围与值得关注的信号" | 结构化文本,含临床参照 |

**不被自改进优化**的东西(固定层):
- 保护类别的建议(疑似虐待/忽视、心理危机、医学转介)
- 教育心理学基本原则(如"表扬努力而非天赋"、"不同年龄段的认知发展阶段")
- 法律法规和伦理约束(如数据隐私、监护人权利)

这些被固定的内容构成 SIC-Agents 意义上的"课程指导"——自改进回路在它们划定的边界内优化,但不能修改边界本身。

## 2. 选型标准

### 2.1 五维选型标准

| 维度 | 权重 | 含义 | 与 rsi_edu_solu1 的差异 |
|---|---|---|---|
| 知识文档优化能力 | 30% | 能否有效优化文本形式的教学策略和心理指导文档?反思和诊断能力如何? | 替代了 edu_solu1 的"场景适配度"(30%)。edu_solu1 的场景是"面向儿童的自适应导师",需要评估能否适配儿童交互;本文的场景是"优化给成人的知识文档",核心能力需求不同 |
| 质量门控严格度 | 25% | 是否有严格的留出验证机制?能否确保更新不退化?产物是否人类可审计? | 替代了 edu_solu1 的"工程可建设性"(25%)。edu_solu1 需要构建完整产品,所以工程可建设性很重要;本文不需要导师平台,门控严格度是安全的关键 |
| 工程成熟度与可组合性 | 20% | 代码是否开源、可用、有文档?能否与其他组件组合?部署成本多高? | 与 edu_solu1 的"自改进机制强度"(20%)对应。本文将工程成熟度放在这里,因为一个面向教师/家长的系统需要稳定可靠 |
| 证据质量与同行认可 | 15% | 顶会/顶刊背书?有无第三方复现?结果可信度? | 与 edu_solu1 相同(15%) |
| 人在回路兼容性 | 10% | 设计是否天然支持人类审计、编辑和回滚? | 替代了 edu_solu1 的"安全兼容性"(10%)。本文的安全通过间接影响模型实现,核心是人在回路——教师/家长能看懂、能改、能回滚 |

### 2.2 标准差异的原因

rsi_edu_solu1 的标准围绕"如何安全地让 AI 直接教孩子"设计,因此"场景适配度"(能否与儿童交互)和"安全兼容性"(能否保护儿童)是核心。

本文的标准围绕"如何让 AI 给成人提供越来越好的教育/心理建议"设计。成人用户本身就能判断建议质量(天然的人在回路),不存在直接暴露风险,所以:
- "知识文档优化能力"取代了"场景适配度":场景是确定的(优化文本文档),关键是优化能力。
- "质量门控严格度"取代了"工程可建设性":不需要构建导师平台,但必须确保建议质量不退化(这是间接影响下的安全保障)。

## 4. 逐项深入分析

### 4.1 GEPA:最均衡的自改进引擎

**能力贡献**:
- GEPA 让 LLM 以自然语言反思执行轨迹,诊断问题、提出提示/策略更新,并从 Pareto 前沿中合并互补经验。
- 6 项任务上平均比 GRPO 高 6pp,rollout 最多少 35 倍,比 MIPROv2 高 10pp 以上(论文自报)。
- 已内置于 [DSPy](https://dspy.ai/current/api/optimizers/GEPA/overview/),有 Shopify、Databricks 等企业采用(官方宣称)。
- ICLR 2026 Oral,MIT 许可证,[`gepa-ai/gepa`](https://github.com/gepa-ai/gepa) 6957 star / 575 fork,维护活跃至 2026-10-12。

**面向教师/家长顾问场景的适配评估**:

GEPA 的"反思式诊断"映射到本场景的方式非常自然:
- 教师使用系统的建议帮助学生 → 反馈"这个分数教学策略在实际课堂上效果不好,因为..." → GEPA 分析轨迹 → 诊断"当前策略假设学生已掌握分数概念的前置知识,但实际上许多学生在等分概念上就有误解" → 提出更新后的策略。
- 家长反馈"你说的应对方法我试了,孩子更抵触了" → GEPA 分析上下文 → 诊断"当前建议忽视了孩子处于叛逆期的可能性,使用了对更小年龄段有效但对 10 岁以上可能适得其反的策略"。

GEPA 的 Pareto 前沿在本场景中支持多维平衡:
- "课堂可操作性" vs "教育学理论严谨度"(教师场景)
- "家庭可执行性" vs "心理发展循证程度"(家长场景)
- "问题针对性" vs "安全保守度"(两者共有)

**风险**:
- GEPA 没有显式的"留出验证门"——改进由 Pareto 前沿管理,但不保证每次更新都严格优于前一版本。这在本场景中意味着建议质量可能波动而非单调改进。
- 评估函数设计是关键:教学/心理建议的"好坏"比编码任务模糊得多,评估函数的质量直接决定 GEPA 优化的方向。

**结论**:保留,作为自改进引擎的首选。

---

### 4.2 SkillOpt:最严格的质量门控

**能力贡献**:
- 把技能文档当作冻结 Agent 的可训练外部状态,用独立的优化器模型训练它。
- 6 基准 × 7 模型 × 3 环境共 52 格全部最佳或并列最佳(论文自报)。
- **严格的留出验证门**:只有在留出验证集上的分数**严格提升**时才接受编辑。有文本学习率预算、被拒编辑缓冲、按 epoch 的慢速/元更新。
- 产物是 300-2000 token 的人类可读 `best_skill.md`,部署时零额外推理调用。
- MIT 许可证,PyPI 包 `skillopt`,[`microsoft/SkillOpt`](https://github.com/microsoft/SkillOpt) 18282 star / 1726 fork,2026-10-06 仍在更新。

**面向教师/家长顾问场景的适配评估**:

SkillOpt 的"技能文档作为可训练参数"范式与本场景有精确映射:

| SkillOpt 概念 | 本场景映射 |
|---|---|
| 技能文档 | 教学策略文档 / 心理发展指导文档 |
| 冻结的 Agent | 基座 LLM(GPT/Claude/Gemini),不修改权重 |
| 留出验证集 | 专家编写的教学/心理情境标准案例 |
| `best_skill.md` | 当前最优的教学策略或心理指导文档 |
| 优化器模型 | 生成策略更新提案的 LLM |

SkillOpt 的留出验证门在本场景中的价值不仅是性能保障,更是**间接安全保障**:
- 建议质量在留出场景上严格只升不降 = 不会因为自改进而退化到给出比初始版本更差的建议。
- 留出场景可以包含**高风险情境**(疑似虐待、心理危机、发展异常),确保这些场景的建议质量永远不退化。

**SkillOpt 产物的人类可读性在本场景中尤其重要**:
- 教育心理学专家可以直接阅读和审核优化后的策略文档,不需要技术背景。
- 有经验的教师可以基于实践直觉判断策略文档是否合理。
- 家长也能理解策略文档的内容(因为是面向成人的自然语言文本)。
- 任何人发现问题都可以手动编辑或回滚。

**与 GEPA 的互补性**:
- GEPA 擅长**诊断问题和提出更新**(反思式的"为什么这个建议不够好,应该怎么改")。
- SkillOpt 擅长**验证更新和保证不退化**(严格的"只有确实变好了才接受")。
- GEPA 提议,SkillOpt 把关——这种组合比任何一个单独使用都更可靠。

**风险**:
- SkillOpt 的优化器是固定的统计过程,不会"理解为什么这次建议失败"。单独使用 SkillOpt,优化方向取决于留出验证集的设计质量,缺乏 GEPA 的语义诊断能力。
- 留出验证集的构建需要教育心理学专家深度参与,这是一个非技术瓶颈。
- 论文的会议接收状态未核实(通用报告第 9 节标注)。

**结论**:保留,作为质量门控的首选。与 GEPA 形成"提议-把关"的互补。

---

### 4.3 ACE:低成本适配,但被 GEPA 覆盖

**能力贡献**:
- Playbook 增量演化——把上下文工程看作持续迭代的"剧本",通过 generate/reflect/organize 三角色不断改进。
- Agent 任务 +10.6%,金融任务 +8.6%(论文自报)。
- ICLR 2026,Apache-2.0,[`ace-agent/ace`](https://github.com/ace-agent/ace) 1360 star / 169 fork。

**适配评估**:
- ACE 的 Playbook 概念映射到"教学情境应对剧本"很自然。
- 但 ACE 的反思和诊断能力弱于 GEPA,且没有 SkillOpt 的留出验证门。
- 它的 Playbook 增量演化可以视为 GEPA 的简化版——GEPA 已经覆盖了 ACE 的核心能力,而且做得更好。

**结论**:不选。GEPA 在反思诊断和多目标优化上严格优于 ACE。ACE 的 Playbook 概念在改造方案中可以作为文档组织方式的参考,但不需要作为独立的基础工作。

---

### 4.4 GenericAgent:知识积累模式参考,非基础工作

**能力贡献**:
- 最小化原子工具集(9 个),层级化按需记忆,验证轨迹沉淀为可复用 SOP 和可执行代码。
- SOP-Bench / Lifelong AgentBench 100%,总 token 约为 Claude Code 的 35%(论文自报)。
- MIT,[`GenericAgent/GenericAgent`](https://github.com/GenericAgent/GenericAgent) 14304 star / 1663 fork。

**适配评估**:
- GenericAgent 的"验证轨迹沉淀为可复用 SOP"映射到本场景:当教师反馈某个教学策略在实际课堂上效果很好时,这个验证过的策略被沉淀为可复用的教学方案。
- 层级化记忆映射到:按年级 → 学科 → 知识点 → 问题类型组织教学策略文档。
- 但 GenericAgent 的核心价值是"知识积累和组织"而非"知识优化"。SkillOpt 的 `best_skill.md` 已经是积累的产物,GEPA 负责优化。GenericAgent 的模式可以作为**文档组织和检索**的参考,不需要作为独立基础。

**结论**:不选为基础工作。其"验证轨迹 → SOP"和"层级记忆"设计模式在改造方案的文档体系设计(6.2 节)中被参考。

---

### 4.5 SIC-Agents:最重要的安全设计范本

**能力贡献**:
- 可编辑技能文档 + LLM 裁判选择 + 技能编辑器改写 + Coach Agent 课程指导。
- EMNLP 2026 录用。
- **关键消融发现**:去掉 Coach 课程指导后,PitfallBench 精度**下降到低于初始种子**,而对话流畅度(grounding)反而继续上升。

**为什么不选为基础工作**:
- SIC-Agents 的代码没有完整公开(只有 benchmark [`Beikewzh/sic-benchmarks`](https://github.com/Beikewzh/sic-benchmarks),0 star / 0 fork),无法直接使用。
- 它服务的是临床医生培训,与教师/家长顾问场景的领域不同(尽管设计模式高度可迁移)。
- GEPA + SkillOpt 已经提供了自改进引擎和质量门控,SIC-Agents 的核心贡献是**课程指导这个设计模式**,不需要作为独立的工程基础。

**为什么必须借鉴**:
- SIC-Agents 的消融发现是本方案中**最重要的安全参考**。它直接证明了:无领域指导的自改进会产生"听起来更好但实际更差"的结果。
- 在教师/家长顾问场景中,这个风险的表现形式是:系统的建议变得"更流畅、更自信、更有说服力",但偏离了循证的教育心理学原则。由于用户是成人(可能被专业语气说服),这种漂移比在儿童场景中**更难被察觉**。
- 课程指导在本方案中的实现方式:在 GEPA 的优化循环中注入教育心理学基本原则作为**不可动摇的约束**。

**结论**:不选为基础工作(代码不可用),但其课程指导设计模式**必须**整合进改造方案。

---

### 4.6 PsychAgent:方法论参考,不选

**能力贡献**:
- 记忆增强的规划引擎 + 技能演化引擎(从历史咨询轨迹中抽取新技能)+ 强化内化引擎(拒绝采样微调)。
- PsychEval 上多项指标最优(论文自报)。
- [`ECNU-ICALK/PsychAgent`](https://github.com/ECNU-ICALK/PsychAgent) 18 star / 5 fork,无许可证。README 声明"不含完整训练资产与完整的会后技能演化流水线"。

**适配评估**:
- PsychAgent 的"从历史咨询轨迹中抽取新技能"在概念上可迁移到"从教师/家长交互轨迹中抽取有效的教学/心理策略"。
- 但它面向成人心理咨询,没有儿童/青少年验证。教育报告明确指出"年龄阶段不可外推"。
- 代码不完整(仓库自述),属于研究代码而非可建设的基础。
- 它的"技能演化"可以被 GEPA 的通用优化能力覆盖——GEPA 在本质上做的就是"分析轨迹 → 抽取经验 → 改进策略",只是用反思式诊断而非显式的技能抽取。

**结论**:不选。GEPA 覆盖了其核心能力。"从轨迹中抽取策略"这个思路在改造方案中会被参考,但不需要 PsychAgent 作为独立基础。

## 5. 最终推荐:2 项基础工作

### 5.1 为什么是 2 项而不是 3 项

rsi_edu_solu1 选了 3 项(GEPA + DeepTutor + PedagogicalRL),因为面向儿童的系统需要:
1. 自改进引擎(GEPA)
2. 自适应导师平台(DeepTutor)——用户管理、学习者画像、知识库、出题、交互界面
3. 导师模型训练方法(PedagogicalRL)——让底层 LLM 具有教学行为能力

本文推荐 2 项而非 3 项,原因是:

**DeepTutor 在本场景中不需要**。教师/家长是成人用户,不需要自适应导师平台的基础设施(学习者画像、出题引擎、脚手架交互、语言复杂度控制)。一个标准的顾问工具(对话界面 + 知识库 + 反馈收集)足以作为产品骨架,工程量小很多,不需要在一个已有的导师平台上做大幅改造。

**PedagogicalRL 在本场景中不需要**。系统不直接面向学生教学,不需要训练"教学行为能力"。系统需要的是"给出好的教学建议的能力",而这更接近"知识文档的质量"(SkillOpt 的领域)和"诊断问题的能力"(GEPA 的领域),而非"在课堂上一步步引导学生思考的能力"(PedagogicalRL 的领域)。

**领域知识是内容,不是 RSI 机制**。教育学和发展心理学的专业知识(课标对齐、认知发展阶段、情绪管理策略等)应该来自专家编写的知识库、循证研究文献和结构化数据(如 [KidMind](https://github.com/wtiantianw/KidMind) 的 33.7k 条指令数据),而不是来自某个 RSI 基础工作。把"领域知识来源"和"RSI 机制"混为一谈是一个范畴错误。

因此,只需要 2 项工作:一个负责"让建议越来越好"(GEPA),一个负责"确保建议不退化"(SkillOpt)。

### 5.2 推荐 1:GEPA — 自改进引擎

| 维度 | 评分(1-5) | 依据 |
|---|---|---|
| 知识文档优化能力 | 5 | 反思式诊断能力直接适用于"分析为什么建议不够好";Pareto 前沿支持多目标平衡;通用优化器可对任何文本组件做进化 |
| 质量门控严格度 | 3 | Pareto 前沿管理改进方向,但没有显式"留出验证门"(由 SkillOpt 补足) |
| 工程成熟度与可组合性 | 5 | MIT;DSPy 集成,`pip install dspy` 即用;575 fork;文档完善;维护活跃至 2026-10-12 |
| 证据质量与同行认可 | 5 | ICLR 2026 Oral;被 Sherpa、Learning to Prompt 等当基线;Shopify/Databricks 采用(厂商宣称) |
| 人在回路兼容性 | 4 | 产物是文本(可读),但不像 SkillOpt 那样有显式的人类编辑和回滚流程 |
| **加权总分** | **4.45** | |

**在系统中的角色**:分析教师/家长与系统的交互轨迹,诊断当前教学策略和心理指导文档的不足,提出更新。GEPA 是"改进的引擎"——它负责思考"为什么这条建议不够好"以及"怎么改会更好"。

**为什么 GEPA 而非其他引擎**:
- 与 ACE 相比:GEPA 的反思诊断能力更强,Pareto 前沿支持多目标优化,且同行认可度远高。
- 与 PsychAgent 的技能演化相比:GEPA 是通用优化器,可以优化任何文本组件,不局限于心理咨询领域。且 PsychAgent 的代码不完整。
- 与 Hermes Agent 相比:GEPA 有 ICLR Oral 背书和独立的效果数据,Hermes 没有受控改进对比。

### 5.3 推荐 2:SkillOpt — 质量门控与技能文档范式

| 维度 | 评分(1-5) | 依据 |
|---|---|---|
| 知识文档优化能力 | 4 | "技能文档作为可训练参数"精确匹配本场景;但优化方式是统计式的,缺少 GEPA 的语义诊断 |
| 质量门控严格度 | 5 | 留出验证门(严格提升才接受);文本学习率预算;被拒编辑缓冲;按 epoch 慢速更新——全场最严格 |
| 工程成熟度与可组合性 | 5 | MIT;PyPI `skillopt`;部署时零额外推理调用;跨模型迁移;1726 fork;文档和复现指南完整 |
| 证据质量与同行认可 | 3 | Microsoft Research;52/52 格最佳的实验覆盖面很广;但会议接收状态未核实 |
| 人在回路兼容性 | 5 | 产物是 300-2000 token 的人类可读 `best_skill.md`;天然支持人工审计和编辑;版本化管理 |
| **加权总分** | **4.45** | |

**在系统中的角色**:接收 GEPA 提出的策略更新提案,在留出验证集上检验——只有确实变好了才接受。SkillOpt 是"质量的守门人"——它负责确保自改进是真正的改进而非退化。同时,它的"技能文档"范式定义了教学策略和心理指导在系统中的**存储形式和更新协议**。

**SkillOpt 与 GEPA 的关系不是替代,而是互补**:

```
教师/家长反馈 → GEPA 诊断问题、提出更新 → SkillOpt 在留出集上验证 → 通过则接受,否则拒绝
                      ↑                                                    ↓
                      └────────── 被拒的更新反馈回 GEPA 重新诊断 ──────────┘
```

- **没有 GEPA 只有 SkillOpt**:优化是"黑箱统计的",不会产生"这条建议为什么不好"的语义诊断,改进方向盲目。
- **没有 SkillOpt 只有 GEPA**:优化可能产生波动——某次更新在某些场景上更好但在其他场景上更差,没有留出验证来把关。
- **两者组合**:GEPA 提供有语义理解的改进方向,SkillOpt 提供有统计保证的质量门控。

### 5.4 必须借鉴的设计模式(非基础工作)

以下不作为代码基础,但其设计模式**必须**在改造方案中实现:

| 来源 | 借鉴的设计模式 | 在本系统中的应用 |
|---|---|---|
| [SIC-Agents](https://arxiv.org/abs/2608.29481)(EMNLP 2026) | 课程指导约束 | 在 GEPA 优化循环中注入教育心理学基本原则作为不可动摇的约束;SIC-Agents 的消融直接证明无此约束会导致关键行为退化 |
| [GenericAgent](https://github.com/GenericAgent/GenericAgent)(MIT) | 验证轨迹沉淀为可复用 SOP | 当教师报告策略有效时,沉淀为可复用的教学方案;层级化记忆用于按年级/学科/问题类型组织文档 |
| [Ouroboros](https://github.com/ouroboros-agents/ouroboros)(MIT) | 保护治理层 + 回滚 + 审计 | 保护类别的建议(虐待/忽视识别、心理危机、医学转介)放入不可修改的治理层;所有策略更新有版本历史和一键回滚 |

### 5.5 与 rsi_edu_solu1 推荐的对比

| 维度 | rsi_edu_solu1 推荐 | 本文推荐 | 差异原因 |
|---|---|---|---|
| 基础工作数量 | 3 项 | 2 项 | 本场景不需要导师平台和教学模型训练 |
| 自改进引擎 | GEPA | GEPA | 相同——GEPA 作为通用优化器适用于两种场景 |
| 平台/骨架 | DeepTutor | 无(标准顾问工具即可) | 教师/家长不需要自适应导师的基础设施 |
| 教学方法论 | PedagogicalRL | 无(由 SkillOpt 文档体系替代) | 系统不直接教学,不需要训练教学行为能力 |
| 质量门控 | GEPA 的 Pareto + 独立评估器 | SkillOpt 的留出验证门 | SkillOpt 提供更严格的统计保证 |
| 安全模型 | 直接暴露(KIDBench/ChildEval + 语言控制) | 间接影响(证据锚定 + 保护类别 + 课程指导) | 用户是成人,不需要儿童安全评估器 |
| 模拟器需求 | 需要小学生模拟器(投入大) | 不需要(由教师/家长真实反馈驱动) | 最大的成本节约点之一 |

## 6. 改造方案

### 6.1 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                    治理层(Ouroboros 模式)                   │
│  保护类别建议(不可修改):虐待/忽视识别、心理危机转介、      │
│  医学转介、法律法规约束                                      │
│  教育心理学基本原则(不可修改):作为 GEPA 的课程指导约束     │
└─────────────────────────────────────────────────────────────┘
                              │ 约束
┌─────────────────────────────▼───────────────────────────────┐
│                    GEPA(策略优化层)                         │
│  分析教师/家长交互轨迹 → 诊断建议不足 → 提出策略更新       │
│  产物:教学策略更新提案、心理指导更新提案                    │
│  受课程指导约束,不能偏离教育心理学基本原则                  │
└─────────────────────────────┬───────────────────────────────┘
                              │ 更新提案
┌─────────────────────────────▼───────────────────────────────┐
│                    SkillOpt(质量门控层)                     │
│  在留出验证场景上测试更新提案 → 严格提升才接受              │
│  产物:验证通过的 best_skill.md(教学策略/心理指导文档)     │
│  所有更新有版本历史,教育专家可审计/编辑/回滚               │
└─────────────────────────────┬───────────────────────────────┘
                              │ 验证通过的策略文档
┌─────────────────────────────▼───────────────────────────────┐
│                    顾问服务层(新建)                         │
│  教师/家长通过对话界面提出问题 → 系统基于最新策略文档回答   │
│  反馈收集:显式(评分/评论)+ 隐式(追问/报告效果)          │
│  反馈数据 → 回传 GEPA 用于下一轮优化                       │
└─────────────────────────────────────────────────────────────┘
```

三层各司其职:
- **没有 GEPA**:系统只能用固定的策略文档回答,不会从教师/家长的反馈中学习和改进。
- **没有 SkillOpt**:GEPA 的更新可能波动,某些场景变好但其他场景退化,没有统计保证。
- **没有治理层**:自改进可能侵蚀关键安全行为(SIC-Agents 的消融已直接证明这一点)。

### 6.3 自改进循环详细设计

#### 数据流

```
教师使用策略文档中的建议 → 在课堂上实践 → 反馈给系统
    "这个分数教学策略在我班上效果不好,
     因为学生对等分概念就没搞清楚"
                    ↓
GEPA 反思式诊断(受治理层约束):
    "当前策略假设学生已掌握等分概念。
     诊断:缺少前置知识诊断步骤。
     建议更新:在策略开头增加3个等分
     概念的诊断问题,根据诊断结果
     分叉到不同的教学路径。"
                    ↓
SkillOpt 留出验证:
    用20个专家标注的分数教学情境测试更新后的策略
    → 留出分数从 3.2/5.0 提升到 3.5/5.0
    → 接受更新
                    ↓
best_skill.md 版本更新(v1.0 → v1.1)
    教育专家定期审核队列中出现新版本
```

#### GEPA 的适配

GEPA 通过 DSPy 集成,调用方式类似:

```python
import dspy

optimizer = dspy.GEPA(
    metric=education_advisory_metric,
    num_threads=4,
    # Pareto 维度
    objectives=["practical_applicability", "evidence_base", "age_appropriateness"]
)
```

需要为教育/心理顾问场景定制的评估函数:

| 评估维度 | 权重 | 评估方式 |
|---|---|---|
| 建议的可操作性 | 30% | 专家标注 + 教师/家长反馈 |
| 循证程度 | 25% | 建议是否有发展心理学/教育学研究支持 |
| 年龄适配性 | 20% | 建议是否匹配目标年龄段的发展特征 |
| 情境针对性 | 15% | 建议是否回应了用户描述的具体情境 |
| 安全性 | 10% | 建议是否可能造成间接伤害(权重虽低,但有一票否决权) |

**课程指导约束的注入**(SIC-Agents 模式):

在 GEPA 的优化循环中,每次提出更新都必须通过课程指导检查:

1. **正面约束**(更新后的策略必须保留的):
   - 建议分层教学而非一刀切
   - 强调过程而非结果(成长型思维)
   - 区分正常发展变异与需要专业关注的信号
   - 对不确定的情况建议寻求专业评估

2. **负面约束**(更新后的策略不能出现的):
   - 给出超出系统能力范围的心理诊断
   - 用非循证方法(如星座、血型)解释行为
   - 暗示某个孩子"不行"或"注定如此"
   - 给出可能加剧家校矛盾的建议

3. **门控机制**:
   - GEPA 提出的更新如果违反正面约束(缺少必须保留的内容),自动拒绝
   - GEPA 提出的更新如果包含负面约束中的内容,自动拒绝且记录
   - 上述约束本身属于治理层,不可被 GEPA 修改

### 6.4 质量门控系统

三级门控:

| 级别 | 机制 | 来源 | 触发条件 |
|---|---|---|---|
| L1:自动留出验证 | SkillOpt 的留出验证门 | SkillOpt 原生 | 每次 GEPA 提出更新时 |
| L2:课程指导约束检查 | SIC-Agents 的课程指导模式 | 新建(基于 SIC-Agents 设计) | 每次 GEPA 提出更新时(与 L1 并行) |
| L3:专家人工审核 | 教育心理学专家 | 新建 | 定期(每周/每两周)批量审核通过 L1+L2 的更新 |

**留出验证集的构建**:

这是整个系统质量的关键非技术依赖。需要教育心理学专家团队:

1. 编写 200-500 个教学/心理情境及其"理想建议"(涵盖所有文档分类)。
2. 其中 30% 为高风险情境(疑似虐待、心理危机、发展异常)。
3. 每个情境有 1-5 分的专家评分及评分理由。
4. 留出集本身需要定期更新(由专家团队维护),但更新频率远低于策略文档的更新频率。

**门控规则**:
- L1(SkillOpt):更新后的留出分数必须 ≥ 更新前,否则拒绝。高风险情境的分数**单独计算**,不能被非高风险情境的提升"平均掉"。
- L2(课程指导):违反任何一条正面/负面约束即拒绝。
- L3(专家):专家可以接受、修改后接受、或拒绝。专家修改后的版本直接成为新的 `best_skill.md`,不再经过 SkillOpt 验证(专家判断优先于统计验证)。

### 6.5 教育心理知识基础

这不是 RSI 机制,而是**被 RSI 机制优化的对象和约束 RSI 机制的边界**:

| 知识来源 | 用途 | 可修改性 |
|---|---|---|
| 发展心理学教科书(如 Berk 的《儿童发展》) | 治理层的基本原则 | 不可由 GEPA 修改 |
| 教育课程标准 | 教学策略的课标对齐依据 | 不可由 GEPA 修改(随课标更新而人工更新) |
| [KidMind](https://github.com/wtiantianw/KidMind) 33.7k 条指令数据 | 心理发展文档的初始种子 | 初始化后由 GEPA 优化 |
| 循证教育研究数据库 | 策略文档的证据引用 | 引用链接不变;引用方式可由 GEPA 优化 |
| 教师/家长交互轨迹(脱敏) | GEPA 优化的输入数据 | 不是知识本身,是优化信号 |

### 6.6 教师/家长交互设计

#### 输入:教师/家长的问题

系统接受的输入类型:
- **具体问题**:"我班上一个三年级学生,数学应用题总是读不懂题目,怎么帮他?"
- **情境描述**:"我女儿最近每天回来都说不想去学校,问她为什么也不说。"
- **策略反馈**:"你上次建议的方法我试了,有用/没用,因为..."
- **发展咨询**:"我儿子 7 岁了还不太会系鞋带,这正常吗?"

#### 输出:系统的回应

基于最新的策略文档(SkillOpt 验证通过的 `best_skill.md`)生成回应,包含:
- **具体建议**:可操作的步骤,不是空洞的原则。
- **证据标注**:建议的依据来源(标注"循证"或"经验性建议")。
- **不确定性透明**:"这种情况有多种可能的原因,最常见的是...但也可能是...如果持续 X 周建议..."
- **转介建议**(当适用):"这种情况建议与学校心理辅导老师/儿童心理咨询师沟通。"

#### 反馈收集

| 反馈类型 | 方式 | 数据用途 |
|---|---|---|
| 显式评分 | 1-5 分 + 可选文字评论 | 直接作为 GEPA 的评估信号 |
| 效果报告 | "我试了你的建议,结果是..." | 高价值信号:真实世界验证 |
| 追问 | 用户对回答追问说明原回答不够好 | 隐式负反馈,用于 GEPA 诊断 |
| 不使用 | 用户查看建议但未采纳(无后续交互) | 弱信号,需谨慎解读 |

### 6.7 间接安全保障

本场景的安全保障与 rsi_edu_solu1 完全不同——不需要 KIDBench、ChildEval、语言复杂度控制、情感依赖预防。需要的是:

#### A. 证据锚定

- 每条建议必须标注证据来源(教科书/研究论文/经验性)。
- GEPA 优化时,证据锚定的质量是评估维度之一(25% 权重)。
- SkillOpt 的留出验证包含"证据引用准确性"子项。

#### B. 保护类别(治理层,不可修改)

| 保护类别 | 固定建议 | 永远不做的事 |
|---|---|---|
| 疑似虐待/忽视 | 立即建议联系相关机构或专业人员 | 不建议"再观察看看"或"家庭内部解决" |
| 心理危机(自伤/自杀信号) | 立即建议联系专业危机干预服务 | 不提供自行处理建议 |
| 疑似发展障碍 | 建议专业评估(明确说"不是诊断") | 不给出诊断性结论 |
| 医学相关 | 建议咨询儿科医生 | 不替代医学建议 |

这些保护类别的建议是**固定的**,不被 GEPA 优化、不经过 SkillOpt 验证。它们放在治理层,优先级高于所有策略文档。

#### C. 漂移检测

SIC-Agents 的消融警告在本场景中的具体检测方式:

- 定期(每月)用固定的高风险情境测试集评估系统的回应。
- 如果高风险情境的建议质量下降(即使整体质量上升),触发人工审核。
- 监控"建议的平均长度""建议的平均自信度"——如果这些指标持续上升但用户满意度没有同步上升,可能是漂移信号。

## 7. 风险分析与缓解

### 7.1 顾问漂移风险(最高风险)

**风险描述**:SIC-Agents 的消融直接证明,无领域指导的自改进会让系统"更流畅"但侵蚀关键行为。在本场景中,表现为:建议变得"更自信、更专业、更有说服力",但偏离循证教育心理学原则。**成人用户比儿童更容易被专业语气说服而采纳偏差建议**——这是本场景的独特风险。

**缓解策略**:
- 课程指导约束(6.3 节)+ SkillOpt 留出门控(6.4 节)是主要防线。
- 高风险情境的留出分数独立计算,不被整体分数"平均掉"。
- 专家定期审核(L3 门控)。
- 所有策略文档有版本历史和回滚能力。

### 7.2 间接影响链断裂风险

**风险描述**:系统给出的建议本身合理,但教师/家长在执行中误解或走样。系统优化的是"建议质量",但实际影响取决于"建议被执行的质量"——系统无法控制后者。

**缓解策略**:
- 建议尽可能具体、可操作、有明确步骤(减少误解空间)。
- 关键建议附带"常见误用"警告(如:"这不意味着放任不管,而是...")。
- 鼓励教师/家长报告执行效果(6.6 节的反馈收集),用于 GEPA 的诊断。
- 承认这个局限:间接影响链的效果衰减是结构性的,自改进无法完全消除。

### 7.3 评估函数设计风险

**风险描述**:GEPA 的优化方向完全取决于评估函数。教育/心理建议的"好坏"比编码任务模糊得多。如果评估函数有偏差,GEPA 会高效地朝错误方向优化。

**缓解策略**:
- 评估函数由教育心理学专家设计,不完全依赖 LLM 评审。
- Pareto 多目标(可操作性/循证度/年龄适配/针对性/安全性)比单一目标更鲁棒。
- 定期用真实的教师/家长反馈校准评估函数。
- 早期阶段保守运行:GEPA 的更新频率低(每周而非每天),每次更新经过充分的人工审核。

### 7.4 留出验证集偏差风险

**风险描述**:SkillOpt 的质量保证完全依赖留出验证集的质量。如果留出集不够多样、不够真实,或遗漏了某些重要场景,策略更新可能在留出集上看起来好但在真实使用中不好。

**缓解策略**:
- 留出集由多位教育心理学专家共同编写(减少单人偏差)。
- 定期用真实的教师/家长问题补充留出集。
- 留出集的高风险情境占比 ≥ 30%。
- 留出集本身有版本管理和审核流程。

### 7.5 效果可能有限

**风险描述**:教育报告的核心发现之一是"自改进尚未被证明能把静态 AI 导师的效果显著抬高"。Khanmigo 两年 RCT 效果只有每学年 0.06-0.08 SD,且瓶颈是使用率。自改进对于一个**顾问**系统(而非导师系统)的增量价值可能更小。

**缓解策略**:
- 设定合理预期:自改进的价值不在于"革命性提升",而在于"持续微改进 + 不退化保证"。
- 关注"使用率"这个可能的瓶颈:教师/家长是否真的会持续使用并提供反馈?
- 早期阶段的目标不是"证明自改进显著提升效果",而是"证明自改进不伤害效果,同时积累有价值的交互数据"。

### 7.6 数据隐私

**风险描述**:教师/家长在与系统交互中可能描述具体儿童的行为、情绪、家庭状况。这些数据是 GEPA 优化的原料,也是最敏感的信息之一。

**缓解策略**:
- GEPA 优化在脱敏后的聚合数据上进行,不使用含个人标识信息的原始轨迹。
- 用户有查看、导出和删除数据的控制权。
- 数据存储在本地/私有云,不上传公共服务。
- 遵循数据最小化原则。

## 8. 实施路径

### 阶段 1:知识基础与顾问骨架(0-2 个月)

| 任务 | 详情 |
|---|---|
| 编写种子策略文档 | 邀请 3-5 位教育心理学专家编写 50-100 个种子文档(覆盖 6.2 节的主要分类) |
| 构建留出验证集 | 邀请专家编写 200-500 个情境及理想建议(含 30% 高风险情境) |
| 搭建顾问服务界面 | 标准对话界面 + 反馈收集 + 文档管理后台(标准工程,不涉及 RSI) |
| 整合 KidMind 数据 | 将 KidMind 的 33.7k 条指令数据整合到心理发展文档的知识基础中 |
| 部署治理层 | 实现保护类别建议和课程指导约束(6.3 节) |

**阶段 1 产出**:一个没有自改进能力的教师/家长顾问系统。基于静态的专家编写策略文档回答问题,已有治理层保护。这个系统本身就有价值,也为后续自改进提供了基础和对照基线。

### 阶段 2:GEPA 集成(2-4 个月)

| 任务 | 详情 |
|---|---|
| 安装和配置 GEPA | `pip install dspy`;配置 GEPA 优化器 |
| 设计评估函数 | 与专家团队协作定义 5 个评估维度及权重(6.3 节) |
| 实现课程指导注入 | 在 GEPA 优化循环中注入正面/负面约束 |
| 实现反馈→轨迹管道 | 将教师/家长的反馈转化为 GEPA 可消费的执行轨迹格式 |
| 离线测试 | 用留出验证集离线运行 GEPA 优化,观察策略文档的变化方向和质量 |

**阶段 2 产出**:GEPA 能对策略文档提出更新建议,但更新尚未自动生效——全部经过人工审核后手动接受或拒绝。

### 阶段 3:SkillOpt 门控(4-6 个月)

| 任务 | 详情 |
|---|---|
| 安装和配置 SkillOpt | `pip install skillopt`;配置留出验证管道 |
| 连接 GEPA 与 SkillOpt | GEPA 的更新提案自动进入 SkillOpt 的留出验证流程 |
| 实现三级门控 | L1(自动留出验证)+ L2(课程指导检查)+ L3(专家审核队列) |
| 实现版本管理和回滚 | 所有策略文档的版本历史和一键回滚 |
| 端到端测试 | 模拟完整的"反馈→诊断→更新→验证→部署"循环 |

**阶段 3 产出**:完整的自改进循环运转起来,但尚未对外部用户生效——仍在内部测试。

### 阶段 4:小规模试点(6-9 个月)

| 任务 | 详情 |
|---|---|
| 招募试点用户 | 50-100 位教师和家长(建议通过学校合作招募) |
| 部署并收集数据 | 3 个月的真实使用,收集反馈和效果报告 |
| 监控自改进质量 | 观察策略文档的更新方向、留出分数变化趋势、用户满意度 |
| 漂移检测 | 每月用固定测试集检测高风险情境的建议质量 |
| 对比基线 | 与阶段 1 的静态系统对比,评估自改进的增量价值 |

**阶段 4 产出**:真实世界的效果数据。回答两个关键问题:(1) 教师/家长是否真的持续使用?(2) 自改进是否比静态系统产生更好的建议?

### 阶段 5:迭代与扩展(9 个月+)

| 任务 | 详情 |
|---|---|
| 根据试点数据调整 | 调整评估函数、课程指导约束、留出验证集 |
| 扩大用户规模 | 根据试点结果决定是否扩大 |
| 扩展领域覆盖 | 增加更多学科、更多年龄段、更多情境类型的策略文档 |
| 考虑与 rsi_edu_solu1 系统的衔接 | 本系统产出的验证过的策略文档可以作为 rsi_edu_solu1(面向儿童)系统的策略输入 |

## 9. 总结

### 9.1 选择的 2 项工作及其角色

| 工作 | 角色 | 许可证 | 热度(fork) | 同行认可 |
|---|---|---|---|---|
| [GEPA](https://github.com/gepa-ai/gepa) | 自改进引擎:诊断问题、提出策略更新 | MIT | 575 | ICLR 2026 Oral |
| [SkillOpt](https://github.com/microsoft/SkillOpt) | 质量门控:留出验证、防退化 | MIT | 1726 | Microsoft Research(会议未核实) |

### 9.2 必须额外借鉴的设计模式

| 来源 | 设计模式 | 在本系统中的关键作用 |
|---|---|---|
| [SIC-Agents](https://arxiv.org/abs/2608.29481) | 课程指导约束 | 防止自改进侵蚀循证教育心理学原则(消融实验直接证明了这个风险) |
| [GenericAgent](https://github.com/GenericAgent/GenericAgent) | 验证轨迹→可复用 SOP | 有效策略的沉淀和层级化组织 |
| [Ouroboros](https://github.com/ouroboros-agents/ouroboros) | 治理层 + 回滚 + 审计 | 保护类别建议不可修改;所有更新可回滚 |

### 9.3 核心设计原则

1. **证据优先于流畅**:建议的价值来自其循证程度和可操作性,不是来自其表达方式。SIC-Agents 的消融警告是本方案的第一安全参考。
2. **GEPA 提议,SkillOpt 把关**:有语义理解的改进方向 + 有统计保证的质量门控。
3. **教师/家长是天然的人在回路**:这是本场景相对于 rsi_edu_solu1 的最大优势——不需要构建独立的安全评估体系,用户自己就能判断建议质量。
4. **领域知识是内容,不是 RSI 机制**:教育心理学知识来自专家和文献,GEPA/SkillOpt 负责让系统**更好地运用**这些知识,而非**发明**这些知识。
5. **诚实面对效果预期**:自改进尚未被证明显著提升教育 AI 的效果。本系统的价值主张是"持续微改进 + 不退化保证",不是"革命性提升"。

### 9.4 与 rsi_edu_solu1 的关系

两个系统可以互补:
- rsi_edu_solu1 直接面向儿童(GEPA + DeepTutor + PedagogicalRL)。
- 本文面向教师/家长(GEPA + SkillOpt)。
- 本系统产出的、经过教师/家长真实反馈验证的策略文档,可以作为 rsi_edu_solu1 系统中 GEPA 优化的种子策略——**教师/家长的反馈比模拟学生的反馈更可靠**(Learning to Prompt 的 sim-to-real gap 已证明这一点)。
- 反过来,rsi_edu_solu1 在真实儿童身上收集到的数据(在严格的隐私保护下)可以帮助本系统更好地理解"哪些建议在实际执行中确实有效"。

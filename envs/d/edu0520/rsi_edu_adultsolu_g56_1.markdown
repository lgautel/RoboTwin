### 0.2 本文明确排除什么

- 按你的要求，本文不讨论数据敏感性、合法合规、租户隔离、隐私、访问安全或许可证带来的使用限制。
- 系统不直接面对孩子，所以本文不设计儿童聊天人设、儿童回复措辞门、陪伴边界或儿童端 UI。
- 是否有公开代码只作为可复现性和实施成本信息，不参与效果排序。

### 0.3 仍然必须讨论什么

系统虽然只把建议给家长，建议仍可能通过家长改变孩子的学习、情绪和亲子关系。因此以下不是合规或“对孩子说错话”问题，而是纯粹的效果问题：

1. 系统是否正确理解了对话证据；
2. 建议是否来自有效干预，而不是模型临场发明；
3. 家长是否看到并实际执行；
4. 家长行为是否真的改变；
5. 孩子的近端反应和延迟结果是否改善；
6. 自改进后的版本是否比旧版更好，而非只更流畅、更讨喜。

### 0.4 证据和术语

- **RSI**：recursive self-improvement，递归自改进。本文不把“记住了更多事情”或“更个性化”自动算作严格 RSI。
- **技能文档**：写给建议生成模型的可编辑规则，规定如何观察、推断、选动作和向家长解释。
- **证据动作库**：版本化的家长动作集合。每个动作都带适用情境、示例话术、观察窗口、证据来源和因果范围。
- **家庭 playbook**：对某个家庭有效或无效的经验条目，不等于通用干预原则。
- **事件账本**：只追加、不覆盖的原始证据和派生事件记录；所有家庭画像都可由它重建。
- **incumbent**：当前已部署的建议策略版本。
- **candidate**：等待验证的候选版本。
- **门**：决定候选能否进入下一阶段或替代 incumbent 的检验。
- **ITT**：intention-to-treat，按系统随机分配了什么建议来比较结果，不按家长最终是否执行来挑样本。
- **证据标记**：
  - 【论文自报】：作者在论文或预印本中的结果；
  - 【项目/厂商自报】：项目官方文档、博客或厂商报告；
  - 【独立/第三方】：独立随机试验、元分析、官方标准或第三方复现；
  - 【我的判断】：本文的设计推论；
  - **未核实**：未找到足够的一手证据。
- 阈值、预算、样本量或成本若不是文献结论，标为“起步建议”“起步估计”或“推算”。

## 1. 结论摘要

### 1.1 选择

**主方案选 4 个互补基础：RegulaTutor（含 PairRoute）+ FAFO 数据管线与 FAPO 优化器 + SkillOpt（含 SkillOpt-Sleep）+ ACE。**

这里按四条研究/产品谱系计数，而不是把同一工作的内部方法或后续扩展重复计数：PairRoute 属于 RegulaTutor 同篇论文；FAPO 是 **Fully Automated Prompt Optimization**，FAFO 是其后续 **Fully Automated Flow Optimization** 数据/流程扩展；SkillOpt-Sleep 是 SkillOpt 的部署期扩展。

| 角色 | 基础工作 | 直接提供什么 | 为什么不可被另外三项完全替代 |
|---|---|---|---|
| 纵向教育分析骨架 | [RegulaTutor](https://arxiv.org/abs/2610.13399)，含论文内部的 PairRoute | 从长历史抽取证据，区分认知、情绪、元认知、动机状态，生成带证据链接的策略；把失败定位到 harness、模型或混合故障 | 另外三项都是通用自改进技术，不知道“亲子教育建议”应怎样分解和诊断 |
| 稀疏反馈工厂 | [FAFO](https://cisco-foundation-ai.github.io/blogs/fafo-recursive-self-improvement/) 数据管线 + [FAPO](https://arxiv.org/abs/2606.19605) 优化器 | 用少量家长反馈提炼评价指南，为大量无反馈事件生成逐案例 rubric 和 memory cards，再优化 prompt、参数或流程 | 家庭真实结果稀疏；SkillOpt 需要可评分任务，ACE 需要可信反馈，而 FAFO 正好把稀疏反馈变成评价资产 |
| 系统技能的版本生命周期 | [SkillOpt](https://github.com/microsoft/SkillOpt) + [SkillOpt-Sleep](https://microsoft.github.io/SkillOpt/docs/sleep/) | 有界编辑、留出验证、被拒编辑缓冲、meta-skill、逐项不退步、候选暂存和人工采纳 | FAFO/FAPO 擅长生成评价和优化流程，但没有 Sleep 这样完整的周期性“stage → review → adopt”产品回路 |
| 每个家庭的经验记忆 | [ACE](https://github.com/ace-agent/ace) | 条目化增量 playbook；每条记录 helpful/harmful 证据；避免整段重写造成 context collapse | RegulaTutor 管分析框架，FAFO 管反馈资产，SkillOpt 管全局技能；都不如 ACE 适合保存“对这个家庭什么时候有效” |

这不是把四个仓库机械拼在一起。四者分别承担不同的更新对象：

- RegulaTutor：**解释框架与建议结构**；
- FAFO/FAPO：**评价资产和候选流程**；
- SkillOpt：**通用建议技能版本**；
- ACE：**家庭特定经验**。

### 1.2 选得更少时

| 最多能选几个 | 建议 | 会失去什么 |
|---|---|---|
| 1 个 | SkillOpt + SkillOpt-Sleep | 需要自行实现领域分析、稀疏反馈转 rubric 和家庭 playbook；但仍保住最关键的“有界修改、留出、暂存、采纳” |
| 2 个 | SkillOpt-Sleep + ACE | 得到全局技能与家庭经验两层；仍需手工写评价 rubric 和亲子教育分析框架 |
| 3 个 | SkillOpt-Sleep + ACE + FAFO/FAPO | 可以从真实日志和少量家长反馈持续产出评价资产；亲子教育分析骨架仍需自建 |
| 4 个 | RegulaTutor + FAFO/FAPO + SkillOpt-Sleep + ACE | 覆盖领域分析、反馈工厂、版本回路和家庭经验，完整度最高 |

**全部要求有公开代码时**，把无公开实现的 RegulaTutor 换成 [Recuris](https://github.com/Gen-Verse/Recuris)：选择 **FAFO/FAPO + SkillOpt-Sleep + Recuris + ACE**，再自行实现 RegulaTutor 的“证据 → 状态 → 策略”骨架。

### 1.3 为什么不再选 DeepTutor + SkillOpt + PedagogicalRL

旧方案优化的是：

> AI 直接怎样教孩子。

新系统优化的是：

> 系统怎样从亲子互动中发现一个可行动机会，向家长建议什么，家长是否执行，以及孩子之后是否变好。

关键中介从“导师回复”变成了“家长行为”。因此：

- **DeepTutor** 的儿童聊天身体、Partner、儿童语音和可视化不再是核心；它的学习者模型、教材检索和记忆设计仍可借用。
- **PedagogicalRL / Sherpa** 评估直接导师能否提升模拟学生解题率，无法覆盖“建议 → 家长执行 → 孩子结果”；降为学习建议的离线内容筛查。
- **SkillOpt** 仍入选，因为它优化的是外部技能文档和部署期版本回路，与输出对象无关。

### 1.4 十项关键改造

1. **系统输出从“对孩子说什么”改为“家长下一步做什么”**，固定格式为：原始证据、可能解释及置信度、一个首选动作、备选动作、示例话术、观察窗口。
2. **建立双时态、append-only 事件账本**。转写、说话人、行为标签、人工修正和模型版本全部可追溯，后来的修正不覆盖原记录。
3. **把事实、状态假设、家庭经验和通用技能分开**，禁止把“这次可能焦虑”写成永久人格事实。
4. **建立版本化证据动作库**。LLM 可以选择、个性化措辞和解释，但不能自行发明干预原则。
5. **音频优先感知**：身份 diarization、中文/英文 ASR、回应关系、低推断行为；视频只在说话人、共同注意或作业操作确有增益时加入。
6. **FAFO 只把稀疏家长反馈扩展为候选 rubric**，不能把合成 rubric 当作真实儿童结果。
7. **SkillOpt 每晚可以生成候选，但不能因离线门通过就自动替换建议策略**；每个建议类别最多一个冻结候选进入真实随机确认。
8. **ACE 条目绑定真实证据**：是否执行、家长行为是否改变、孩子近端反应和延迟结果；只记录点赞或采纳不算 helpful。
9. **推广的主证据改为 ITT**。短时建议用 MRT，学习用知识点/技能簇随机，持续亲子技能用随机多基线。
10. **用 anytime-valid e-process 和不可重置的生命周期错误预算推广**；删除“后验概率超过 0.8 就采纳”这类不能控制反复尝试的门槛。

### 1.5 现实预期

- 截至 2026-10-15，没有一项工作端到端证明：从真实 6–12 岁亲子对话中学习的成人侧系统，能持续自改进并改善儿童长期结果。
- 成人侧 AI 可以改变成人行为：
  - [Tutor CoPilot](https://arxiv.org/abs/2410.03017) 的导师级随机试验中，近端 exit-ticket 通过率从 62% 提升到 66%，低评分导师约提升 9 个百分点；年终数学成绩没有显著改善【论文自报】。
  - [TeachFX](https://doi.org/10.1016/j.compedu.2024.105183) 的专项随机反馈让教师聚焦性问题增加约 20%，但没有学生学习结局【论文自报】。
- 家长侧 AI 仍很早期：
  - PACEE、COMPASS 是小型实验室或 HCI 研究；
  - ParenteAI 是 22 人无对照前后测；
  - PaiCoach 只有 4 个低龄自闭症儿童家庭，且 31.4% 的输出需要专家修改；
  - Active Family 的家长提示 MRT 平均近端效果接近零。
- 因此最合理的第一版不是“实时耳机教练 + 每晚自动进化”，而是“会后可核查复盘 + 少量证据动作 + 完整实验账本”。先证明系统能改变一个具体家长动作，再逐步增加实时性和自改进范围。

## 2. 问题重述与分析过程

### 2.1 真正要优化的因果链

本系统的完整链路是：

```text
家庭情境
  → 系统是否识别到可行动事件
  → 系统随机选择是否给建议、给哪种建议
  → 建议是否送达并被家长看到
  → 家长是否理解、接受、实际执行
  → 家长行为是否按预期改变
  → 孩子的近端反应
  → 数天或数周后的学习/心理结果
```

每一箭头都可能失败。把最后结果简单归因给“建议文本好不好”，会掩盖五种不同问题：

1. 音频或说话人识别错；
2. 事件分段或行为标签错；
3. 状态解释没有证据；
4. 建议本身正确，但家长没执行；
5. 家长执行了，近端看起来顺利，延迟结果却没有改善。

因此本方案把系统拆成可分别验证的部件，而不是训练一个端到端模型给家庭打总分。

### 2.2 三级 RSI 证据

| 级别 | 定义 | 本场景中的例子 |
|---|---|---|
| 任务增益 | 一次输出更好，但没有留下持久修改 | 某次建议让家长觉得有帮助 |
| 留存增益 | 持久修改在未参与优化的未来事件上更好 | 新技能版本在新事件上提高家长目标行为和孩子结果 |
| 改进器增益 | 产生修改的机制本身被改进，并在同预算下产出更好的后续修改 | 新 meta-skill 让 SkillOpt 后续候选的真实通过率更高 |

主系统只要求**可验证的留存增益**。改进器增益放到离线 L2：

- SkillOpt 的 meta-skill 消融提供支持性线索，但不是家庭场景的改进器增益证明；
- WER、VERSE、HyperAgents 在程序任务上有更接近改进器增益的证据，但都依赖大量可执行验证，不能直接迁移；
- 家庭建议的评价器稀疏、滞后且受家长执行中介影响，不适合早期做代码级或权重级递归修改。

### 2.3 系统的十个“器官”

| 编号 | 器官 | 职责 | 主要候选 |
|---|---|---|---|
| O0 | 感知器 | diarization、ASR、回应关系、行为与挫败 episode | Nemotron 3、pyannote、Qwen3-ASR、Pasketti、Playlogue、Homework Wars |
| O1 | 事件真值层 | 保存原始证据、修正、模型版本和双时态历史 | Event Sourcing、ActiveGraph、Regimes |
| O2 | 家庭与学习状态 | 维护孩子知识点、遗忘、家长行为率和互动状态 | BKT、IRT、FSRS、RegulaTutor |
| O3 | 证据动作库 | 规定在什么情境下可建议什么 | PMT/PCIT、SPACE、Co-CAT、情绪辅导、家庭读写/数学证据 |
| O4 | 家长建议生成器 | 选择动作并用家庭语言改写 | RegulaTutor、Tutor CoPilot/PACEE 的交互形态 |
| O5 | 家庭经验 | 记住这个家庭试过什么、是否执行和结果 | ACE、Recuris、Letta、Graphiti/Hindsight |
| O6 | 反馈工厂 | 把少量人工反馈转成评价指南和逐案例 rubric | FAFO、Future-Feedback、TeleTune |
| O7 | 候选提议器 | 修改全局技能、路由和建议流程 | SkillOpt、FAPO、GEPA、SkillHone、EvoSkill |
| O8 | 离线与发布门 | 固定留出、回归、审阅、暂存和回滚 | SkillOpt-Sleep、Recuris、SkillHone、Regimes、SGM |
| O9 | 真实因果确认 | 用真实随机数据决定是否推广 | MRT、N-of-1、随机多基线、e-process、OPE |

没有一个仓库覆盖十个器官，所以“选 1–4 个基础”只能选最难替代的核心，再借模块补齐。

### 2.4 新前提改变了什么

| 方面 | 儿童直接使用的旧方案 | 本方案 | 选型影响 |
|---|---|---|---|
| 在线输出 | AI 直接教孩子 | 只向家长给建议 | DeepTutor 的儿童端身体降权 |
| 优化对象 | 导师回复与儿童独立解题 | 家长动作选择、时机、执行和孩子后续结果 | PedagogicalRL 降为内容筛查 |
| 主要数据 | 儿童与导师对话 | 亲子自然对话、作业过程、家长执行和结果 | 感知与事件账本成为核心 |
| 反馈 | 模拟儿童或题目评分 | 家长编辑/执行、家长行为变化、孩子近端与延迟结果 | FAFO、ACE 价值上升 |
| 门 | 模拟课堂过门即可暂存 | 离线门只能预筛，真实随机门决定推广 | MRT/e-process 成为关键 |
| 个体化 | 对孩子选择讲法 | 对家庭选择“何时给哪项已验证家长动作” | contextual policy 取代儿童聊天策略 |
| 实时性 | 孩子发问时实时回答 | 会后复盘起步，证实有效后才做实时提示 | PACEE/COMPASS 只借交互设计 |

### 2.5 评价维度

候选按六个维度判断，不把热度当效果：

1. **真实效果相关性**：是否覆盖亲子历史、家长动作或真实用户反馈；
2. **反馈可信度**：是否依赖可核查结果、留出集、多种子或真实随机；
3. **长期个体化**：能否在不覆盖原始证据的前提下积累家庭经验；
4. **发布门**：能否隔离评价器、暂存、审阅、回滚；
5. **工程可用性**：代码、文档、活跃度、集成难度；
6. **RSI 证据级别**：任务增益、留存增益还是改进器增益。

### 2.6 分析路径

1. 重新定义输出对象和因果链，不沿用旧方案的结论；
2. 从通用 RSI 报告扩展 2026 下半年的日志学习、技能进化和改进器研究；
3. 单独搜索家长干预、成人侧 AI 教练和亲子互动研究；
4. 单独搜索 diarization、儿童 ASR、亲子行为自动编码、时序记忆与知识追踪；
5. 单独搜索只有 1–3 个孩子时可用的 MRT、N-of-1、OPE、序贯检验和层级模型；
6. 按十个器官整理候选，并构造组合；
7. 对正式名称、关键数字、代码、许可、同行评审和证据边界逐项复核；
8. 选择四个基础，设计改造、门、成本与路线图；
9. 把反例、不选项和未核实项单列，避免结论只展示正面证据。

## 3. 效果约束：十二条不能因“只面对家长”而消失的规则

### C1：主目标是儿童结果，不是家长喜欢建议

建议采纳、点赞和满意度只说明系统可用。主要链路必须同时测：

- 家长是否实际执行；
- 目标家长行为是否出现；
- 孩子的近端反应；
- 儿童延迟学习或心理结果。

Tutor CoPilot 的近端掌握度提高而年终成绩无显著变化，就是“成人行为/近端结果不等于长期儿童结果”的直接例子【论文自报】。

### C2：历史后续反应不是候选建议的反事实标签

历史中家长做了 A，孩子后来平静，只能说明“当时情境 + 家长选择 A”与结果相关，不能证明未发生的 B、C 更差。

[Future-feedback 方法](https://arxiv.org/abs/2607.18973)在私有销售对话上把后续信号预测做到平衡留出集准确率超过 75%，但论文明确承认：它只验证反馈预测器，没有证明由它指导的新回复能带来更好结果【论文自报】。因此未来反馈预测只能预筛，不能替代真实随机门。

### C3：干预内容与个性化策略分开

- 全局动作库来自随机试验、元分析或明确标注的弱证据，版本冻结；
- RSI 首先优化时机、路由、剂量、解释和家庭化措辞；
- 新动作只能经过独立证据审阅后进入库；
- 模型不能因为某次看起来成功，就发明并固化新的心理或教学原则。

### C4：家长执行是中介，主分析必须按随机分配

积极的家长往往更容易执行，也更容易报告改善。只比较“执行了”和“没执行”会产生选择偏差。主要 estimand 必须是 ITT：

```text
系统随机提供候选建议 vs incumbent/无建议
```

执行率、剂量和忠实度是机制分析，不用于筛掉“不听建议”的决策点。

### C5：感知结果是概率证据，不是真值

- Nemotron 3 在 DIHARD III 的 DER 为 12.73%–13.18%，但没有儿童家庭专项验证【项目/厂商自报】；
- pyannote 的旧 powerset 模型在 Playlogue 零样本 DER 约 53.4%，显示域偏移很大【论文自报】；
- Homework Wars 的 GPT-4o 行为编码 κ=.724，只评预切分文本，不含原始音频、ASR 或说话人误差【论文自报】；
- Playlogue 家长八分类 accuracy 77.70%，macro-F1 只有 48.09%，Reflection recall 约 2.26%【论文自报】。

所以系统必须保留原音频证据、N-best、置信度、模型版本和 abstain；不能把自动标签写成永久事实。

### C6：先识别低推断行为，再推断状态

可优先自动化：

- 具体/笼统表扬；
- 问句、命令、纠错、批评；
- 轮次、打断、重叠、响应时间；
- 题目、作答、提示等级。

“温暖”“依恋质量”“孩子人格”“家长动机”需要高层推断，不适合作为首版自动奖励。

### C7：多个评价器不能替代真实结果

LLM 评委、专家盲评、Future-Feedback、模拟家庭和 OPE 都可用于缩小候选范围。但只有冻结版本在真实家庭中的随机数据，才能触发建议策略推广。

### C8：学习不可逆，不能对同一知识点做简单 ABAB

孩子一旦学会，旧版本无法让他“洗脱”。学习建议按知识点或技能簇随机，主要结果用 7 天无提示迁移/检索；当场正确率只作机制指标。

### C9：持续家长技能存在 carryover

家长学会具体表扬、情绪验证或减少焦虑迁就后，可能在没有提示时继续使用。此类策略用随机多基线或错开引入，而不是假设一周后回到原状态。

### C10：单家庭只能在可接受时间内确认较大效应

`31.4/d²` 只是 IID、等分随机、无自相关、无残留、无缺失且无执行稀释时的粗略总决策点数推算。真实家庭数据通常需要更多点；最终样本量必须用基线期数据做 Monte Carlo 功效模拟。

### C11：成人建议应短、具体、嵌入事件

成人侧随机试验的共同信号是：反馈能改变被明确点名的成人行为，但很少自动迁移到所有行为或长期儿童结果。

- TeachFX 只让被专项反馈的聚焦性问题增加，其他行为没有明显改变；
- M-Powering Teachers 让高中导师更多接续学生观点、减少说话，但不是小学家庭；
- Active Family 每天 7 次实时建议的平均效果接近零。

因此首版一次只给一个可观察动作；实时提示必须证明优于会后复盘。

### C12：每次自改进都要消耗长期错误接受预算

反复试候选并在 `p<.05` 时保留，最终几乎必然误采纳。每个正式确认 attempt 必须从不可重置的生命周期预算中预分配 `αk`，并用 anytime-valid 方法允许随时查看而不破坏错误率控制。

## 5. 组合比较与最终选择

### 5.1 八种组合

| 组合 | 基础 | 覆盖 | 优点 | 主要缺口 | 结论 |
|---|---|---|---|---|---|
| A | RegulaTutor + FAFO/FAPO + SkillOpt-Sleep + ACE | 领域骨架、反馈工厂、系统技能、家庭经验 | 效果导向最完整；更新对象边界清楚 | RegulaTutor 无代码；四套概念需要集成 | 主选 |
| B | FAFO/FAPO + SkillOpt-Sleep + Recuris + ACE | 全开源反馈、版本、故障定位、经验 | 可立即开发；每项都有代码 | CAMM/亲子领域分析需自建 | 全开源替代 |
| C | SkillOpt-Sleep + ACE | 系统技能 + 家庭经验 | 最小可用，组件少 | rubric、领域骨架、真实评估都要自建 | 两项方案 |
| D | RegulaTutor + SkillOpt-Sleep + ACE | 领域、版本、经验 | 适合数据少的第一阶段 | 少量家长反馈无法有效覆盖大量日志 | 三项备选 |
| E | FAFO/FAPO + Future-Feedback + Regimes + ACE | 不可重放日志、预测、审计、经验 | 研究边界最诚实 | 两项无代码/弱证据；缺成熟 stage/adopt | 研究型 |
| F | SkillHone + Recuris + ACE | 决策历史、局部故障、经验 | 人工审阅和可追溯性强 | 稀疏反馈工厂与亲子领域结构弱 | 保守发布型 |
| G | DeepTutor + SkillOpt + PedagogicalRL | 儿童身体、版本、直接导师奖励 | 对儿童直接导师完整 | 优化对象与家长侧链路错位 | 不选 |
| H | Ouroboros/DGM/HyperAgents + 家庭应用 | 代码级或元级自修改 | RSI 严格度高 | 没有可靠家庭级代码 verifier，收益归因弱 | 不选 |

### 5.2 为什么主选 A

**第一，四项解决的是四个互不相同的失败面。**

- 没有 RegulaTutor，系统可能从长历史里抓错证据、把状态和策略混为一谈；
- 没有 FAFO，绝大多数真实事件没有人工反馈，SkillOpt 没有足够的评分任务；
- 没有 SkillOpt-Sleep，候选缺少稳定的周期、留出、暂存和采纳生命周期；
- 没有 ACE，每个家庭的经验只能混进全局技能，容易串家庭或在整体重写时丢失。

**第二，它避免把一项技术放到不擅长的位置。**

- ACE 不负责自动上线；
- FAFO 合成的 rubric 不当成真实效果；
- SkillOpt 的离线门不当成最终推广证书；
- RegulaTutor 的状态解释不写成不可修正事实。

**第三，它给 1–3 个孩子保留了小数据友好的更新对象。**

更新文本技能、家庭 playbook、动作路由和结构化状态，比每孩子训练 LoRA 或数字孪生体更适合小样本。

### 5.3 对四项选择的反方质疑

**质疑 1：RegulaTutor 没有代码，怎么能算基础？**

它是概念/架构基础，不是工程依赖。其价值是把长期建议分成证据、状态解释和策略，并用 PairRoute 区分 harness 与模型故障。工程实现可用 Recuris 的分组件记忆和 Regimes 的事件账本替代。文档同时提供全开源组合 B。

**质疑 2：FAFO 只有博客，公开实验还是模拟零售，证据太弱。**

成立。因此它不直接决定哪条建议有效，只负责产生候选评价指南和 rubric；真实推广仍由随机门决定。FAPO 论文方法和 FAFO 项目结果分开引用，不把 63/88→75/88 写成生产成效。

**质疑 3：SkillOpt 的任务都可重放，家庭互动不可重放。**

SkillOpt 只处理可固定的部分：历史证据问答、事件分类、建议内容、保护案例和家长盲评。真实家庭结果另走 MRT/N-of-1；Sleep 不直接采纳影响建议行为的修改。

**质疑 4：ACE 没有门，而且无可靠反馈时会退化。**

正因此 ACE 只做家庭 playbook 数据结构。条目计数只绑定执行与结果证据，候选条目经过质量门；ACE 无权改变通用动作库或自动推广。

**质疑 5：四项是不是过度设计？**

首版不需要同时实现全部高级功能。路线图先做事件账本、静态动作库和 SkillOpt 的候选/回滚；ACE、FAFO 和 RegulaTutor 式诊断按阶段加入。四项是目标架构的基础，不是第一周的四个运行服务。

**质疑 6：为什么不选严格 RSI？**

代码级自修改需要可靠、快速、可重复的 verifier。家庭结果滞后、受家长执行影响、不可重放。严格 RSI 会扩大可修改面，却没有相应提高验证能力；这会降低而非提高预期效果。

**质疑 7：为什么不直接用最强模型读全部历史并给建议？**

它缺少四样东西：可追溯证据、稳定动作库、版本化实验、对真实结果的因果归因。更长上下文只能减少部分检索问题，不能解决反事实和执行中介。

**质疑 8：家长本来会判断，为什么还要严谨的门？**

家长对单次建议的判断非常有价值，但“听起来合理”与“数周后孩子结果更好”不同。家长审阅是内容门；随机结果是效果门，二者不能互相替代。

## 6. 家长侧总体架构

### 6.1 在线链路

首版采用“接近实时分段 + 会后建议”，而不是边听边打断：

```text
亲子音频 / 手工输入 / 作业题目
  ↓
AEC、VAD、重叠检测、片段质量评分
  ↓
说话人 diarization → 家庭声纹身份映射
  ↓
ASR N-best、时间戳、语言/混说识别
  ↓
低推断行为标签 + 对话回应边 + 学习事件
  ↓
append-only 事件账本
  ↓
证据检索与事件窗口构造
  ↓
家庭状态 + 学习状态 + 不确定性
  ↓
机会/可用性/冷却期判断
  ↓
从冻结的证据动作库选候选动作
  ↓
家庭 playbook 排序 + 全局建议技能渲染
  ↓
给家长：证据、解释、动作、话术、观察窗口
  ↓
记录送达、看到、接受、执行、家长行为、孩子结果
```

建议输出使用固定契约：

```yaml
event_window:
  start: "19:42:10"
  end: "19:45:36"
observations:
  - evidence_id: "turn_184"
    text: "孩子连续两次说‘我不会’，家长随后直接给出答案"
    confidence: 0.87
interpretations:
  - hypothesis: "当前可能是挫败感升高，而非知识完全缺失"
    confidence: 0.61
    alternatives:
      - "疲劳"
      - "任务难度过高"
recommendation:
  action_id: "learn.scaffold.wait_then_hint.v2"
  one_action: "先等 5 秒，再只给一个最小提示"
  parent_script: "先看看第一步需要找什么，我等你想一会儿。"
  observation_window: "本次题目接下来的 3 分钟"
  fallback: "若挫败继续上升，暂停任务并约定稍后再做"
why:
  evidence_level: "B/C"
  family_playbook_refs: ["fp_203"]
experiment:
  policy_version: "policy_018"
  assignment_id: "mrt_00924"
```

这份契约强迫系统区分“听到了什么”“可能意味着什么”“建议做什么”。家长可以分别纠正转写、身份、事件、解释和建议，不能用一个总赞/踩吞掉故障位置。

### 6.2 七类持久数据必须物理或逻辑分层

| 层 | 内容 | 可否被 RSI 直接覆盖 | 典型主键 |
|---|---|---|---|
| 原始证据 | 音频哈希、时间戳、ASR N-best、说话人后验、手工输入 | 否，只追加修正版 | family / recording / segment |
| 派生事件 | 行为标签、回应边、题目、作答、提示、冲突/挫败 episode | 否，只追加新版本 | event / extractor_version |
| 状态假设 | 当前挫败、家长指令清晰度、知识掌握概率等 | 可重算，不覆盖证据 | state / valid_time / transaction_time |
| 家庭 playbook | 对该家庭何时有效、无效、不确定的条目 | ACE 可提议增量；经门后生效 | family / action / context |
| 通用建议技能 | 如何选证据、解释、选动作、写给家长 | SkillOpt 提议版本；不可在线覆写 | skill / version |
| 证据动作库 | 干预内容、适用条件、剂量、反例、证据级别 | 仅人工证据审阅后改变 | action / evidence_version |
| 实验与结果账本 | eligibility、randomization、delivery、execution、outcomes | 否；分析可版本化 | decision_point / assignment |

把家庭 playbook 与通用技能分开尤其重要：

- “这个孩子在晚饭后更容易接受先休息再复习”可进入家庭 playbook；
- “所有焦虑儿童都应先避免任务”不能由单家庭经验写进通用技能；
- 一个家庭的数据可贡献匿名化的候选失败模式，但不能直接修改另一个家庭的 active playbook。

### 6.3 分层自改进架构

| 层 | 更新对象 | 反馈 | 提议器 | 通过后到哪里 | 是否能自动生效 |
|---|---|---|---|---|---|
| L0 证据修正 | 说话人、转写、事件标签 | 家长修正、模型置信度、标注复核 | 感知模型/人工 | 新证据版本 | 可以，仅影响重算；不删旧记录 |
| L1 家庭适应 | 家庭 playbook、动作优先级、措辞偏好 | 执行链、近端反应、延迟结果 | ACE + 简单层级模型 | shadow family playbook | 低风险措辞可自动；影响动作选择需真实门 |
| L2 通用技能 | 分析、路由、建议、复盘技能 | 固定训练集、隐藏留出、家长盲评、真实确认 | SkillOpt-Sleep / FAPO | staged skill | 否；真实确认后才能 adopt |
| L3 改进器 | meta-skill、rubric 生成、搜索预算、路由方式 | 后续候选通过率、成本、真实推广率 | FAFO/FAPO + SkillOpt meta-skill | research challenger | 否；独立消融后手工更新 |
| L4 代码/权重 | 感知模型、基础 LLM、服务代码 | 单元/回归/本域标注集 | 常规训练与工程流程 | release candidate | 不属于运行期 RSI |

L0–L2 是产品主线；L3 是受控研究；L4 不允许由家庭日志自动修改。原因不是权限或合规，而是家庭级评价器不够快、不够密，无法可靠验证代码或权重自修改。

### 6.4 候选生命周期

```text
日志冻结
  → 训练/发现集产生修改
  → replay 与机制指纹
  → 未参与提议的固定留出
  → 家长盲评/内容审阅
  → staged（只影子运行）
  → 一个建议类别、一个冻结候选进入真实随机
  → anytime-valid 效果与非劣分析
  → adopt / reject / extend
  → 可一键回到前一 incumbent
```

候选状态只允许：

`draft → offline_passed → staged → live_confirming → adopted`

或从任一中间态转到 `rejected` / `rolled_back`。已进入真实确认后不得改 prompt、动作库、模型、eligibility、主要结局或方向；任何修改都产生新候选和新 attempt。

### 6.5 时间和家庭隔离：防止“用答案出题”

对每个候选，在时间 `T` 冻结：

- **发现窗口**：`T` 之前较早的事件，可供 FAFO/ACE/SkillOpt 查看；
- **离线隐藏窗口**：`T` 之前较新的事件，不给提议器，只给 evaluator；
- **前瞻窗口**：`T` 之后发生的新事件；
- **跨家庭泛化集**：没有参与该候选修改的其他家庭；
- **保护集**：罕见但高代价的误识别和不适用场景。

同一段事件不能同时生成 rubric、编辑技能并评价该编辑。若案例的未来结果被 FAFO 用于写 rubric，该案例只能留在训练/发现集。

### 6.6 何时给建议，何时 abstain

进入建议选择前必须依次通过：

1. **证据足够**：说话人、关键词或事件边界的联合置信度达到该动作类别的最低要求；
2. **可行动**：当前存在家长能在规定窗口内执行的动作；
3. **可用**：家长没有开启勿扰，事件未过期；
4. **冷却期**：近期没有同类别高频提示；
5. **适用条件**：动作库中的前提满足；
6. **实验 eligibility**：若在真实确认中，符合预注册决策点定义。

否则输出“信息不足/本次不建议”，或只给可核查的观察摘要。abstain 是提升有效信号密度的正常行为，不是错误。

### 6.7 运行节奏

| 节奏 | 任务 |
|---|---|
| 每个事件后 | 写原始证据、更新短时状态、判断是否建议、记录随机分配 |
| 每晚 | 重跑低置信度片段、生成会后复盘、ACE 提议家庭条目、SkillOpt-Sleep 生成但不采纳候选 |
| 每周 | 家长确认目标行为、查看执行链、盲评少量候选、审阅 staged 修改 |
| 每个证据窗口结束 | 运行正式离线门或真实 sequential 分析；只能按协议 adopt/reject/extend |
| 每月/每主题足量后 | 更新家庭层级先验、成本预算和动作频率；不重置错误接受预算 |

### 6.8 一个端到端例子

场景：孩子做分数题时连续说“不会”，家长立即替孩子完成。

1. 感知器记录两次放弃语句、家长接管、无孩子后续作答；
2. 状态层给出两个竞争假设：“挫败升高”0.61、“前置知识缺失”0.32；
3. 动作库给出“等待 + 最小提示”和“降一级诊断题”两个适用动作；
4. 家庭 playbook 显示：晚间先给完整解释时孩子常停止参与；周末上午最小提示曾两次执行但证据不足；
5. 当前 policy 选“等待 5 秒后给最小提示”，给家长一句话术；
6. 日志分别记录家长是否看到、是否真的等待、孩子是否尝试第一步、3 分钟内情绪/参与和 7 天无提示迁移；
7. ACE 只能把这些数据写为“候选经验”；若该类别正在 MRT，则效果按随机分配分析；
8. 足量后，候选动作路由只有在儿童延迟结果和家长行为链同时通过时才进入 active playbook。

## 7. 四个基础的逐项改造，以及从其他工作借什么

### 7.1 RegulaTutor：从纵向学生辅导器改成亲子干预分析骨架

#### 保留

- 从长历史中检索可引用证据，而不是只看最近一轮；
- 区分观察证据、状态解释和策略；
- 把认知、情绪、元认知、动机作为不同但相互作用的状态面；
- PairRoute 式故障定位：问题在模型能力、harness/上下文，还是二者混合；
- 独立证据正确性与诊断/策略正确性评分。

#### 删除或降权

- 删除直接对学生生成教学回复的默认路径；
- 不把论文基准上的纵向辅导得分当作家庭效果；
- 不依赖某个专有模型才能工作的 prompt 技巧；
- 不把状态解释保存为不可更改的“孩子画像”。

#### 改造成四阶段家长建议器

| 阶段 | 输入 | 输出 | 核心检查 |
|---|---|---|---|
| E：Evidence | 当前事件 + 历史账本 | 带时间戳、说话人、置信度的证据集合 | 每个结论是否能回到原始片段 |
| H：Hypotheses | 证据 + 家庭/学习状态 | 竞争状态假设与不确定性 | 是否列出替代解释；是否越过证据 |
| A：Action | 假设 + 冻结动作库 + 家庭 playbook | 1 个首选、最多 2 个备选动作 | 是否满足适用条件；有无更简单动作 |
| O：Observation | 动作 + 实验设计 | 执行定义、近端与延迟观察窗口 | 结果能否观测；能否区分未执行与无效 |

原 CAMM 维度不直接复制。首版状态建议为：

- **学习**：知识点掌握、提示依赖、检索成功、错误类型；
- **调节**：挫败/唤醒、恢复时间、回避/坚持；
- **家长行为**：具体表扬、问题/提示等级、指令清晰度、接管、批评、等待；
- **关系/情境**：回应性、共同注意、活动、时间、疲劳代理；
- **不确定性**：每项来源、时间衰减和竞争解释。

#### PairRoute 的本地化

把原来的模型/脚手架路由扩为五类故障：

1. **P：Perception**——说话人、ASR 或事件识别错误；
2. **S：State**——证据正确，但状态解释错误；
3. **C：Content**——动作库选择或干预内容错误；
4. **D：Delivery**——建议太长、时机不对、家长没看到或难执行；
5. **E：Evaluation**——结果定义、执行记录或归因错误。

每个失败必须归到最小可修改组件。感知错时不编辑建议 prompt；家长没执行时不把动作标成对孩子无效。

#### 工程落地

RegulaTutor 没有公开代码，所以只实现接口和测试：

- `retrieve_evidence(event_window)`;
- `propose_hypotheses(evidence, state)`;
- `select_action(hypotheses, action_library, playbook)`;
- `define_observation(action)`;
- `route_failure(trace, outcomes)`.

用 Recuris 的结构化轨迹/检查器和 Regimes 的 append-only 事件图承载实现；以论文报告的 Gold1000 提升作为“为什么采用此分析思路”的支持，不当作本系统预期提升。

### 7.2 FAFO + FAPO：从模拟零售反馈扩增改成家庭稀疏反馈工厂

#### 角色边界

- **FAFO**：整理日志和少量反馈，产出评价指南、逐案例 rubric、memory cards 和候选流程数据；
- **FAPO**：在冻结训练/验证数据上搜索 prompt、超参数、工具顺序和流程结构；
- 二者都不能直接给 ACE 条目盖“有效”章，也不能仅凭合成评分推广策略。

#### 输入信号分级

| 级别 | 信号 | 可用于什么 | 不能用于什么 |
|---|---|---|---|
| F0 | 无反馈的亲子事件 | 发现覆盖盲点、生成待标注案例 | 判断动作有效 |
| F1 | 家长点赞、接受、编辑或跳过 | 可用性、措辞、时机 rubric | 儿童受益 |
| F2 | 家长自报执行 + 自动检测目标行为 | 执行链和忠实度 rubric | 单独证明因果效果 |
| F3 | 孩子近端结果 | 机制和短时排序 | 长期推广的唯一依据 |
| F4 | 预定义延迟儿童结果 | 真实候选确认 | 脱离随机分配做反事实标签 |
| F5 | 专家/家长对证据与建议的分项编辑 | 高质量内容与故障标签 | 代替真实家庭结果 |

#### 改造后的 FAFO 流程

1. 对 F1–F5 反馈聚类，形成“何时算好建议”的候选规则；
2. 家长/专家只审核规则，不要求逐条标所有日志；
3. 为 F0 日志生成**候选**逐案例 rubric，并标明推断来源；
4. 用多模型/多视角生成 rubric 时保留分歧，不用平均分掩盖；
5. 只有真实随机结果能把 rubric 从“合成”升级为“经验校准”；
6. memory cards 保存可迁移的评价经验，不保存家庭身份性事实；
7. FAPO 在 discovery 数据上优化流程，在隐藏时间/家庭留出上评分；
8. 产出 staged candidate，交给 SkillOpt-Sleep 生命周期。

#### 防止自证循环

不得让同一个模型：

```text
生成建议 → 生成“正确答案”rubric → 给自己的建议打分 → 自动上线
```

至少分开：

- 提议模型；
- rubric/证据构造模型；
- 隐藏 evaluator；
- 真实随机结果。

模型分开只能降低相关误差，不能创造因果证据，所以最后一层不可省。

#### FAPO 可以优化什么

- 检索窗口和证据压缩格式；
- RegulaTutor 四阶段 prompt；
- 动作库过滤、候选数和路由顺序；
- 输出长度、解释层级、建议时机；
- 辅助模型选择与调用预算；
- 低置信度阈值和是否转人工确认。

首版不允许优化：

- 动作库的干预原理；
- 主要儿童结局；
- 正式 eligibility；
- 正式推广阈值；
- 实验进行中的随机化概率。

### 7.3 SkillOpt + SkillOpt-Sleep：从任务技能优化改成建议策略发布系统

#### 技能拆分

不要把全部系统写成一个巨型 `SKILL.md`。按可独立归因的单元拆分：

1. `evidence_extraction`：证据引用；
2. `state_hypothesis`：竞争解释和置信度；
3. `learning_support`：作业/阅读/数学动作；
4. `emotion_coaching`：情绪命名、验证、边界和共同解决；
5. `anxiety_parent_support`：支持、减少迁就、分级面对；
6. `behavior_parenting`：具体表扬、清晰指令、强化和后果；
7. `family_personalization`：从 playbook 个性化但不越过证据；
8. `parent_delivery`：短、具体、可执行的成人侧表达；
9. `outcome_definition`：为动作定义执行和观察窗口；
10. `failure_routing`：P/S/C/D/E 故障定位。

一个候选只改一个或少量相邻技能，方便回归、归因和回滚。

#### 四类离线数据

| 数据集 | 用途 | 提议器是否可见 |
|---|---|---|
| discovery/train | 从失败提议修改 | 可见 |
| fixed hidden holdout | 防止在同一案例上“学答案” | 不可见 |
| rolling future holdout | 检查未来时间漂移 | 在评估前不可见 |
| protected counterexamples | 检查常见越界、不适用和感知错误传播 | 只返回失败类别，不返回答案 |

SkillOpt 论文的“逐项不退步”保留，但扩为：

- 建议质量不能退；
- 证据引用不能退；
- 家长执行率不能退；
- 主要儿童结果需要优效或达到预设最小效应；
- 其他建议类别不得出现实质回归；
- 成本/延迟不能超过预算。

#### Sleep 的本地化

- 每晚离线 replay，不在家庭互动进行中修改技能；
- rejected edits 进入缓冲，供后续 meta-skill 学习；
- staged 候选在影子模式输出，与 incumbent 做盲评；
- 家长可以看 diff、原因、正反例和预期影响后接受进入真实确认；
- 本系统把 Sleep 的采纳按钮改名为**“批准进入真实确认”**，避免误解为效果已证明；
- 真正替换 active policy 由第 11 节的真实推广门决定。

Sleep 官方压力测试是 preview 文档中的受控自报，不是同行评审的家庭部署证据；本文只借其交互和版本生命周期。

#### meta-skill 的评价

不能因 meta-skill 改写了自己就称为 RSI 成功。至少比较：

- 相同 token/rollout/时间预算；
- 相同训练和隐藏集；
- 多个独立候选周期；
- 后续候选的隐藏集通过率；
- 最终真实推广率和每次有效推广成本。

只有后续修改变得更好，才算改进器增益；单次建议分数提高只算留存增益。

### 7.4 ACE：从通用 agent playbook 改成家庭级经验层

#### 条目 schema

```yaml
playbook_item_id: "fp_203"
family_id: "family_01"
context:
  activity: "晚间数学作业"
  child_state_hypothesis: "挫败上升"
  parent_behavior_before: "快速接管"
action_id: "learn.scaffold.wait_then_hint.v2"
mechanism: "增加孩子自主尝试机会"
evidence:
  randomized_assignments: 4
  delivered: 4
  executed: 3
  target_parent_behavior_observed: 3
  proximal_child_positive: 2
  delayed_child_positive: 1
  conflicting: 1
helpful: 1
harmful_or_worse: 0
uncertain: 3
valid_from: "2026-10-01"
last_supported_at: "2026-10-14"
status: "candidate"
```

#### 关键改造

1. ACE 原有 helpful/harmful 计数扩成完整执行链；没有执行时标为“不可判”，不是 harmful；
2. 家长喜欢或接受建议只能更新 `delivery_preference`，不能更新儿童效果；
3. 每条经验绑定具体动作库版本、上下文和 observation window；
4. 条目是增量、局部修改，禁止每晚重写整份家庭总结；
5. 竞争条目并存，保留矛盾证据；
6. 事件来源和随机 assignment 可追踪；
7. 长期无新证据时降低排序权重，但不删除历史；
8. 只有通过本家庭真实门的条目变成 `active`；其余为 `candidate` 或 `uncertain`；
9. 跨家庭汇总只生成全局 skill 的候选，不直接复制到另一家庭；
10. 负面条目优先用于过滤不适用动作，不自动产生相反动作。

#### 防止 context collapse

ACE 的核心价值是小步增量而非反复总结。实现时限制：

- 一次最多增加或修改少量原子条目；
- 原始证据和旧版本永不因摘要而消失；
- playbook 检索按活动、状态、动作和最近证据，不把全部条目塞进上下文；
- 合并近义条目前，必须证明上下文和机制相同；
- 删除只做 tombstone，保留决策历史。

## 8. 亲子感知、事件账本、家庭与学习状态

### 8.1 为什么音频优先、视频后置

首版要回答的不是“孩子现在究竟是什么情绪”，而是：

- 谁在说话；
- 说了什么；
- 家长用了哪类可观察行为；
- 孩子如何回应；
- 当前发生了什么作业/学习事件；
- 是否出现值得给家长一个动作的 episode。

这些问题主要由音频、文本和任务日志回答。视频可能补充共同注意、姿态和操作对象，但会显著增加处理量，而且现有公开亲子多模态研究多是低龄、实验室、小样本。DAMI-P2C 最佳音频模型对儿童 arousal 的 Spearman `ρ=.547`、对 valence 仅 `.221`【论文自报】，也说明“唤醒”比“正负情绪意义”更容易从声音估计。视频应在音频基线后做增量消融，而不是首版依赖。

### 8.2 音频流水线的具体选型

#### 1. 前处理

- 16 kHz 单声道分析副本，同时保留原始音轨；
- AEC、降噪、VAD 和重叠语音检测；
- 不提前删除低置信片段，只给质量标签；
- 所有模型输出映射到同一绝对时间轴。

#### 2. 说话人

- 默认：[NVIDIA Nemotron 3 Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization)，100M 参数，最多八位说话人，支持流式/离线和重叠；DIHARD III full DER `12.73%`（30.4 秒配置）和 `13.18%`（1.04 秒配置）【项目/厂商自报】。
- 独立 challenger：[pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)；通用 DIHARD 3 full DER `20.2%`【项目/厂商自报】。
- 用数段家长/孩子 enrollment 音频，把匿名 speaker cluster 映射到稳定家庭身份。
- [USC child-adult diarization](https://github.com/usc-sail/child-adult-diarization)只作成人/儿童角色辅助票。其 ADOS 8–13 岁结果 DER `56.8%`，差于 VBx `46.8%`【论文自报】，不能作为主分离器。

Nemotron 与 pyannote 的通用数字不能证明家庭效果。真正选型依据是自家金标准家庭测试集上的 speaker-attributed WER、child/adult confusion、overlap F1 和最终事件 precision。

#### 3. ASR

- 中文、方言、混说和成人：默认 [Qwen3-ASR 1.7B](https://github.com/QwenLM/Qwen3-ASR)，0.6B 作低成本 challenger；
- 英语儿童：[Pasketti](https://huggingface.co/drivendata/pasketti-word)，其 148 小时、2,300 多名儿童的 held-out 集报告 `17% WER`，但不能外推到长时远场家庭噪声【项目/厂商自报】；
- 中文本域微调/评测：[ChildTalk](https://aclanthology.org/2026.findings-acl.251/)，112.5 小时、498 名 2–8 岁儿童和 500 名照护者；Qwen3-ASR-1.7B 加 3 轮上下文后附录错误率 `17.01→14.07`，但正文/附录把指标分别称 CER/WER，文档不替作者判定；
- 每段保存词级时间戳、N-best、语言路由、置信度和声学质量；
- 数学表达、姓名、教材术语使用家庭词表重评分。

#### 4. 级联与 challenger

[USC 联合 ASR/角色分离](https://arxiv.org/abs/2601.17640)可做短片段 challenger，但 Playlogue 上 Whisper-large 的 WER/DER 为 `32.2%/42.6%`，联合模型 DER 还差于 diarization-first 的 `36.4%`【论文自报】。因此首版保留易于逐层诊断的级联方案。

### 8.3 从话语到事件

#### 低推断话语标签

综合 DPICS、Playlogue、SpecialTime 和 Homework Wars，首版标签：

- 家长：具体表扬、笼统表扬、行为描述、反映、开放/封闭问题、中性陈述、直接/间接命令、提示、纠错、批评、给答案、接管、鼓励、情绪命名、验证、边界；
- 孩子：作答、解释、提问、同意/执行、不执行、拒绝、求助、放弃语句、正/负话语；
- 互动：打断、重叠、等待时间、回应关系、话轮占比、命令—回应配对；
- 学习：知识点、题目、尝试、正确/错误、提示等级、提示后作答、无提示迁移；
- episode：重复错误、提示升级、接管循环、冲突升级、挫败上升和恢复。

[Playlogue](https://doi.org/10.1145/3699775)约 33 小时，其中约 5 小时、8,668 个 DPICS 标签；其 GPT-4 家长八分类 accuracy `77.70%`、macro-F1 `48.09%`，Reflection recall 约 `2.26%`【论文自报】。这说明高 accuracy 会掩盖稀有而重要的标签，生产门应看逐类 precision/recall、macro-F1 和 abstention 曲线。

[Homework Wars](https://doi.org/10.1145/3749517)提供最贴近目标场景的中文小学作业本体：78 个家庭、602 次会话、约 475 小时、18 类家长行为和 7 类冲突。其 `κ=.724/.517` 仅对应抽样的已切分文本上行为/冲突编码，不覆盖端到端音频发现。行为与冲突的相关也不能解释为某行为导致冲突。

#### 多轮分类而非单句情感

- 先检测可编码事件，再做多标签分类；
- 输入当前话语前后 3–8 轮、说话人、停顿、重叠、韵律和任务状态；
- 同一片段可同时有“命令 + 批评 + 接管”，不强迫单标签；
- arousal 用音频，valence/功能用文本、上下文和任务日志；
- 状态解释在事件层之后产生，不由“负面音调”直接等同于焦虑或敌意。

### 8.4 端到端感知评测

固定家庭隔离和时间前推测试，并按年龄、语言、噪声、设备和第三人加入分层：

| 层 | 指标 | 最重要的失败问题 |
|---|---|---|
| diarization | DER/JER、child miss、adult-child confusion、overlap F1 | 建议引用错人 |
| ASR | WER/CER、speaker-attributed WER、数学表达错误率 | 关键动作/否定词转错 |
| 轮次结构 | boundary F1、回应边 F1、打断 recall/FPR | 把相邻话轮错配 |
| 行为事件 | event AUPRC、边界 IoU、逐类 P/R、macro-F1、ECE/Brier | 稀有类被 accuracy 掩盖 |
| episode | AUROC/AUPRC、提前量、每小时假警报 | 频繁无效提示 |
| 建议证据 | 引用正确率、来源可追溯率、abstain 后 precision/coverage | 错证据产生合理建议 |

必须做四组级联消融：

1. 金标准 speaker + 金标准 transcript；
2. 自动 speaker + 金标准 transcript；
3. 金标准 speaker + 自动 transcript；
4. 自动 speaker + 自动 transcript。

这能回答瓶颈到底在 diarization、ASR 还是行为模型，而不是只看到最终分数下降。

### 8.5 双时态事件账本

每条记录同时保存：

- `valid_time`：家庭事件实际发生时间；
- `transaction_time`：系统何时写入或修正；
- 音频区间和内容哈希；
- 模型、prompt、词表和本体版本；
- N-best、标签后验和 abstain；
- 人工修正及被替代版本；
- 派生事件的父证据；
- 是否被某次建议/实验使用。

例子：

```text
10-01 19:43 实际发生：speaker_2 说“别管我”
10-01 20:00 ASR v4 记录为“别怪我”
10-02 08:10 家长修正为“别管我”
10-02 08:12 状态视图重算，但原 ASR 记录仍存在
```

[Graphiti](https://github.com/getzep/graphiti)可提供有效时间/摄取时间和事实失效图；[Hindsight](https://github.com/vectorize-io/hindsight)可提供事实、经历、摘要和信念分层。但二者都只是账本上的可重建检索投影。其发布方 LongMemEval 数字协议不同，不能拿 `71.2%` 和 `83.6%` 直接排名，更不能让图数据库成为唯一真值。

### 8.6 家庭状态模型

状态不是一段“家庭画像”，而是一组可校准时变变量：

| 状态 | 观测输入 | 表示 | 更新 |
|---|---|---|---|
| 家长目标行为率 | 表扬、问题、命令、接管等事件 | Beta-Binomial 或层级 logistic | 每个合格机会 |
| 提示响应 | 送达、看到、接受、执行 | 分阶段 Bernoulli/hazard | 每个决策点 |
| 互动动态 | 命令→拒绝→升级→让步等序列 | 事件转移/episode 模型 | 每段会话 |
| 挫败/唤醒 | 韵律、放弃语句、错误循环、恢复 | 带不确定性的连续状态 | 秒/轮级，快速衰减 |
| 情境 | 活动、时间、任务难度、疲劳代理 | 结构化上下文 | 事件级 |
| 家庭偏好 | 建议长度、时机、语气、UI 选择 | ACE preference 条目 | 家长明确反馈 |
| 动作效果 | 随机分配、执行链、儿童结果 | 分层贝叶斯/序贯统计 | 观察窗口结束 |

所有心理状态必须带：

- 源证据；
- `confidence`；
- `valid_from/to`；
- 替代解释；
- 衰减规则；
- 是否经过家长确认。

系统不从一两段音频推断稳定人格。原因不是敏感性，而是这种高推断标签不可可靠验证，会污染后续动作选择。

### 8.7 学习状态：BKT、IRT、FSRS 各司其职

只有同时有 `knowledge_component + item + response + correctness + hint + latency` 的事件进入学习模型。

1. **BKT / [pyBKT](https://github.com/CAHLR/pyBKT)**：追踪每个知识点的 mastery、learn、guess、slip，可扩展 forget 和题目差异。它回答“这个知识点当前掌握概率是多少”。
2. **IRT / [py-irt](https://github.com/nd-ball/py-irt)**：标定孩子能力和题目难度/区分度，避免把难题上的错误全当不掌握。它不建模学习过程。
3. **FSRS / [fsrs-rs](https://github.com/open-spaced-repetition/fsrs-rs)**：根据确认过的回忆结果安排复习。生产基线用正式发布的 FSRS-6；FSRS-7 只作主分支 challenger。它不负责掌握诊断或教学策略。

结构化模型输出进入 RegulaTutor 的证据层，LLM 负责解释，不允许 LLM 凭聊天印象覆盖 mastery 数值。

### 8.8 最小反馈 UI

家长看到每条建议时可分别点：

- “不是我/不是孩子”；
- “听错了”；
- “事情理解错了”；
- “建议不适用”；
- “我会/不会做”；
- “已做”；
- “孩子随后如何”。

不同按钮分别更新感知、状态、交付偏好、执行链和结果，不能合成一个 reward。自由文本编辑同时保留原建议与 diff，供 FAFO 和 SkillOpt 使用。

## 9. 版本化的教育与心理证据动作库

### 9.1 证据等级

| 等级 | 定义 | 可以声称什么 |
|---|---|---|
| A | 具体动作或提示本身被随机操纵 | 对研究人群、情境、剂量和结局有动作级因果证据 |
| B | 整个干预包随机，动作是包内组成 | 干预包有效；不能把全部效果归给单项动作 |
| C | 组件元回归、中介、调节或机制证据 | 该组件可能是有效成分，仍需本系统单独确认 |
| D | 观察相关或跨人群/场景迁移 | 用于提出候选，不声称因果 |
| E | 可行性、HCI 或产品设计 | 支持怎么呈现/使用，不支持儿童效果 |

同一动作可标 `B+C`：它属于有效的随机干预包，同时跨试验组件分析提示该成分与更大效果相关。

### 9.2 每张动作卡的完整字段


### 9.3 外化行为、不服从与冲突

首批动作：

1. 目标行为出现后立即**具体表扬**；
2. 把奖励绑定到可观察行为，及时稳定兑现；
3. 一次给一个清楚、可执行的指令并等待；
4. 预先说明自然/逻辑后果，平静一致跟进；
5. 在非冲突时间增加积极关注、反映和行为描述；
6. 识别“命令 → 拒绝 → 升级 → 家长让步”循环，在升级前换动作。

证据边界：

- [Leijten 等的 154 项随机试验元分析](https://pubmed.ncbi.nlm.nih.gov/30738545/)中，儿童问题行为效应随人群从普遍预防 `d=-.21`、选择性预防 `-.27`、指征预防 `-.55` 到临床治疗 `-.69`；随机的是**整个家长方案**。正强化、具体表扬、自然/逻辑后果与更大效果相关，但这是跨试验组件元回归，不是单动作随机；42 项长期试验中没有组件预测更强长期效果【独立/第三方】。
- [PMT/PCIT 的 25 项 RCT 元分析](https://doi.org/10.1007/s10578-022-01367-y)，N=2,023、2–13 岁：PMT 对家长报告破坏行为 `g=.64`、育儿技能 `.83`、儿童社交技能 `.49`；PCIT 相对等待名单 `g=1.22`【独立/第三方】。两者研究年龄和对照不同，不能用 `.64` 与 `1.22` 得出 PCIT 必然更优。
- [4–12 岁家长小组干预元分析](https://doi.org/10.1007/s10578-017-0745-9)，21 项 RCT：外化 `g=-.38`、内化 `g=-.18`【独立/第三方】，是目标年龄较直接的总体估计。

因此上述动作标 `B` 或 `B+C`，不是 `A`。系统可以把它们产品化，但不得把某一句“具体表扬”写成已有动作级 RCT 效应。

### 9.4 焦虑、回避和家庭迁就

首批动作：

1. 在表达理解的同时传递“我相信你能面对”的信心；
2. 识别并逐步减少替孩子回避、代做、反复保证等家庭迁就；
3. 与孩子约定可完成的分级面对步骤；
4. 在步骤后复盘实际结果，而不是只讨论灾难预测；
5. 保持支持，但不把短时焦虑下降作为唯一目标。

证据边界：

- [SPACE 随机非劣试验](https://doi.org/10.1016/j.jaac.2019.02.014)：124 名 7–14 岁儿童，12 次纯家长 SPACE 对 12 次纯儿童 CBT 非劣；独立评估者反应 `87.5% vs 75.5%`、缓解 `58.3% vs 59.2%`，家庭迁就在 SPACE 下降更多【独立/第三方】。
- [Co-CAT](https://doi.org/10.1016/s2215-0366(23)00429-7)：444 名 5–12 岁儿童、34 个真实服务点；在线家长主导 CBT + 治疗师支持在 26 周 CAIS-P 相对常规治疗非劣，`SMD=.01 [-.15,.17]`，非劣界值 `.33`【独立/第三方】。
- [纯家长 CBT 元分析](https://pmc.ncbi.nlm.nih.gov/articles/PMC7802251/)：6 项 RCT、N=407；对等待名单 `SMD=-.72`、缓解 `RR=4.33`，但区间宽、异质性高，且相对含儿童 CBT 的退出率更高 `RR=1.93`【独立/第三方】。

这些是 `B`：随机的是 SPACE/CBT 包，减少某一次保证、某一级暴露并未独立随机。系统早期应推荐动作库中的方案步骤，并用本家庭随机/多基线数据确认时机和剂量。

### 9.5 情绪辅导与共同解决问题

首批动作：

1. 先用中性词描述可观察线索；
2. 邀请孩子给情绪命名，不替孩子断言；
3. 简短验证体验；
4. 把“情绪可以存在”和“某些行为有边界”同时说清；
5. 唤醒下降后再共同定义问题和选择一步行动；
6. 会后复盘触发、恢复和下次计划。

示例：

> “你已经改了三次，听起来很泄气。泄气可以，撕作业不行。我们先停两分钟，然后你选：我给一个提示，还是换一道容易点的？”

证据边界：

- [情绪导向家长干预综述/元分析](https://doi.org/10.3389/fpsyg.2023.1159892)：29 项量化研究，外化 `d=.31`、内化 `.25`；但混合 RCT、准实验和无对照设计，年龄 1.5–18 岁、过半集中 3–6 岁，偏倚均为中或严重【独立/第三方】。
- [Tuning in to Kids Online RCT](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2024.1393708/full)：分析 150 名家长，儿童 4–10 岁；6 个月家长情绪否定中等下降，同理/教练/效能小幅改善；家长报告儿童焦虑小幅改善，但儿童行为交互和教师报告不显著【论文自报】。

动作标 `B+C`，不能写成“情绪验证这一句话已被动作级 RCT 证明”。

### 9.6 家庭阅读与语言

首批动作：

- 让孩子预测、解释和复述；
- 家长等待并接续孩子回答，而不是立即给答案；
- 用开放问题、扩展和联系生活经验促进意义建构；
- 低年级按需要加入音素、解码、重复阅读等结构化练习；
- 记录孩子独立阅读/理解，而不只记录共同活动次数。

[学龄家庭实施读写干预综述](https://doi.org/10.1007/s10648-025-09985-3)含 22 项研究、25 个干预；12 项组间设计 N=972，总体 `g=.36`、代码技能 `.28`、意义技能 `.41`【独立/第三方】。组间设计含实验和准实验，18/22 主要为 K–2，不能统一称 RCT 或直接外推高年级。

[2026 对话式阅读元分析](https://doi.org/10.1016/j.ijer.2026.102963)的总体效应更大，但没有限定家长实施，混合学前至小学，且标准化测验效果更小。它作为 `C/D` 的内容支持，不作为家长单动作的效应量。

### 9.7 家庭数学与作业脚手架

首批动作：

1. 用短数学故事或日常数量问题让孩子解释；
2. 作答前给等待时间；
3. 提示按“开放问题 → 定向线索 → 部分步骤”逐级增加；
4. 提示后要求孩子自己完成下一步；
5. 先诊断前置知识，而不是反复重复同一解释；
6. 以无提示迁移题衡量是否学会；
7. 作业时支持选择和解释，减少直接接管。

证据边界：

- [非正式家庭数学干预元分析](https://doi.org/10.3102/00346543231156182)最终期刊版含 25 项干预、83 个效应量，学前至三年级，`g=.26 [.07,.45]`【独立/第三方】；研究混合实验和准实验。较早作者稿为 23 项、81 个效应量、`g=.28 [.08,.48]`，两组版本数字不能混用。
- [Bedtime Math 随机现场试验](https://doi.org/10.1126/science.aac7427)含 587 名一年级儿童，数学故事 app 对阅读 app，一学年数学进步更大，高数学焦虑家长家庭获益更明显【独立/第三方】。按本文定义，完整 app/重复活动是有随机证据的干预包 `B`；从中拆出的“一次短数学故事”没有单独随机，不标 `A`。“约三个月优势”是新闻稿解释性换算，不是标准化效应。
- [一般人群作业参与元分析](https://doi.org/10.7334/psicothema2023.92)含 28 项研究、N=378,222：总体 `r=-.064`，自主支持 `r=.164`；这是纯相关证据【独立/第三方】，所以一般“作业自主支持”标 `D`。
- [ADHD 作业专项随机试验](https://pmc.ncbi.nlm.nih.gov/articles/PMC5280087/)含 75 名 5–12 岁儿童，作业 BPT + 每日报告卡相对等待名单的客观完成/准确 `d=1.40–2.21`【独立/第三方】；这是专项干预包 `B`，不能外推成一般家庭多监督作业。

### 9.8 成人侧反馈如何转成产品原则

| 证据 | 因果范围 | 产品原则 |
|---|---|---|
| Tutor CoPilot | 系统分配改善近端 exit-ticket；单项建议未随机；年终成绩无显著改善 | 建议附一句可直接执行的话术，但仍测延迟结果 |
| TeachFX | 在已有基础反馈上，专项聚焦问题反馈使该行为增加约 20%；无儿童结局 | 一次只反馈一个可观察家长行为 |
| M-Powering Teachers | 会后反馈改变高中导师 uptake、提问/复述和说话比例 | 首版优先会后可核查复盘，不必一开始追求实时 |
| PACEE | 低龄小型实验室研究增加即时谈话轮次和情绪词 | 使用结构化脚手架；不声称长期心理效果 |
| COMPASS | 家长频繁切换协作模式 | 让家长控制“只总结/给话术/解释/不提示” |
| PaiCoach | 4 个个案出现功能关系，但 31.4% 输出需专家修改 | 输出支持编辑；“需修改”不是错误率 |

### 9.9 动作选择规则

1. 先按可观察 trigger 和年龄/人群过滤；
2. 优先证据等级更高、对目标年龄更直接的动作；
3. 再按家庭 playbook 和当前状态排序；
4. 一次首选一个动作，最多两个备选；
5. 每个动作必须有执行定义和观察窗口；
6. 没有合适动作时 abstain，不由 LLM 即兴创造；
7. 真实结果只改路由/剂量和家庭经验；修改通用动作内容要重新走证据维护流程。

### 9.10 首版动作库规模

起步建议不是收录数百条育儿技巧，而是约 20–30 张原子卡：

- 外化/亲子行为 6–8 张；
- 焦虑/回避 4–6 张；
- 情绪辅导 4–5 张；
- 阅读 3–4 张；
- 数学/作业 5–7 张。

每张卡先在 5–20 个金标准案例上验证 trigger、反例和输出，再开放真实决策点。动作少使每类能更快积累足量随机证据，也降低 ACE 把偶然成功拆成过多稀疏条目的风险。

## 10. 目标函数、指标和 estimand

### 10.1 不用一个混合 reward 隐藏失败

建议质量采用分层目标，而不是把点赞、执行、孩子结果、成本加权成一个容易被优化器钻空子的数：

1. **有效证据约束**：引用真实片段、状态和证据匹配、动作存在于冻结库；
2. **与效果主张匹配的主要儿童结局**：短时反应可预先指定近端结局；凡主张持续的教育或心理改善，必须指定延迟结局；
3. **家长目标行为和执行链**：解释机制；
4. **儿童近端反应**：检查是否沿预期路径；
5. **其他儿童/家庭结果不退步**；
6. **家长负担、提示频率、延迟和计算成本**。

推广首先看第 2 项是否达到最小有意义改善，并要求第 1、5 项过门；不能用“更喜欢、更常点开、成本更低”补偿儿童结果无效。

### 10.2 完整指标漏斗

| 层 | 指标 | 作用 |
|---|---|---|
| eligibility | 可行动事件数、可用率、abstain/原因 | 系统有多少真实机会 |
| assignment | 随机概率、propensity、分层平衡 | 因果可识别性 |
| delivery | 送达、看到、延迟、重复提示 | 判断交付失败 |
| acceptance | 接受、编辑、跳过、理由 | 可用性与偏好 |
| execution | 是否执行、剂量、忠实度、自动/自报一致性 | 关键中介 |
| parent behavior | 等待、具体表扬、接管、迁就等目标行为率 | 建议是否改变成人 |
| child proximal | 尝试、合作、恢复、暴露完成、即时掌握 | 短时主张可作主要结果；否则是机制结果 |
| child distal | 无提示迁移、周级行为率、功能/回避变化 | 持续效果主张的主要结果 |
| burden/cost | 提示数、查看时长、编辑率、模型调用和延迟 | 次级优化 |

### 10.3 各域建议的预定义结果

| 建议类别 | 执行 | 近端结果 | 建议的持续效果确认结局 |
|---|---|---|---|
| 等待 + 最小提示 | 家长是否等待并只给规定提示级别 | 孩子是否自主发起下一步、3 分钟内再投入 | 同知识点 7 天无提示迁移 |
| 具体表扬 | 合格机会后是否具体表扬 | 下一同类机会合作、当次冲突是否升级 | 2–4 周目标合作行为率 |
| 清晰指令 + 一致跟进 | 指令是否单一、可执行、留等待并跟进 | 一次指令后的执行、升级时长 | 2–4 周问题行为/合作率 |
| 情绪验证 + 边界 | 是否先验证并给清楚边界 | 恢复时间、共同解决是否开始 | 2–4 周可观察调节/冲突 episode |
| 减少迁就 + 分级面对 | 家长是否按计划减少迁就并支持步骤 | 步骤完成、回避是否中断 | 2–6 周目标活动参与/功能 |
| 共同阅读/数学故事 | 是否完成规定互动与等待 | 孩子解释、复述、独立解题 | 7–14 天标准化或平行迁移题 |

每个正式候选只指定一个与其效果主张匹配、用于最终推广的主要儿童结果。若主张只限明确时间窗内的短时反应，可预注册近端结果；凡主张持续的教育或心理改善，主要结果必须是上表的延迟结局。近端与延迟结果都要预先记录，不能在看到结果后互换主次。

### 10.4 主要 estimand

主 estimand：

```text
ITT = E[Y | 随机分到 candidate] - E[Y | 随机分到 incumbent/control]
```

还应报告但不替代 ITT：

- **delivery effect**：作为实施诊断；
- **execution/complier 分析**：只有预先设计工具变量等方法时才作因果解释；
- **per-protocol**：描述性；
- **heterogeneous effects**：按预设情境分层，主要用于下一轮候选，不作为本轮补救显著性。

### 10.5 机制指纹

每个动作在入库时预注册一条机制链。例如：

```text
等待 + 最小提示
  → 家长接管率下降
  → 孩子独立尝试增加
  → 当场提示依赖下降
  → 7天无提示迁移上升
```

若最终分数提高但家长等待没有增加、孩子独立尝试没有增加，系统不能简单称动作按预期有效；需要检查测量、旁路机制或污染。机制指纹能发现“建议让家长直接报答案，因而当场正确率上升”这类奖励劫持。

## 11. 离线门、真实随机门与长期错误预算

### 11.1 离线门的职责

离线门只回答：

> 这个候选是否足够可信，值得消耗真实家庭的决策点？

它不回答候选是否真的改善孩子。

### 11.2 离线门顺序

#### Gate 0：完整性和零容忍约束

任何一项失败即拒绝：

- 引用不存在或证据片段与说话人不符；
- 把状态假设写成原始事实；
- 推荐动作不在冻结动作库，或不满足年龄/人群/情境；
- observation window 缺失；
- 读取隐藏留出答案或未来数据；
- 无法从版本、输入和随机种子重放输出；
- 同一案例被同时用于提议和隐藏评分。

#### Gate 1：机制与回归

- 证据引用、状态、动作和观察定义逐项评分；
- 检查预注册机制指纹；
- protected counterexamples 全部通过；
- 非目标建议类别不退步；
- 多次运行检查脆弱性，不挑单个最佳 seed。

#### Gate 2：配对隐藏集统计

同一案例由 incumbent 和 candidate 都运行，因此用配对方法：

- 二元对错：exact McNemar；
- 连续评分：以家庭或独立 episode 为 cluster 的 paired bootstrap；
- 多类别：逐类 paired 差异、macro 指标和预设校正；
- 同时报告点估计、区间、有效 cluster 数和最差家庭/类别。

正式 paired cluster bootstrap 起步建议至少 `10,000` 次重采样。更多重采样只能降低 Monte Carlo 误差，不能弥补独立家庭或 episode 太少。

#### Gate 3：盲评与 shadow

- 家长/专家看不到版本标签；
- 分别评证据、解释、动作、可执行性，不给单一总分；
- shadow 模式在新事件上运行但不影响建议；
- rolling future holdout 过门；
- 成本、延迟和 abstain coverage 在预算内。

通过 Gate 3 只进入 `staged`。

### 11.3 为什么 LLM 评委、模拟器、OPE 只能预筛

- LLM 评委与提议模型可能共享偏好和盲点；
- 模拟家庭不会真实承受时间压力，也不产生可靠儿童延迟结果；
- PedagogicalRL/Sherpa 的模拟学生适合发现明显差的学习建议，但没有家长执行中介；
- OPE 依赖正确 propensity、overlap 和未观测混杂假设；家庭策略、状态和执行会随时间变化；
- Future-Feedback 只能预测历史后续信号，不能知道未采用建议的结果。

因此这些工具用来减少进入真实试验的候选，不用来自动推广。

### 11.4 三种真实确认设计

#### A. 短时、可重复、残留小的建议：孩子—事件 MRT

适用：等待、提示等级、具体表扬提醒、问题类型、复盘时机。

在每个合格且家长可用的决策点，随机：

- candidate；
- incumbent 或无提示。

记录 availability 和实际随机概率。MRT 的主要因果 estimand 使用预定义近端窗口和 moderator；方法基础见 [micro-randomized trial](https://doi.org/10.1037/hea0000305)。它是即时机制门：若候选声称持续改善学习或心理结果，仍须通过第 10.3 节对应的延迟儿童结局；只有当产品主张明确限定为短时反应时，近端结果才可作为最终主要结局。Active Family 证明家庭 MRT 可运行，也以平均零效应提醒我们“及时”本身不等于“有效”。

#### B. 学习建议：知识点/技能簇随机

- 在不同但难度匹配的知识点或题目簇之间随机策略；
- 用 IRT 难度和基线 mastery 分层；
- 主要结果是 7 天左右的无提示平行迁移；
- 不对同一知识点做“学会后再回到基线”的 ABAB；
- 对污染明显的知识点簇整体分配，而非逐题切换。

#### C. 持续家长/心理技能：随机多基线

具体表扬、减少迁就、情绪辅导等技能可能迁移并持续。对多个：

- 行为类别；
- 家庭活动；
- 时间段；
- 或 1–3 个孩子

随机错开引入时点，观察目标行为是否只在引入后改变，并保留其他序列作并发对照。报告遵循单个案设计规范，如 [SCRIBE 2016](https://doi.org/10.1037/arc0000026)；视觉分析之外用随机化检验/层级模型。

### 11.5 N-of-1 能做什么，不能做什么

适合：

- 高频、定义清楚、短时可逆的结果；
- 有多次合格决策点；
- candidate 与 control 的 carryover 可估计或很小。

不适合：

- 已发生的知识学习；
- 家长已掌握且会持续使用的技能；
- 一次性重大事件；
- 结果窗口很长、同时发生很多共同变化。

对一个家庭可用 blocked randomization、washout/carryover 项、时间趋势和自相关稳健模型。对 1–3 个孩子，层级模型用于部分汇聚和估计异质性，但不把多个相关事件当作大量独立儿童。兄弟姐妹共享家庭环境和同一位家长，不能当独立样本；只在预先指定、方向一致的参数上做强收缩的部分汇聚，同时保留每个孩子的单独轨迹和推广判断。

### 11.6 冻结与随机化纪律

每次真实确认开始前冻结：

- candidate/incumbent；
- 动作库；
- eligibility 与 availability；
- 随机概率和分层；
- 主要/次要结局；
- observation window；
- 最小有意义效应 `δ_min`；
- 分析、缺失处理、停止和回滚规则。

同时只允许**一个冻结候选/建议类别**进入真实确认。这样一个结果能归到一个变化；多个类别可并行，但必须使用不同、预先划分的错误预算和避免相互污染的决策点。

### 11.7 Anytime-valid 正式门

普通固定样本 `p` 值不能在每晚查看后随时停止。使用与随机设计相匹配的 one-sided e-process 或 confidence sequence；时间一致置信序列基础见 [Howard 等](https://doi.org/10.1214/20-AOS1991)。

对“越大越好”的主要结果检验：

```text
H0: Δ ≤ δ_min
H1: Δ > δ_min
```

推广要求同时满足：

1. 与候选效果主张匹配的预注册主要儿童结果，其 anytime-valid 下界高于 `δ_min`；持续教育/心理改善必须使用延迟结果，MRT 近端机制结果不能单独替代；
2. 预设其他儿童/家庭 guardrail 的不劣界通过；
3. 家长执行链按机制方向变化，或有预先允许的替代机制；
4. 没有某个孩子持续、明显恶化而被总体平均掩盖；
5. 数据完整性、随机化和版本审计通过。

若下界长期不可能越过阈值，可按预注册 futility 规则停止。停止后候选不得换指标复活；修改后以新 attempt 重新进入 discovery。

### 11.8 生命周期错误接受预算

给整个系统/建议类别一个不可重置预算 `δ_life`。第 `k` 个正式候选分配：

```text
α_k = δ_life / [k(k+1)]
```

因为：

```text
Σ 1/[k(k+1)] = 1
```

所有 attempt 的总错误接受概率受 `δ_life` 约束。`δ_life=.05` 只是一个协议选择，不是科学常数；应按建议类别、主要结局和系统生命周期预先分配。拒绝、崩溃或看起来“几乎通过”的 attempt 都消耗已分配预算，不能重置编号。

### 11.9 小样本量的诚实计算

在极简 IID、两组等分、连续标准化结局、无自相关/cluster/carryover/缺失、执行率 100% 的假设下：

```text
N ≈ (z_(1-α/2) + z_(1-β))² / [p(1-p)d²]
```

当 `p=.5`、双侧 `α=.05`、功效 `.80`：

```text
N ≈ 31.4 / d²
```

于是粗略为：

| 标准化 ITT 效应 d | 独立决策点 N |
|---:|---:|
| 0.20 | 785 |
| 0.30 | 349 |
| 0.40 | 196 |
| 0.50 | 126 |

这些不是本系统承诺。家庭事件自相关、知识点 clustering、残留、测量误差和执行稀释都会增大需求。若只有一半被分配者实际执行，而动作对执行者的效应不变，ITT 约减半，所需 N 约增至四倍。

正确做法：

1. 先收集基线事件；
2. 估计每周合格决策点、cluster size、自相关、缺失、执行率和残留；
3. 按计划分析模型做 Monte Carlo power / expected stopping time 模拟；
4. 只有在可接受时间内能识别的 `δ_min` 才进入试验；
5. 无法区分的小效应标为未知，不因样本少就判无效或推广。

因此本文不声称“6–9 周足够”。有些高频近端行为可较快判断，儿童延迟学习或持续心理结果可能需要数月，1–3 个孩子也可能永远不足以确认小效应。

### 11.10 观察性日志的正确用途

随机试验前的历史日志用于：

- 估计 availability、方差、自相关和执行率；
- 发现候选 moderator 和动作不适用条件；
- 构造测试、rubric 和保护集；
- 为层级模型提供弱先验；
- 用 OPE 做候选排序。

不能用于：

- 把历史后续结果当未采用动作的标签；
- 从家长自选动作直接估计因果收益；
- 因 ACE helpful 次数多就自动推广；
- 在看到试验结果后更换主要结局。

### 11.11 回滚

每个建议记录 `policy_version + action_version + state_version + assignment_id`。若：

- 主要或 guardrail 的 anytime-valid 证据跨越预设恶化界；
- 感知版本产生系统性身份/证据错配；
- 执行链断裂且提示负担明显上升；
- 日志或随机化不完整；

立即停止该候选，恢复前一 incumbent。回滚不删除候选、结果或已消耗的错误预算。

## 12. 运行方式、模型分工与成本

### 12.1 模型按职责分工

| 职责 | 推荐 | 是否可由 RSI 修改 |
|---|---|---|
| diarization | Nemotron 3；pyannote shadow | 否，常规版本升级 |
| ASR | Qwen3-ASR 1.7B；英语儿童 Pasketti | 否，常规本域微调 |
| 事件编码 | 小型多标签模型 + 规则 + LLM challenger | prompt/阈值可提议，模型发布走常规流程 |
| 状态模型 | BKT/IRT、层级统计、确定性事件聚合 | 参数随证据更新；结构不自动改 |
| 建议推理 | 强推理 LLM，受动作库和技能约束 | SkillOpt/FAPO 修改技能/流程 |
| 家庭经验 | ACE 数据结构 + 检索器 | 增量条目受门控制 |
| rubric/候选 | 与建议模型角色隔离的 LLM | FAFO/FAPO 离线修改 |
| 正式统计 | 固定随机化、e-process/CS 实现 | 不允许 LLM 修改试验中的规则 |

不要为了“模型多样性”无条件调用多模型。独立 judge 只用于离线预筛；真实随机结果才是最终 evaluator。

### 12.2 本地优先的最小部署

单家庭吞吐很低，首版可在一张约 24 GB 显存 GPU 上串行运行：

- 100M diarization；
- 0.6B/1.7B ASR；
- 小型行为分类器；
- 量化 7B–14B 建议模型，或把建议模型放 API。

这是容量起步估计，不是硬件兼容承诺；实际显存取决于精度、上下文、实现和是否并发。建议用批量会后处理，把实时链路限制在 VAD/diarization/ASR 和少量触发检测。

### 12.3 成本公式

用可测参数预算，避免绑定易变的 API 报价：

```text
C_month =
  H_audio × (c_pre + c_diar + c_asr + c_event)
  + N_advice × c_reason
  + N_offline_eval × c_eval
  + C_storage
  + C_labeling
```

其中：

- `H_audio`：VAD 后真正处理的音频小时；
- `N_advice`：实际产生的建议，不是所有话轮；
- `N_offline_eval`：SkillOpt/FAPO 候选 × 案例 × seeds，通常是最大可控项；
- `C_labeling`：家长/专家分项修正，早期可能比推理更贵。

16 kHz、16-bit、单声道 PCM 约 `115 MB/小时`；Opus 视码率约为其一小部分。若每天录 3 小时、VAD 后保留 35%，每月模型处理约 `31.5 小时`。这只是示例，产品应先量真实活动率。

### 12.4 控制自改进成本

- 先用小模型和硬规则跑全部案例，强模型只看不确定/高价值片段；
- rubric 缓存并版本化，不为同一候选反复生成；
- successive halving：小样本淘汰明显差候选，再扩大隐藏集；
- 一个技能单元一次只保留少量 Pareto 候选；
- 只有离线过门者进入昂贵盲评；
- 真实确认期间停止该类别的新候选竞争；
- 报告每个 adopted improvement 的总 token、GPU、人工分钟和真实决策点成本。

### 12.5 延迟目标

| 阶段 | 起步目标 | 理由 |
|---|---|---|
| 会后摘要/建议 | 事件结束后 2–5 分钟 | 可重跑 diarization/ASR，证据更可靠 |
| 近实时候选提示 | 30–90 秒 | 只在静态系统已证明某动作有效后开放 |
| 真正实时耳机提示 | 暂不承诺 | Active Family 零效应和成人认知负担说明低延迟不自动有效 |
| 夜间改进 | 数小时内 | 完全离线，不影响互动 |

### 12.6 可观测性

每次建议 trace 至少包含：

- 音频与转写版本；
- 被引用 evidence IDs；
- 状态后验和替代解释；
- 被过滤/入选动作及原因；
- skills/playbook/model 版本；
- 随机 assignment 与 propensity；
- 送达、执行和结果事件；
- 成本、延迟和异常。

这不是访问安全审计，而是效果归因的必要条件。

## 13. 分阶段路线图和退出条件

时间只是起步估计，阶段能否结束由证据门决定。

### 阶段 0：定义与测量（约 2–4 周起）

交付：

- 选择 2–3 个首要家庭目标；
- 建立 20–30 张版本化动作卡；
- 建事件、状态、建议和实验 schema；
- 采集/标注家庭隔离的金标准音频；
- 跑 Nemotron/pyannote、Qwen3-ASR/Pasketti 基线；
- 只 shadow，不向家长推荐。

退出条件：

- 每个主要结局可观测、窗口明确；
- 关键行为标签有足够 inter-rater agreement；
- 在目标 coverage 下，证据引用和说话人 precision 达到预注册起步门；
- 可以从原始账本完全重建状态和建议 trace。

### 阶段 1：静态证据约束顾问（约 4–8 周起）

交付：

- RegulaTutor 式 E/H/A/O 流程；
- 冻结动作库和全局技能；
- 会后建议与分项纠错 UI；
- 无 ACE 自动学习、无 FAFO 自动 rubric、无真实推广。

只验证：

- 建议是否引用正确；
- 家长是否理解和执行；
- 目标家长行为是否能被观测改变；
- 提示负担和最佳交付时机。

退出条件不是点赞，而是在至少一个动作类别上看到稳定的“分配 → 看到 → 执行 → 目标家长行为”链。

### 阶段 2：家庭 playbook 与小型随机确认（约 8–16 周起）

交付：

- ACE 候选条目；
- 简单分层状态和 BKT/IRT；
- 一个高频、短时类别的 MRT 或 N-of-1；
- 一个持续技能的随机多基线；
- anytime-valid 仪表和回滚。

限制：

- playbook 不自动改通用技能；
- 同类别只测一个冻结候选；
- 首先验证较大的、可观测的效果，不追逐小效应。

退出条件：至少一个家庭动作路由在与效果主张匹配的儿童结果上通过正式门；若主张持续改善，该结果必须是延迟结局。另一种合格结论是诚实得到“在当前可识别效应和时间内无足够证据”。

### 阶段 3：SkillOpt-Sleep + FAFO/FAPO（约 8–12 周起，建立在阶段 2 上）

交付：

- discovery/fixed/rolling/protected 四套数据；
- FAFO 反馈指南、rubric 和 memory cards；
- SkillOpt 单元编辑、rejected buffer、meta-skill；
- staged/approval workbench；
- 离线门与真实门完整串联。

退出条件：

- 相同预算下，候选比手工维护流程有更高隐藏集通过率；
- 至少若干周期中没有非目标类别回归；
- 至少一个机器提议候选最终通过真实门；
- 每次有效改进成本可接受。

只有前两项仍只是改进器的离线证据；第三项才证明自改进对家庭结果产生留存增益。

### 阶段 4：实时性、跨家庭与改进器研究

可以逐项挑战：

- 会后建议 vs 近实时提示；
- 音频 vs 音频+视频；
- 简单层级策略 vs 有概率下限的 contextual bandit；
- 手工 meta-skill vs 自动改进器；
- Recuris 式局部修复 vs FAPO 流程搜索；
- 多家庭部分汇聚。

进入条件：

- 目标事件感知在真实环境中足够精确；
- 静态动作在本家庭已有真实效果证据；
- 每个动作都有足够探索概率；
- 有持续的真实随机数据和不可重置错误预算。

早期不上 bandit。1–3 个孩子的数据不足以同时学习大量上下文、动作和长期奖励；先用均匀/分层随机得到可识别数据，再让复杂策略做 challenger。

### 路线图总原则

```text
先证明测得准
  → 再证明家长会执行
  → 再证明孩子的延迟结果改善
  → 再让系统个性化
  → 再让系统修改建议技能
  → 最后才改进改进器和实时化
```

## 14. 效果风险、负面证据与停止条件

### 14.1 家长侧相对儿童聊天的机制优势与代价

截至检索日，没有找到“家长侧 AI”与“儿童直接聊天 AI”的头对头 RCT。因此以下是设计机制，不是已证的一般优越性。

可能优势：

- 家长可以结合现场非语言信息和家庭目标过滤建议；
- PMT、PCIT、SPACE、家长主导 CBT、家庭读写/数学已有成人执行路径；
- 系统能在自然互动中观察“家长动作 → 孩子反应”，而不仅是孩子对 AI 的回答；
- 同一个家长技能可能跨多个事件复用；
- 家长可修正证据和执行建议，产生比单一 LLM 评分更丰富的反馈。

代价：

- 每条建议都增加“送达 → 理解 → 执行”的稀释；
- 家长既是执行者又常是结果报告者，测量偏差更强；
- 成人压力最大时可能最难看建议；
- 系统只能间接影响孩子，近端成人行为改变未必转成长期儿童结果；
- 家长过滤可能很有价值，也可能系统性选择自己本来就会做的建议。

所以家长侧不是天然更有效；它只是更匹配本项目的输出渠道和现有家长干预证据。

### 14.2 主要失败模式

| 失败模式 | 会造成什么假象 | 如何发现 | 设计回应 |
|---|---|---|---|
| diarization/ASR 错 | 把孩子话归给家长，却生成很合理的建议 | speaker-attributed WER、证据回放、分项纠错 | 高置信门、N-best、原片段引用、abstain |
| 相关当因果 | 历史中表扬与冲突共现，就判表扬引发冲突 | 检查 assignment 和 propensity | 观察日志只产候选；真实随机确认 |
| 采纳当有效 | 家长喜欢新版本，系统反复强化悦耳措辞 | 执行、家长行为、儿童延迟结果分开 | ACE 不以点赞更新 helpful |
| 当场正确率劫持 | 建议家长直接给答案，分数立刻升高 | 机制指纹、提示等级、无提示迁移 | 以延迟迁移为主要结果 |
| 干预包拆错 | 把整个 PMT/SPACE 效果归给一句话 | 动作卡 causal_scope | 标 B/C，并做本系统动作级试验 |
| 个性化过拟合 | 一次偶然成功变成长期家庭规则 | 随机次数、矛盾证据、区间 | candidate/uncertain/active 状态与收缩 |
| 家庭间污染 | 一个家庭经验直接套到另一个家庭 | 条目 provenance | 家庭 playbook 分开；跨家庭只产全局候选 |
| carryover | 已学会的家长技能污染 control | 检查引入后的所有阶段 | 持续技能用随机多基线 |
| 时间趋势/成熟 | 孩子自然进步被归给系统 | 并发随机、错开基线、时间项 | 不用单纯前后测推广 |
| 多指标挑选 | 总能找到一个变好的结果 | 冻结主要结局和方向 | 一个正式主要结局，次要如实报告 |
| 反复试候选 | 生命周期中迟早误采纳 | attempt 账本 | `α_k=δ_life/[k(k+1)]` |
| 评委共谋 | 提议器和 rubric 都偏爱同种文风 | 跨模型、人工盲评、真实结果 | 合成评价只预筛 |
| 提示疲劳 | 高频提示降低查看和执行，平均效果归零 | 提示数、查看率、冷却期、交互项 | 优化机会和剂量，不追求覆盖率 |
| 发展漂移 | 孩子能力/语言变化，旧 playbook 失效 | 时间前推留出、状态衰减 | 条目带有效时间与再确认 |
| 均值掩盖 | 总体平均好，一个孩子持续变差 | 个体 CS/轨迹和最差分位 | 推广要求个体恶化检查 |
| 系统自我塑造数据 | 建议改变家长行为，后续模型把它当自然偏好 | 区分实验分配和自然事件 | 状态模型纳入 policy/assignment |

### 14.3 必须正面保留的负结果

1. **Active Family**：25 对家长/3–4 岁儿童、2 周、每日 7 个 MRT 决策点；有效效果数据仅 18 对，儿童/家长活动近端效应 `d=.01–.10`，均不显著【论文自报】。结论：高频、及时和传感器驱动仍可能完全无效。
2. **PCIT-AI / PISTACHIo**：50 名 3–7 岁儿童，两组都做 PCIT；ECBI 和睡眠组间不显著，仅次要家长日志中的发脾气时长 `10.4 vs 22.1 分钟` 较好【论文自报】。结论：加 AI 预警不自动改善主要量表。
3. **Tutor CoPilot**：近端 exit-ticket 改善，但年终数学测验无显著变化【论文自报】。结论：成人行为/近端掌握改变不保证长期成绩。
4. **TeachFX**：被专项反馈的聚焦问题增加约 20%，其他行为未明显改变，也没有学生结局【论文自报】。结论：成人反馈可能高度行为特异。
5. **ParenteAI**：外化 `d=1.00`、内化 `.63` 来自无对照前后测，且部分模块有现场人员协助【论文自报】。结论：不能把大前后差当 AI 因果效果。
6. **PaiCoach**：4 个低龄自闭症个案中出现改善，但 `31.4%` 输出需专家编辑【论文自报】。结论：这是修改率，不是“错误率”，也不支持一般 6–12 岁家庭的自主系统。
7. **ACE**：在缺乏可靠反馈的 FiNER 条件，报告从 `70.7` 降到 `67.3`【论文自报】。结论：增量记忆会积累坏经验，必须外加门。
8. **Playlogue**：家长八分类 accuracy `77.70%`，macro-F1 仅 `48.09%`，Reflection recall 约 `2.26%`【论文自报】。结论：漂亮的总体准确率不足以驱动建议。
9. **USC child-adult diarization**：ADOS 8–13 岁 DER `56.8%`【论文自报】。结论：儿童专项模型也可能在目标年龄/新域明显失效。
10. **SkillOpt-Sleep 和 FAFO**：前者是 preview 的受控项目自报，后者公开量化仍是模拟零售；都没有真实家庭儿童效果。结论：只能借机制，不能继承效果。

### 14.4 何时应停止或缩小项目

满足任一项，应停止增加 RSI 复杂度，先修基础或终止该方向：

- 在可接受 coverage 下，目标事件证据 precision 长期达不到动作所需水平；
- 家长查看和执行率低，以至 `δ_min` 的 ITT 效应不可能在合理时间识别；
- 静态证据动作经过足量真实确认仍不改善儿童延迟结果；
- 只有点赞或当场结果改善，延迟结果反复无效；
- 自改进候选的真实通过率不高于人工维护，而成本显著更高；
- 效果只来自无法稳定识别的极窄情境；
- 1–3 个孩子可提供的决策点不足以识别关心的最小效应。

正确结论可能是“保持静态顾问”“只做会后复盘”“只保留学习子系统”或“当前不可识别”，不必为了名义上的 RSI 继续扩张。

## 16. 未核实、待复现和不得偷换的结论

截至 2026-10-15，以下必须保持“未知”：

1. 没有找到家长侧 AI 与儿童直接聊天 AI 的头对头疗效 RCT。
2. 没有工作端到端证明“监听真实小学家庭 → 给家长建议 → 递归自改进 → 儿童长期结果持续改善”。
3. RegulaTutor 没有公开实现；本文只能复现概念接口。PairRoute 是同篇论文中的方法，不是独立项目。
4. FAFO 没有独立论文；公开说明是项目博客。FAPO 才有论文和公开仓库。
5. SkillOpt-Sleep 是 preview 文档，压力测试不是同行评审的家庭部署结果。
6. ACE、FAFO、SkillOpt 和 RegulaTutor 集成后是否互补优于更简单系统，需要本项目消融。
7. 具体表扬、正强化、逻辑后果、情绪验证、减少迁就等大多没有“单句话术”级随机效应；已知的是干预包效果及部分组件关联。
8. PACEE、COMPASS、PaiCoach、ParenteAI 和 Homework Wars 未找到可直接复用的作者完整代码；前四者的疗效外推均受设计或年龄限制。
9. ParenteAI 的进行中 [NCT07469215](https://clinicaltrials.gov/study/NCT07469215)计划 2027 年完成，截至当前无结果。
10. Homework Wars 论文一处写“8 类核心冲突”，摘要、列表和结论为 7 类；本文采用实际列出的 7 类并保留此不一致。
11. ChildTalk 主体/附录对 14.07 的指标名称 CER/WER 不一致。
12. Pasketti `17% WER`、Nemotron DIHARD DER 和 Qwen3-ASR 通用 WER 均不代表本家庭远场、重叠、混说条件。
13. 视频相对音频是否提升最终建议效果未知；不能用实验室情绪识别指标推断。
14. pyBKT、py-irt 和 FSRS 的预测指标不证明家庭建议有效；FSRS-7 在 2026-09 已合并主分支，但核查时最新正式 release 仍早于该提交。
15. `δ_life=.05`、动作库 20–30 张、硬件 24 GB、各阶段周数和任何工程阈值都是起步协议/估计，不是论文结论。
16. `31.4/d²` 不适用于未修正的自相关、cluster、carryover、缺失和执行稀释；不能据此承诺完成周期。
17. LLM judge、模拟学生、Future-Feedback、OPE、家长点赞或专家偏好都不能单独触发真实推广。
18. 开源状态和论文版本会变化；实施时应锁 commit、模型 revision、文档日期和评测协议。

## 附录 B：可审计的决策过程与旧方案差异

### B.1 从目标反推组合，而不是先挑热门仓库

决策步骤：

1. 把目标从“AI 导师回复”重写为完整家长执行因果链；
2. 拆出十个系统器官；
3. 把严格 RSI 分成任务、留存、改进器三层证据；
4. 扩展通用 RSI、日志学习、家长干预、亲子感知和小样本因果候选；
5. 对关键数字、代码和证据范围逐项复核；
6. 先评单项成熟度，再按互补覆盖组成 1–4 项组合；
7. 用反方质疑、负结果和不可识别条件压力测试；
8. 最终选择能覆盖领域分析、稀疏反馈、全局技能和家庭经验的最小组合。

### B.2 单项分析评分

- 评分衡量单项成熟度，不衡量组合边际覆盖；

### B.4 与旧方案的关键差异

| 旧方案角色 | 新方案处理 | 原因 |
|---|---|---|

| “6–9 周足够” | 先用基线数据做功效/停止时间模拟 | 真实自相关、carryover 和执行稀释未知 |

### B.5 最终决策

如果目标是**效果优先且允许复现论文概念**：

> 选 RegulaTutor（含 PairRoute）+ FAFO/FAPO + SkillOpt-Sleep + ACE。

如果目标是**四个基础都必须立即有公开代码**：

> 选 FAFO/FAPO + SkillOpt-Sleep + Recuris + ACE，并自行实现 RegulaTutor 的 E/H/A/O 领域骨架。

如果只能先做一个：

> 选 SkillOpt-Sleep，但首版先实现静态动作库、事件账本和真实评估，不要把离线技能优化当作儿童效果。

真正决定项目成败的不是第四个仓库，而是三条边界：

1. 感知只产生可修正证据；
2. RSI 只在版本化动作库和分层状态上优化；
3. 真实随机儿童结果才有推广权。

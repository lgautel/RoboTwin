# RSI 系统选型方案分析:面向抑郁症治疗场景

> 分析日期:2026-10-13。
> 本文件基于以下材料的全部数据与结论:
> - [`rsi_analyz1.markdown`](./rsi_analyz1.markdown):通用 RSI 领域 40+ 项工作的对比分析(第三版)
> - [`rsi_edu_analyz1.markdown`](./rsi_edu_analyz1.markdown):RSI 在儿童教育与儿童心理发展领域的对比分析

>
> 应用场景:**抑郁症治疗**,覆盖两种模式:
> - **模式 A:治疗师辅助**(系统帮助治疗师优化治疗策略、会话分析、干预方案)
> - **模式 B:来访者交互**(系统在治疗师督导下直接与抑郁症来访者对话,如基于 CBT 的会话、会间支持)
>

## 1. 分析目标与决策框架

### 1.1 目标

从两份报告覆盖的 60+ 项工作中,选出 1-3 个作为基础进行改进,改良出一个**面向真实抑郁症来访者**的 RSI 系统。"面向真实来访者"在抑郁症治疗场景中意味着:

- 系统能在临床或半临床环境中持续运行,服务真实的抑郁症来访者(而非仅跑一次实验)
- 自改进的产物(治疗策略、会话技能、干预话术)必须对来访者的治疗结局产生可测量的正面影响
- 系统的安全性必须达到临床级别:**不得增加自杀/自伤风险,不得延误危机干预,不得替代合格治疗师的临床判断**
- 两种模式都需要覆盖:治疗师辅助(降低门槛)和来访者直接交互(扩大可及性)

### 1.2 从两份报告与选型报告中提炼的核心教训

前八条(L1-L8)继承自选型报告 1.2 节,此处不重复全文,只标出在抑郁症场景中的特殊含义。后五条(L9-L13)是抑郁症场景独有的。

| # | 教训 | 出处 | 在抑郁症场景中的特殊含义 |
|---|---|---|---|
| L1 | 严格 RSI(改进器增益)没有可用实证,所有落地的 RSI 都是有界自改进 | 通用报告 1.1 | 同选型报告:不追求无界 RSI |
| L2 | 落地效果最强的是评估器驱动的有界优化(GEPA、SkillOpt) | 通用报告 1.2 | 同选型报告:GEPA 作为通用优化器 |
| L3 | 门控质量决定一切——无课程指导的自改进会侵蚀关键行为 | 教育报告 1.7 | **在抑郁症场景中后果更严重**:系统可能变得"更会共情"但逐步偏离循证治疗技术(如 CBT 的行为激活、认知重构),甚至在危机时刻选择"安慰"而非"评估风险并转介" |
| L4 | "更新了 harness"不等于"harness 带来收益" | 通用报告 4.10 | 同选型报告 |

| L7 | 儿童/教育场景有结构性风险(LLM 评审偏向更长更流畅) | 教育报告 1.7, 6.1-6.2 | 扩展到抑郁症:LLM 评审可能偏向"更温暖更共情"的回复,而这恰恰不是所有治疗时刻都需要的——CBT 要求在适当时机做认知挑战,DBT 要求在危机时做去激活 |

| **L9** | **心理咨询方向的自进化工作全部面向成人,没有抑郁症特异性验证** | 教育报告 4.5 | PsychAgent/PsyEvo/PsychEval 都面向成人通用心理咨询;PsychEval 涵盖五种疗法但**来访者画像中抑郁症的比例和严重度分布未核实**;没有任何工作报告过"在抑郁症来访者上自改进带来了症状减轻" |
| **L10** | **临床安全需求在所有 RSI 工作中没有先例** | — | 自杀风险评估、危机分级(C-SSRS 等)、即时转介协议、安全计划——这些在所有 RSI 和自进化咨询工作中**完全缺失**,需要从临床实践指南中独立引入 |
| **L11** | **治疗效果的测量比代码/数学/任务完成困难得多** | — | PHQ-9/BDI-II 分数变化缓慢(周级别),治疗联盟是多维度的,会话质量(治疗师技能评定)需要人工评分;把"来访者满意度"或"会话流畅度"当作优化目标可能**直接有害**——来访者可能更"满意"但症状没有改善 |
| **L12** | **监管路径复杂且场景特异** | — | 美国 FDA 对数字疗法(DTx)有 De Novo/510(k) 路径;中国 NMPA 对 AI 辅助诊疗有三类医疗器械注册要求;欧盟 MDR+AI Act;所有路径都要求**临床试验证据**而非基准分数 |
| **L13** | **"自适应"与"治疗依赖"的边界在抑郁症中尤其模糊** | 教育报告 7.2.1 | 抑郁症来访者的依赖风险高于一般人群;系统如果变得"越来越懂我",可能成为来访者回避真实人际关系的替代品,而这恰恰是抑郁症维持因素之一(行为退缩) |

### 1.3 选型标准(针对抑郁症治疗场景调整)

选型报告用五维标准。抑郁症场景需要大幅提升安全/临床有效性的权重,并增加"临床适用性"维度:

| 标准 | 权重 | 说明 | 与选型报告的差异 |
|---|---|---|---|
| **安全与门控设计** | 25% | 是否有显式留出门;产物是否人类可审计可回滚;是否有危机协议;是否能防止"侵蚀关键行为"(L3) | 从 15% 升至 25%,增加危机协议 |
| **临床证据** | 25% | 是否有同行评审;是否在治疗/咨询相关基准上有成绩;是否有真实来访者数据;基准是否独立(PsychEval 自建) | 从 25% "实践证据"改名并聚焦于临床 |
| **代码可用性** | 20% | 许可证;维护活跃度;模块化可拆 | 从 30% 降至 20%(安全更重要) |
| **可组合性** | 15% | 能否作为组件嵌入治疗系统;与闭源 API 的兼容性 | 从 20% 降至 15% |
| **社区与生态** | 15% | fork 数;文档;是否被后续工作当基线 | 从 10% 升至 15%(治疗系统需要活跃维护) |

| **直接相关** | 面向心理咨询/治疗,且有多会话/多疗法设计 | PsychAgent、PsyEvo、PsychEval |

### 2.5 淘汰过程中的关键判断

**为什么保留 PsychAgent(评分仅 2.30,许可证无声明)?**
因为它是**唯一**把"技能演化+强化内化+多会话记忆"完整集成在一起的自进化咨询系统。尽管代码是"研究级"(仓库自述:"不含论文规模的完整训练资产与完整的会后技能演化流水线"),但其**架构设计**——记忆增强规划引擎、技能演化引擎、强化内化引擎——是本领域独一无二的,可以作为参考架构来重新实现。

**为什么保留 PsyEvo(0 fork,创建仅 18 天)?**
因为它的"层级贝叶斯技能策略(每位来访者的技能后验)+跨来访者的列表式偏好优化"是目前最精巧的**测试时个体化适配**机制。MIT 许可。虽然极新,但其设计可以被独立实现。

**为什么 PsychEval 作为"评测环境"而非"基础系统"?**
PsychEval(677 个元技能、4,577 个原子技能、18 项评价指标、2,000+ 来访者画像、多会话多疗法)是目前心理咨询领域**最完整的评测基础设施**,但它不是一个自改进系统。在本方案中它的角色是**评估环境**——自改进系统改出来的技能/策略在 PsychEval 上测试,而不是反过来。

**为什么 KidMind 只是边缘候选?**
KidMind 是儿童心理健康领域最完整的数据/模型框架(KidIns 33.7k 条指令,KidGPT 微调,KidBen 评测),但它是 SFT 路线,**没有自改进回路**。如果目标系统包含青少年抑郁症,KidMind 的数据和评测可以作为补充,但不作为 RSI 基础。

### 3.2 评分依据(逐项)

**GEPA(3.90)**:
- 安全与门控 3:依赖 Pareto 前沿做隐式筛选,没有"不通过就拒绝"的硬门(选型报告 3.2);但可叠加外部门控
- 临床证据 3:ICLR 2026 Oral(通用报告 4.3);已集成于 DSPy;Shopify/Databricks/Dropbox 采用(厂商宣称)。**但没有任何心理/治疗场景验证**,只因其机制("反思式进化任意文本组件")与疗法无关才给 3 分而非 2 分
- 代码可用性 5:MIT;PyPI 包;内置于 DSPy;维护活跃至 2026-10-12
- 可组合性 5:是"优化器",不是"系统",可嵌入任何框架(选型报告 3.2)
- 社区生态 5:575 fork;DSPy 生态;被 Sherpa、Learning to Prompt 等当基线

**SkillOpt(3.85)**:
- 安全与门控 5:**本批最强**。"仅当编辑严格提升留出验证分数时才接受";文本学习率预算;被拒编辑缓冲;产物是 300-2000 token 的人类可读文本(选型报告 3.2)
- 临床证据 2:52/52 格最佳(通用报告 4.10),但全部是 Agent/编码基准,与治疗无关
- 代码可用性 5:MIT;PyPI;1726 fork;有文档与复现指南
- 可组合性 4:输入是任意 Agent 的"技能文档",部署时零额外推理调用
- 社区生态 4:1726 fork;VentureBeat 等报道

**PsychAgent(2.55)**:
- 安全与门控 3:技能演化引擎有"拒绝采样"过滤不当技能(教育报告 4.5);但没有显式的留出验证门,也没有危机协议
- 临床证据 3:PsychEval 上得分最高(教育报告 4.5);522 段匹配对话中人类评分员排第一;**但 PsychEval 是同团队自建基准**,来访者年龄/诊断分布未核实
- 代码可用性 2:无许可证声明;仓库自述"不含论文规模的完整训练资产与完整的会后技能演化流水线";5 fork;最后 push 2026-04-05(已 6 个月)
- 可组合性 3:三引擎架构(记忆、技能演化、强化内化)在概念上可拆,但代码完整度不支持直接复用
- 社区生态 1:5 fork;无文档;无 PyPI

**PsyEvo(2.65)**:
- 安全与门控 3:层级贝叶斯策略提供了"来访者特定后验"的个性化,但没有显式安全门;有序信用分配防止错误归因
- 临床证据 3:PsychEval 上 Overall 7.684(教育报告 4.5);去掉单组件使均值下降 0.138-0.171;**但同样是自建基准上的自报结果**
- 代码可用性 3:MIT 许可(与 PsychAgent 相比这是优势);0 fork 但代码存在;创建于 2026-09-25(极新)
- 可组合性 3:"跨来访者共享回复适配器+来访者特定后验"的设计可独立实现
- 社区生态 1:0 fork;无文档

**SIC-Agents(2.65)**:
- 安全与门控 5:**本批最重要的安全发现**(教育报告 4.3):去掉课程指导后,通用对话质量(Grounding)上升但关键行为(PitfallBench)降到初始种子以下。技能文档人类可读、可审计、可回滚
- 临床证据 3:EMNLP 2026 录用;有消融实验和多种子;但场景是儿科沟通培训,不是抑郁症治疗

**Ouroboros(3.15)**:

- 临床证据 2:自建 TutorBench(大学课程);无治疗/咨询证据
- 代码可用性 5:Apache-2.0;v1.6.14;5201 fork;文档完整
- 可组合性 4:"trace forest"层级记忆可独立使用
- 社区生态 5:5201 fork;活跃维护

### 3.3 关键对比矩阵

### 3.4 一个关键事实

**以上所有候选中,没有任何一项有抑郁症治疗的验证数据**。PsychAgent/PsyEvo 在 PsychEval 上有成绩,但 PsychEval 的来访者画像中抑郁症的比例和严重度分布**未核实**(教育报告 4.5)。PsychEval 涵盖五种疗法(据教育报告:未列举具体疗法名称),是否包含抑郁症的核心循证疗法(CBT-D、行为激活、IPT)**也未核实**。

因此,本方案推荐的是**架构与机制的组合**,而非"已经在抑郁症上被验证的系统"。从选定的基础到一个有临床证据的抑郁症治疗系统,中间需要大量的领域适配和临床试验,这不是 RSI 技术选型能解决的。

## 4. 推荐方案

### 4.1 核心推荐(两种模式共享):GEPA

**为什么 GEPA 是必选?**

理由同选型报告 4.1,此处不重复。简要概括:

1. **它是"优化器",不是"系统"**——可以嵌入任何治疗系统,优化任何文本组件(治疗策略提示、会话技能文档、干预话术模板、危机处理流程描述)
2. **ICLR 2026 Oral**——同行认可在全场最高之列
3. **MIT 许可,内置于 DSPy**——`pip install dspy` 即可用,有成熟生态
4. **与闭源 API 天然兼容**——基座冻结,只改文本
5. **可组合性 5 分**——调用方式:`dspy.GEPA(metric=..., num_threads=...)`

**GEPA 在抑郁症场景中的特殊不足(需要互补)**:
- 没有多会话来访者状态管理
- 没有治疗流派约束(L3:无课程指导的优化会侵蚀关键行为)
- 没有危机检测与转介协议
- 优化目标需要自行定义——"什么叫治疗更好了"比"什么叫代码更对了"难得多(L11)

### 4.2 领域推荐:PsychAgent 架构 + PsyEvo 适配机制

**推荐的不是"使用 PsychAgent/PsyEvo 的代码"——两者的代码都无法直接用于生产。推荐的是它们的架构设计和机制设计,需要基于设计重新实现。**

#### 从 PsychAgent 借鉴的架构(教育报告 4.5)

PsychAgent 的三引擎架构是目前心理咨询自进化系统中最完整的设计:

1. **记忆增强规划引擎**:维护多会话连续性——来访者的问题描述、情绪状态、治疗进展在会话间持久保存,规划引擎在每次会话开始前读取历史并生成本次会话计划。这对抑郁症治疗至关重要:CBT 通常需要 12-16 次会话,每次要基于前次的家庭作业和进展来推进。

2. **技能演化引擎**:从历史咨询轨迹中抽取新技能——把成功的治疗片段归纳为可复用的技能(如"当来访者表现出思维反刍时的引导策略")。这些技能不断积累,形成越来越丰富的技能库。

3. **强化内化引擎**:经拒绝采样微调把技能写入模型——将演化出的好技能通过 RL 写入模型权重,使模型"内化"这些技能而非仅在提示中外挂。

**在本方案中的改造**:
- 保留三引擎架构,但**不做权重微调**(强化内化引擎改为技能文档层面的优化,由 GEPA 驱动)——这更安全、更可审计、更易回滚
- 记忆引擎增加**来访者安全状态追踪**(自杀风险等级、安全计划、紧急联系人)
- 技能演化引擎增加**治疗流派约束**(见 4.3)

#### 从 PsyEvo 借鉴的适配机制(教育报告 4.5)

PsyEvo 的个体化适配设计在所有咨询工作中最精巧:

1. **层级贝叶斯技能策略**:每位来访者有自己的技能后验(哪些技能在 TA 身上效果好),同时所有来访者共享一个先验(群体级别的技能基线)。新来访者从先验开始,随着会话积累逐渐个体化。

2. **跨来访者的共享学习**:一个来访者身上学到的好技能,通过列表式偏好优化更新共享回复适配器,可以惠及其他来访者。

3. **有序信用分配**:分辨"是哪个技能让这次会话有效"——在多技能组合使用时,正确归因到具体技能。

**在本方案中的改造**:
- 保留层级贝叶斯框架,但**先验分布从 PsychEval 的通用技能树替换为抑郁症特异性技能树**(CBT-D 的行为激活、认知重构、苏格拉底式提问等)
- 跨来访者共享学习**不应跨诊断**——抑郁症来访者身上学到的技能不应自动推广到焦虑症或 PTSD
- 增加**安全技能的硬约束**:危机干预技能的后验不允许被贝叶斯更新降低

### 4.3 安全设计推荐:SIC-Agents 模式 + Ouroboros 治理

**这是与选型报告最大的不同:在抑郁症场景中,安全设计不是"借鉴",而是与核心推荐同等重要的第三个基础。**

#### 从 SIC-Agents 借鉴(教育报告 4.3)

SIC-Agents 的核心发现(EMNLP 2026)直接适用于抑郁症治疗:

> 去掉课程指导后,通用对话质量(Grounding)仍持续上升,但临床关键行为(PitfallBench)**降到初始种子以下**。

翻译到抑郁症场景:**如果让系统根据"来访者满意度"或"会话流畅度"自由优化,系统会变得"更会安慰人"但逐渐放弃认知挑战、行为激活等不那么"舒服"但治疗上必要的技术。** 在抑郁症中,认知挑战(质疑来访者的自动化消极思维)短期内可能让来访者不舒服,但这恰恰是 CBT 的核心治疗机制。

借鉴的设计:
1. **治疗流派课程指导**(对应 SIC-Agents 的 Coach):定义每种疗法的核心技术列表和期望行为,作为自改进的**不可退化约束**
2. **可编辑技能文档**(对应 SIC-Agents 的 Skill Document):所有自改进产物都是人类可读的文本,治疗师可以查看、编辑、否决
3. **Skill Editor + 治疗师审计**:自动生成的技能改进提案必须经过治疗师(模式 A)或督导(模式 B)的审核才能生效

#### 从 Ouroboros 借鉴(通用报告 4.10)

Ouroboros 的治理设计在所有 RSI 工作中最系统(选型报告 3.2):

1. **受保护层**:核心安全规则(自杀风险评估流程、危机转介条件、保密例外)不可被优化器修改
2. **确定性预检**:任何技能更新在上线前必须通过预定义的安全检查
3. **diff 指纹+不可篡改日志**:所有修改有完整审计追踪
4. **回滚机制**:一键回退到上一个通过安全检查的版本
5. **花费上限**:防止优化过程失控
6. **紧急停止**:操作员可随时暂停所有自改进

### 4.4 推荐总结

| | 模式 A:治疗师辅助 | 模式 B:来访者交互 | 如果只选 1 个 |
|---|---|---|---|
| **核心优化器** | GEPA | GEPA | GEPA |
| **领域架构** | PsychAgent 三引擎架构(重新实现) | PsychAgent 三引擎 + PsyEvo 个体适配 | PsychAgent 架构(精简版) |
| **安全设计** | SIC-Agents 课程指导模式 | SIC-Agents 模式 + Ouroboros 治理(全套) | SIC-Agents 课程指导 |
| **评估环境** | PsychEval(适配) | PsychEval(适配)+ 抑郁症特异性留出集 | PsychEval(适配) |
| **记忆基础设施** | 可选借鉴 DeepTutor 的 trace forest | 需要完整的来访者状态系统 | — |
| **安全要求等级** | 中:治疗师审查所有产物 | 极高:危机协议+受保护层+灰度发布 | 中 |

### 4.5 为什么不选那些"看起来更合适"的替代方案

**为什么不直接用 PsychAgent 代码?**
- 许可证无声明,商用法律风险不明
- 仓库自述"不含论文规模的完整训练资产与完整的会后技能演化流水线"——研究代码,不是可部署系统
- 最后 push 2026-04-05,已 6 个月未更新
- 强化内化引擎(微调模型权重)在临床场景中不安全——权重变化不可审计不可回滚

**为什么不用 Hermes Agent 架构?(选型报告场景 D 推荐了它)**
- Hermes 的"自进化"是通用记忆/技能/提示层,**没有任何治疗流派约束**
- 其热度(54870 fork)反映的是通用个人助手需求,与治疗安全无关
- PAST-Bench 第三方评测显示改进"真实但不均匀"(通用报告 4.7)——在抑郁症治疗中,"不均匀"意味着某些维度可能退化,这是不可接受的

**为什么不用 DeepTutor 作为主要基础?(选型报告教育场景推荐了它)**
- DeepTutor 是教育产品,不是治疗产品——其"trace forest"记忆设计面向知识掌握度而非心理状态
- 没有多疗法支持,没有危机处理,没有治疗联盟建模
- 可以借鉴其记忆基础设施,但不应作为治疗系统的主架构

**为什么不直接跑 SkillOpt 优化治疗技能?**
- SkillOpt 的门控最严谨(这是优点),但它只管"技能文档"这一个对象——在治疗系统中还需要管来访者记忆、会话规划、危机协议、跨来访者学习,这些都超出 SkillOpt 的范围
- 在门控设计层面借鉴 SkillOpt 的留出验证门(与 GEPA 互补),但不作为主要基础

### 5.2 门控/安全系统改造(抑郁症特异性)

**综合 SkillOpt + SIC-Agents + Recuris + Ouroboros 的设计,增加抑郁症特异性门控:**

1. **留出验证门**(SkillOpt):
   - 维护一个抑郁症治疗的**留出评估集**,自改进过程永远看不到
   - 留出集应包含:标准 CBT 会话片段、危机场景、治疗联盟挑战场景、来访者阻抗场景
   - 任何修改必须在留出集上**严格不退步**
   - **关键区别于通用场景**:不能只看"平均更好",必须检查**每个安全维度**都不退化

2. **治疗流派约束门**(SIC-Agents):
   - 定义抑郁症核心治疗技术的**不可退化清单**:
     - CBT-D:行为激活、活动计划、认知重构(识别自动化思维、检验证据、替代思维)、苏格拉底式提问、家庭作业布置与回顾
     - DBT(适用于伴随情绪调节困难的来访者):正念、痛苦耐受、情绪调节、人际效能
     - IPT(适用于人际问题突出的来访者):角色转换、人际冲突、悲伤
     - 行为激活(BA):活动监测、活动计划、价值观导向行动
   - 通用反馈(来访者满意度、会话流畅度)只作辅助奖励,**不允许覆盖治疗流派约束**
   - **这直接来自 SIC-Agents 的核心发现:无课程指导的自改进会侵蚀关键行为**

3. **组件定位门**(Recuris):
   - 当治疗效果不佳时,不做全局修改,而是**定位到具体组件**(是"认知重构话术"不好,还是"治疗联盟建立"不够,还是"家庭作业设计"不合适)
   - 只修补被定位的组件,其他组件不动
   - 配对留出验证:修补后用同类来访者的其他会话验证

4. **安全回归门**(新增,无直接先例):
   - 所有修改前后,自动在**危机场景集**上测试
   - 危机场景包括:来访者表达自杀意念、来访者报告自伤行为、来访者情绪急性恶化、来访者报告药物滥用
   - 在危机场景上的表现**只允许提升,不允许退步**——即使其他维度都改善了,如果危机处理退步,修改也必须被拒绝

### 5.3 评估基础设施改造

**原则**:评估器必须独立于被改进的系统(L3);抑郁症治疗效果的评估比代码/任务完成**难得多**(L11)。

| 评估层 | 来源 | 度量 | 更新策略 |
|---|---|---|---|
| **来访者症状** | PHQ-9/BDI-II 自评 | 分数变化(周级别) | 每次会话前后采集;**不作为 GEPA 的优化目标**(变化太慢,且受多种因素影响) |
| **会话技能评定** | 改编自 PsychEval 的 18 项指标 | 咨询师共享/特定指标 | PsychEval 作为自动评估器;定期用临床心理学家人工评分校准 |
| **治疗流派忠诚度** | CTRS(认知治疗评定量表)改编版 | CBT 核心技术使用频率与质量 | 由治疗流派约束门自动检查;人工抽检 |
| **危机处理质量** | 自建危机场景集 | C-SSRS 问题覆盖率、转介触发准确率 | 每次修改前自动运行;**永远不暴露给优化器** |
| **治疗联盟** | WAI-SR(工作联盟量表短版)改编 | 来访者与系统的联盟感知 | 每 4 次会话采集;**只作监测,不作优化目标**(优化联盟感知可能导致情感依赖,L13) |
| **留出评估集** | 手动构建 + 从真实会话中采样(需脱敏和伦理审查) | 综合 | 定期扩充;**永远不暴露给优化器** |
| **长程安全测试** | TSJ 方法(教育报告 4.6) | ~140 轮后的稳定风险估计 | 每个版本上线前运行 |

**关于 PsychEval 作为评估环境**:
- PsychEval(教育报告 4.5)提供了 677 个元技能/4,577 个原子技能/18 项指标/2,000+ 来访者画像/多会话多疗法
- **需要适配**:验证其来访者画像中抑郁症的覆盖度;如果不足,需要补充抑郁症特异性画像(不同严重度、不同共病模式、不同年龄段)
- **需要独立性检查**:PsychEval 是 PsychAgent/PsyEvo 的同团队产品(教育报告 4.5),如果系统架构借鉴了 PsychAgent,那么评估器和被评估系统有同源风险——建议补充独立的评估维度

**为什么不把"来访者满意度"或"会话流畅度"作为 GEPA 的主要优化目标**:

这是 L11 的核心问题。在抑郁症治疗中:
- 认知挑战(质疑消极自动化思维)短期内让来访者不舒服,但是 CBT 的核心机制
- 行为激活(推动来访者做不想做的事)同样让来访者不舒服,但是恢复的关键
- 暴露(让来访者面对回避的情境)在过程中增加焦虑
- 如果优化"满意度",系统会学会避免这些"不舒服"的干预,变成一个"好的倾听者"但不是"有效的治疗师"
- SIC-Agents 的消融(教育报告 4.3)已经在不同领域直接验证了这个风险

**GEPA 的优化目标应当是**:
- **主目标**:治疗流派忠诚度(CTRS 分数 或 PsychEval 的技能使用质量指标)
- **安全约束**:危机处理质量不退步
- **辅助目标**:来访者参与度(会话完成率、家庭作业完成率)——注意这不是"满意度",而是"治疗行为发生了"

### 5.4 危机检测与转介协议(抑郁症特异性,无 RSI 先例)

**这是所有 RSI 工作中完全缺失的部分,必须从临床实践指南中独立引入。**

| 风险等级 | 触发条件(示例) | 系统行为 | 是否可被自改进修改 |
|---|---|---|---|
| **绿色**(低风险) | 来访者无自杀意念,PHQ-9 Q9=0 | 正常治疗 | 治疗内容可优化 |
| **黄色**(中风险) | 来访者表达被动自杀意念("活着没意思"),PHQ-9 Q9=1-2 | 进行 C-SSRS 简版评估;记录结果;提醒治疗师查看;制定/更新安全计划 | 评估流程不可修改;后续治疗策略可在门控内优化 |
| **橙色**(高风险) | 来访者有主动自杀意念但无计划;或报告自伤行为 | 立即触发治疗师通知;提供安全计划;提供危机热线号码;不结束会话但切换到安全模式 | **完全不可被自改进修改** |
| **红色**(紧急) | 来访者有自杀计划和获取手段;或正在自伤 | 立即通知治疗师和紧急联系人;提供 120/988/希望24热线;保持连接直到人类介入 | **完全不可被自改进修改** |

**关键设计原则:**
- 以上四级分类和对应行为属于 Ouroboros 式的**受保护层**——自改进过程**永远不能修改**这些规则
- 危机检测的**灵敏度可以被调高但不可被调低**——宁可误报(治疗师多看一眼)也不可漏报
- 来访者直接交互(模式 B)的危机协议必须比治疗师辅助(模式 A)更保守

### 5.5 模式 A:治疗师辅助的专项改造

| 功能 | 实现 | 自改进范围 |
|---|---|---|
| **治疗策略优化** | GEPA 对治疗师的会话提示/策略做反思式进化;治疗师每次会话后审查建议 | 策略提示可优化;治疗师有否决权 |
| **会话分析** | 对每次会话生成结构化反馈(技术使用、联盟信号、来访者变化信号) | 分析模板可优化;分析结果供治疗师参考 |
| **案例概念化演化** | 来访者的认知模型/行为模式/维持循环图谱随治疗进展演化 | 概念化框架可优化;治疗师审核 |
| **治疗计划生成** | 基于来访者状态和治疗进展,建议下次会话的目标和技术 | 计划模板可优化;治疗师决定最终计划 |
| **跨来访者学习** | PsyEvo 式:某个来访者上有效的策略更新共享先验,惠及其他治疗师 | 共享学习在门控下运行;按诊断分组,不跨诊断 |

**模式 A 的安全等级较低**,因为所有产物都经过治疗师审查。主要风险是:
- 治疗师因工作量大而不仔细审查建议("审查疲劳")
- 缓解:按风险等级标记建议(常规/需关注/需审查),只在"需审查"时弹出强提示

### 5.6 模式 B:来访者交互的专项改造

模式 B 在模式 A 的基础上增加以下要求:

| 功能 | 实现 | 安全约束 |
|---|---|---|
| **会话互动** | 冻结基座模型 + 治疗技能文档 + 来访者个体适配器 | 回复前经安全预检(是否触发危机检测);每次会话有时长和话题边界 |
| **会间支持** | 在正式会话之间提供简短的情绪检查、家庭作业提醒、正念练习引导 | 不做深度治疗;有自杀意念时立即触发黄色/橙色协议 |
| **治疗连续性** | PsychAgent 式记忆引擎维护完整来访者状态 | 状态中的安全信息(风险等级等)不可被自改进修改 |
| **来访者知情同意** | 明确告知:这是 AI 辅助,不替代治疗师;所有内容会被治疗师查看;使用数据的范围和目的 | 不可被修改或省略 |
| **督导审查** | 所有会话记录可被督导治疗师审查;自改进产物需督导定期审核 | 审查频率:初期每次,稳定后抽检 |
| **退出与转介** | 来访者症状恶化(PHQ-9 上升 5 分以上)或连续 4 次会话无改善,自动升级到治疗师面对面评估 | 不可被自改进修改 |

**模式 B 的特殊风险**:
- **情感依赖**(L13):来访者可能把系统当作唯一的情感支持,回避真实人际关系——这对抑郁症来访者尤其有害(行为退缩是维持因素)。缓解:奖励函数不包含会话频率/情感亲密度;系统主动鼓励来访者的线下社交行为
- **治疗深度不足**:AI 系统在认知挑战(质疑深层信念)方面可能力不从心。缓解:系统识别到"需要更深层认知工作"时,建议来访者与治疗师讨论
- **虚假安全感**:来访者可能认为"我有 AI 陪着,不需要看医生了"。缓解:定期提醒治疗师角色;不允许在没有治疗师的情况下单独使用超过 8 周

### 5.7 分阶段实施路线

| 阶段 | 内容 | 产出 | 预计工作量 |
|---|---|---|---|
| **Phase 0** | 定义治疗流派约束(CBT-D/BA/IPT);构建留出评估集(含危机场景);确定基座模型;搭建基础会话框架;获得伦理审查委员会(IRB/伦理委)批准 | 基线系统 + 评估基础设施 + 伦理批件 | 4-8 周(伦理审批可能更长) |
| **Phase 1** | 集成 GEPA;对治疗策略提示做反思式优化;建立 Pareto 前沿;在 PsychEval(适配版)上测试 | 治疗策略提示在留出集上有可测量的提升 | 2-3 周 |
| **Phase 2** | 实现 PsychAgent 式三引擎(记忆+技能演化+规划);实现来访者状态管理;建立门控系统(四层) | 多会话治疗系统 + 完整门控 | 6-8 周 |
| **Phase 3** | 实现 PsyEvo 式个体适配;实现跨来访者共享学习;建立治理层(Ouroboros 式) | 可个体化的治疗系统 + 完整治理 | 4-6 周 |
| **Phase 4** | 实现危机检测与转介协议;建立治疗师/督导审核接口;长程安全测试(TSJ 式,140+ 轮) | 可对治疗师开放的模式 A 系统 | 4-6 周 |
| **Phase 5** | 模式 A 小规模试点:5-10 名治疗师,各自 3-5 名来访者;收集反馈;迭代门控 | 治疗师使用数据和初步安全证据 | 12-16 周 |
| **Phase 6** | 模式 B 开发:增加会话互动/会间支持/知情同意流程;在模拟来访者上广泛测试;第二轮 IRB 审查 | 可对来访者开放的模式 B 候选系统 | 8-12 周 |
| **Phase 7** | 模式 B 小规模试点:治疗师督导下,10-20 名来访者;随机对照或非劣效设计;PHQ-9/BDI-II 为主要结局 | 初步临床证据 | 16-24 周 |

**总计约 14-20 周到模式 A 的第一个试点版本;约 40-60 周到模式 B 的第一个临床试验数据。**

这个时间线比选型报告(9-14 周到第一个可对真实用户开放的版本)长很多,原因是:
1. 伦理审查/IRB 批准是硬性前置条件
2. 危机协议需要临床专家参与设计和测试
3. 模式 B 需要在模式 A 充分验证后才能启动
4. 临床试验(Phase 7)本身需要 4-6 个月的来访者招募和随访

## 6. 风险与缓解

| 风险 | 来源 | 严重度 | 缓解措施 |
|---|---|---|---|
| **自杀/自伤风险升高** | L10:无 RSI 先例 | 极高 | 受保护层不可自改;危机检测灵敏度只升不降;模式 B 有督导;症状恶化自动升级到治疗师 |
| **治疗技术侵蚀** | L3:SIC-Agents 消融(教育报告 4.3) | 高 | 治疗流派约束门:核心技术不可退化;GEPA 的优化目标为治疗忠诚度而非满意度 |
| **情感依赖** | L13:抑郁症来访者依赖风险高 | 高 | 奖励不含会话频率/亲密度;系统主动鼓励线下社交;使用时长限制;定期评估依赖指标 |
| **评估器漂移/被钻空子** | L3,通用报告 1.6 | 中 | 评估器独立于被优化系统;留出集不暴露;定期人工校准;PsychEval 同团队同源风险需补充独立评估 |
| **来访者隐私泄露** | 治疗记录是自改进的原料 | 高 | 脱敏后再用于技能演化;技能文档中不含个人信息;HIPAA/中国个人信息保护法合规;跨来访者学习仅在聚合层面 |
| **虚假安全感** | 来访者过度信任 AI | 中 | 知情同意明确告知限制;不允许无治疗师监督长期单独使用;定期提醒治疗师角色 |
| **奖励投机** | 通用报告 1.6(DGM 伪造日志) | 中 | 留出集永远不暴露;人工抽检;回归测试 |
| **治疗师审查疲劳** | 模式 A 特有 | 中 | 按风险标记建议;只在"需审查"时强提示;自动化常规审查 |
| **监管不合规** | L12 | 高 | Phase 0 即获 IRB 批准;Phase 7 按临床试验标准设计;如需上市走 DTx 审批路径 |
| **成本失控** | 通用报告 1.6 | 低 | 治理层花费上限;GEPA 的反思式进化本身比 RL 训练便宜得多 |

| 维度 | 选型报告(通用/教育) | 本方案(抑郁症治疗) |
|---|---|---|
| **安全权重** | 门控设计 15% | 安全与门控 25%,另有独立的危机协议 |

## 8. 总结

### 8.1 核心结论

1. **如果只选 1 个:选 [GEPA](https://github.com/gepa-ai/gepa)**。理由同选型报告:ICLR 2026 Oral、MIT、DSPy 集成、可嵌入任何系统。在抑郁症场景中,它优化的对象是治疗策略提示和技能文档,优化目标是治疗忠诚度而非来访者满意度。

2. **如果选 2 个:加 PsychAgent 的架构设计**(三引擎:记忆+技能演化+规划)。这是目前唯一完整的自进化咨询架构。注意:借鉴架构,不直接用代码(许可证无声明、代码不完整)。结合 PsyEvo 的个体适配机制(MIT 许可)实现来访者级别的个性化。

3. **如果选 3 个:加 SIC-Agents 的安全设计模式**(可编辑技能文档 + 治疗流派课程指导 + 治疗师可审计)。SIC-Agents 的消融实验(EMNLP 2026)直接证明了"无课程指导的自改进会侵蚀临床关键行为"——这在抑郁症治疗中意味着系统会变得"更会安慰人"但放弃认知挑战和行为激活,**这是不可接受的**。

### 8.2 必须诚实说明的局限

- **没有任何 RSI 工作在抑郁症治疗上有验证数据**。本方案推荐的是"架构与机制的组合",不是"已被证明有效的系统"
- **从选定基础到有临床证据的系统,中间是 40-60 周的工作**,包括临床试验——这不是技术选型能跳过的
- **PsychEval 作为评估环境是否覆盖抑郁症未核实**——如果覆盖不足,需要大量补充工作
- **所有安全机制都是设计层面的**——没有任何 RSI 工作经过独立的红队评估(通用报告 6.8)
- **抑郁症治疗效果的衡量本身就是心理学的开放问题**——PHQ-9/BDI-II 是金标准但变化缓慢、受多因素影响;把它们当 GEPA 的优化目标在技术上不可行(信号太弱太慢),但不用它们又缺乏临床意义

### 8.3 下一步

1. 组建跨学科团队:需要临床心理学家(CBT 方向)、精神科医生、AI 工程师、伦理/法律专家
2. Phase 0:定义治疗流派约束、构建留出评估集、获 IRB 批准
3. 验证 PsychEval 对抑郁症的覆盖度——如果不足,这是一个需要优先解决的前置问题
4. 集成 GEPA(约 2-3 周即可看到第一个治疗策略优化结果)
5. 重新实现 PsychAgent 三引擎(基于公开论文的架构描述,不依赖其代码)

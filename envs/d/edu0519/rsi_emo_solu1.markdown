# 面向抑郁症治疗场景的 RSI 系统选型与改造方案

> 基于 [`rsi_analyz1.markdown`](./rsi_analyz1.markdown)(通用 RSI 报告,第三版)与 [`rsi_edu_analyz1.markdown`](./rsi_edu_analyz1.markdown)(教育/心理发展报告)的深入分析。
> 撰写日期:2026-10-13。

---

## 0. 分析前提

**目标**:选择 1-3 个 RSI 相关工作作为基础,改良出一个 RSI 系统,用于**有真实用户的抑郁症治疗场景**。

**"有真实用户"这四个字决定了选型逻辑**:不是选"RSI 严格度最高的",而是选"能在临床/准临床场景里安全落地,且自改进回路可被治疗师审计和回滚的"。抑郁症治疗是高风险场景——错误的干预可能加重症状、诱发自伤,因此安全约束的优先级高于任何基准分数。

---

## 1. 抑郁症治疗场景的特殊约束

在分析选型之前,必须先明确这个场景与通用 RSI 或教育 RSI 的根本区别:

| 约束 | 说明 | 对选型的影响 |
|---|---|---|
| **临床安全** | 抑郁症患者可能有自伤/自杀风险;不当干预可直接造成伤害 | 自改进回路的产物必须是人类可读、可审计、可回滚的;不能用不可检视的权重更新 |
| **疗法合规** | CBT、IPT、BA 等循证疗法有明确的结构化流程;偏离流程的"创新"可能有害 | 自改进必须在疗法框架内进行,不能自由漂移;需要"课程指导"类约束 |
| **个体差异大** | 每位来访者的症状谱、共病、用药、社会支持系统不同 | 需要按个体维护状态/画像,且画像更新要有临床依据 |
| **长程性** | 抑郁症治疗通常 8-20 次会谈,需跨会话连续性 | 记忆与技能的持久化是刚需,不是可选功能 |
| **治疗师在回路中** | 真实场景中系统应辅助治疗师,而非替代;即使是自助场景也需要临床监督 | 自改进的产物必须对治疗师透明,治疗师有否决权 |
| **隐私与伦理** | 心理健康数据是最敏感的个人数据之一;需要知情同意、数据最小化 | 自改进回路的"训练数据"(交互轨迹)不能随意使用 |
| **评估器不能用 LLM 评审** | 教育报告已证明 LLM 评审会偏向"更长更流畅"的回复(SIC-Agents 消融);在抑郁症场景,"更流畅"可能意味着更多情感依赖而非更好的治疗效果 | 评估器必须锚定在临床量表(PHQ-9、BDI-II、GAD-7 等)和治疗师评分上,不能纯用 LLM 自评 |

## 2. 候选工作的筛选与淘汰

### 2.1 筛选池

从两份报告中,与抑郁症治疗场景相关的工作可按相关度分三层:

**第一层:直接相关(心理咨询/治疗方向)**
- **PsychAgent**(华东师大 ICALK):经验驱动终身学习的心理咨询师,技能演化 + 拒绝采样微调
- **PsyEvo**(Lingxi):测试时按来访者自进化,层级贝叶斯技能策略
- **PsychEval**(ICALK):多会话多疗法基准,可作为 RL 环境

**第二层:结构相关(机制可迁移)**
- **SIC-Agents**(EMNLP 2026):可编辑技能文档 + 课程指导 + 临床医生审计
- **GEPA**(ICLR 2026 Oral):反思式提示进化,已内置于 DSPy
- **DeepTutor**(HKUDS):持久学习者记忆的工程底座
- **SkillOpt**(Microsoft):技能文档作为可训练参数

**第三层:间接相关(方法参考)**
- **PedagogicalRL / Sherpa**:RL 训练导师策略的方法论
- **ACE**:上下文 Playbook 的自适应演化
- **Recuris**:确定性配对留出验证门
- **KidMind**:儿童心理健康 SFT 数据(中文)

### 2.2 淘汰理由

| 淘汰的工作 | 理由 |
|---|---|
| DGM / HGM / HyperAgents / MGM 等脚手架自改进线 | 改进的是编码 Agent harness,与心理治疗场景无关;改进器增益的证据也依赖编码基准 |
| AlphaEvolve / OpenEvolve / ShinkaEvolve | 程序/算法进化,目标函数需要可精确评估;心理治疗的"好坏"无法用程序正确性衡量 |
| 具身层(RPent / ENPIRE / ASPIRE 等) | 物理世界反馈闭环,与对话式治疗无关 |
| Ouroboros / DarwinX | 自改进核心代码;在高风险临床场景中不可接受 |
| 产品化自进化 Agent(Hermes / Prime) | 通用 Agent 的自进化;缺乏临床约束;证据级别低 |
| Park 2019 / 陪伴机器人 | 面向儿童的情感 RL;非 LLM 路线;年代偏早 |
| PedagogicalRL / Sherpa | 核心是"模拟学生上的 RL 训练";抑郁症来访者不能被当作"模拟学生"来训练系统 |

### 2.3 留下的候选

经淘汰后,真正值得深入比较的候选只有 5 个,它们各自提供了不同的"积木":

| 候选 | 提供什么 | 缺什么 |
|---|---|---|
| **PsychAgent** | 完整的自进化咨询师架构(技能演化 + 记忆 + 微调) | 面向成人通用咨询;无抑郁症专项验证;代码不完整("不含完整训练资产") |
| **PsyEvo** | 测试时按来访者自适应;层级贝叶斯技能策略 | 极新(2026-10);0 fork;无独立验证;与 PsychAgent 是同一基准上竞争 |
| **SIC-Agents** | 可审计的技能文档自改进 + 课程指导消融 + 临床医生在回路 | 面向儿科医护培训,不是心理治疗;代码未开源 |
| **GEPA** | 成熟的反思式提示进化引擎;ICLR 2026;DSPy 集成;大量落地 | 通用工具;需要自行设计抑郁症场景的评估函数 |
| **DeepTutor** | 最成熟的持久学习者记忆工程(trace forest,多 Agent 蒸馏画像) | 面向教育;无心理治疗验证;5201 fork 说明工程可用 |

## 3. 深入对比分析

### 3.1 PsychAgent vs PsyEvo:心理咨询自进化的两条路

这两项来自关联团队(华东师大 ICALK 与 Lingxi),共用同一个基准 PsychEval。它们代表了自改进在心理咨询场景的两种时机:

| 维度 | PsychAgent | PsyEvo |
|---|---|---|
| **改进时机** | 离线:从历史会话中抽取技能,拒绝采样微调写入模型权重 | 在线:测试时按每位来访者的贝叶斯后验调整技能选择 |
| **改进对象** | 技能库 + 模型权重(通过微调) | 技能选择策略(共享回复适配器的偏好分布) |
| **多会话支持** | 有:记忆增强的规划引擎维护跨会话连续性 | 有:层级贝叶斯在来访者间共享先验 |
| **PsychEval 成绩** | 咨询师共享 7.32、特定 7.91、来访者共享 5.92、特定 8.24 | Overall 7.684 |
| **开源程度** | 18 star / 5 fork;代码"不含完整训练资产" | 0 star / 0 fork;MIT 许可 |
| **对抑郁症的适用性** | 技能演化可以锚定在 CBT/BA 技能树上 | 贝叶斯技能策略天然适合"按个体调整治疗计划" |
| **风险** | 微调后的权重不可检视;技能抽取的质量依赖 LLM | 极新;代码可用性未经验证 |

**判断**:PsychAgent 的架构更完整(记忆 + 技能演化 + 微调三层),且有人评验证(522 段匹配对话,人评排第一)。PsyEvo 的在线适配思路更适合"每位来访者不同",但太新、代码几乎不可用。

**选择 PsychAgent 作为第一个基础工作**,原因:
1. 它是目前唯一一个把"技能演化"明确用在心理咨询场景的工作
2. 它的三层架构(记忆 → 技能演化 → 微调内化)给出了一个完整的"从对话到改进"的闭环
3. 技能演化的产物(技能描述)是文本,可以被治疗师审计
4. PsychEval 基准本身可以作为 RL 环境使用,降低了评估器的构建成本
5. PsyEvo 的贝叶斯技能选择思路可以作为 PsychAgent 的增强,而不需要单独选它

**PsychAgent 的主要缺陷需要改造弥补**:
- 权重微调不可检视 → 需要用 SIC-Agents 的"可编辑技能文档"替代或补充
- 无抑郁症专项评估 → 需要构建锚定在 PHQ-9 等量表上的评估器
- 代码不完整 → 需要重新实现核心模块

### 3.2 SIC-Agents:安全设计的范本

SIC-Agents 本身是儿科医护培训的模拟家长,与抑郁症治疗的场景不同。但它的**设计理念**是所有候选中最值得借鉴的:

**为什么选 SIC-Agents 作为第二个基础工作**:

1. **可编辑技能文档**:自改进的产物不是不可检视的权重,而是文本形式的"技能文档"。在抑郁症治疗场景中,这意味着治疗师可以直接阅读、修改、回滚系统学到的技能,例如"当来访者表达无望感时,应先验证情绪再引入认知重评"。

2. **课程指导(Coach)的关键消融**:SIC-Agents 最重要的发现是——去掉课程指导后,通用对话质量(Grounding)上升,但临床关键行为(PitfallBench)下降到初始种子以下。这直接说明:**在高风险场景中,自改进回路如果没有领域约束,会"变流畅"但"变危险"**。抑郁症治疗中的等价物是:系统可能学会更"共情"的措辞,同时丢失"识别自杀风险信号"的能力。

3. **临床专业人员在回路中**:SIC-Agents 的设计允许临床医生审计并编辑技能文档与每次改写。这正是抑郁症治疗场景需要的——治疗师审计自改进的产物。

4. **EMNLP 2026 录用**:同行认可度高,设计经过评审验证。

**SIC-Agents 需要的改造**:
- 从"模拟家长"迁移到"辅助治疗师与来访者的对话"
- 课程指导从"儿科沟通痛点 P1-P10"替换为"CBT/BA/IPT 的结构化治疗阶段与关键干预技能"
- 评估器从 PitfallBench/DialogueBench 替换为锚定在 PHQ-9 变化和治疗师评分上的指标

### 3.3 GEPA:经过验证的优化引擎

**为什么选 GEPA 作为第三个基础工作**:

1. **成熟度最高**:ICLR 2026 Oral,575 fork,已内置于 DSPy,Shopify/Databricks/Dropbox 等企业采用(官方宣称)。在所有候选中,GEPA 是唯一一个"已被大规模验证的提示/技能优化引擎"。

2. **机制适配性好**:GEPA 让 LLM 以自然语言反思执行轨迹,诊断问题、提出提示更新,并从 Pareto 前沿中合并经验。这个机制可以直接用于"治疗技能的反思式改进"——从治疗会话轨迹中反思,诊断哪些技能用得不好,提出更新。

3. **与 PsychAgent 互补**:PsychAgent 的技能演化引擎是其自己设计的;用 GEPA 替换或增强这一环节,可以获得更强的优化效率(GEPA 比 GRPO 少用 35 倍 rollout)。

4. **已有"在 Hermes Agent 上落地"的先例**:[`hermes-agent-self-evolution`](https://github.com/NousResearch/hermes-agent-self-evolution) 用 DSPy + GEPA 对 Hermes 的技能、工具描述、系统提示做反射式进化,每次约 2-10 美元。这说明 GEPA 可以作为"通用技能优化引擎"插入不同框架。

5. **评估函数可定制**:GEPA 的核心设计是"给定评估函数,优化提示/程序使之得分更高"。关键在于评估函数——在抑郁症场景中,评估函数不能是 LLM 自评,必须锚定在临床量表和治疗师评分上。GEPA 本身不限制评估函数的来源。

**GEPA 需要的改造**:
- 评估函数必须从"任务正确性"替换为"治疗技能有效性"(下面详述)
- 需要与 PsychAgent 的记忆系统和 SIC-Agents 的技能文档格式整合
- 需要添加"课程指导"约束,防止优化方向偏离疗法框架

### 3.4 为什么不选 DeepTutor / SkillOpt

**DeepTutor** 的持久学习者记忆工程(trace forest,动态学习者画像)非常成熟,5201 fork 说明工程可靠性高。但它面向教育,核心抽象是"知识库 + 学习者掌握度 + 出题",这与抑郁症治疗的抽象("治疗计划 + 来访者症状/功能状态 + 干预技能选择")差距较大。改造成本不低于从头设计一个面向治疗的记忆系统,且 DeepTutor 的自改进只到"个体记忆演化"(RSI 严格度 3),不涉及技能/策略层面的改进。

**结论**:DeepTutor 的 trace forest 设计可以参考,但不值得作为三选一的基础工作。PsychAgent 的记忆增强规划引擎已经提供了类似功能,且是为咨询场景设计的。

**SkillOpt** 的"技能文档作为可训练参数"与 SIC-Agents 的"可编辑技能文档"有设计上的亲缘关系,但 SkillOpt 的优化器是固定的、评估基于任务正确性,且没有"课程指导"约束。在抑郁症场景中,SIC-Agents 的"人可编辑 + 课程指导"设计比 SkillOpt 的"自动优化"更安全。

## 4. 最终选择与理由总结

### 选择 1:[PsychAgent](https://github.com/ECNU-ICALK/PsychAgent) — 核心自进化架构

**角色**:提供"从会话轨迹到技能演化到模型内化"的完整闭环。

**选择理由**:
- 唯一将自改进机制明确用于心理咨询的工作
- 三层架构(记忆增强规划 + 技能演化 + 拒绝采样微调)给出了完整的闭环
- PsychEval 基准覆盖五种疗法、677 个元技能、4577 个原子技能,可作为初始技能库和 RL 环境
- 人评验证(522 段匹配对话中排第一,人-人 QWK 0.675)

**关键风险**:
- 代码自述"不含完整训练资产与完整的会后技能演化流水线"
- 面向通用成人咨询,无抑郁症专项验证
- 微调步骤使改进不可检视,需要用 SIC-Agents 的设计替代

### 选择 2:[SIC-Agents](https://arxiv.org/abs/2608.29481) — 安全设计与课程指导

**角色**:提供"可审计的技能文档自改进 + 领域课程指导"的安全框架。

**选择理由**:
- 可编辑技能文档是高风险场景中唯一可接受的自改进产物形式
- "去掉课程指导后关键行为退化"的消融结论,直接论证了抑郁症场景中课程约束的必要性
- 治疗师可直接阅读、修改、回滚技能文档
- EMNLP 2026 录用,设计经过同行评审

**关键风险**:
- 自改进系统代码未开源(仅基准仓库)
- 需要从"儿科沟通培训"迁移到"抑郁症治疗"
- PitfallBench 的设计逻辑需要用临床量表重建

### 选择 3:[GEPA](https://github.com/gepa-ai/gepa) — 优化引擎

**角色**:提供经过验证的反思式提示/技能优化引擎。

**选择理由**:
- ICLR 2026 Oral,575 fork,已内置 DSPy,工程成熟度最高
- 比 GRPO 少用 35 倍 rollout,适合心理治疗场景中"训练数据稀缺"的现实
- 已有在 Hermes Agent 上做技能/提示进化的落地先例
- 评估函数可定制,不限制评估来源

**关键风险**:
- 通用优化工具,需要自行设计评估函数
- 原始设计不包含"课程指导"约束
- 优化方向完全取决于评估函数的质量

### 三者的互补关系

```
PsychAgent:    提供"做什么"——咨询技能演化的完整架构与初始技能库
SIC-Agents:    提供"怎么做才安全"——可审计的技能文档 + 课程指导约束
GEPA:          提供"怎么做才高效"——经验证的优化引擎
```

## 5. 改造方案

### 5.1 总体架构

将三个基础工作的核心模块重组为一个面向抑郁症治疗的 RSI 系统,架构分五层:

**第一层:来访者状态层(来自 PsychAgent 的记忆引擎,借鉴 DeepTutor 的 trace forest)**
- 维护每位来访者的持久状态:PHQ-9 分数变化轨迹、症状谱、共病、用药、社会支持、治疗阶段、会话摘要
- 状态更新需要治疗师确认(不自动更新)
- 存储格式为结构化文本(YAML/Markdown),治疗师可读可编辑

**第二层:治疗技能文档层(来自 SIC-Agents 的可编辑技能文档)**
- 初始技能库从 PsychEval 的 677 个元技能中筛选与抑郁症相关的子集,并按 CBT/BA/IPT 的阶段结构组织
- 每个技能是一份文本文档,包含:适用情境、干预话术模板、预期来访者反应、禁忌(如"来访者提到自伤时不能使用认知挑战")
- 技能文档是自改进的**唯一产物**——不做权重微调

**第三层:课程指导层(来自 SIC-Agents 的 Coach 设计)**
- 定义抑郁症治疗的阶段性结构:
  - 第一阶段(1-3 次):建立治疗联盟、心理教育、行为激活入门
  - 第二阶段(4-8 次):认知重评、行为实验
  - 第三阶段(9-12 次):核心信念工作、复发预防
- 每个阶段定义"关键干预行为"和"禁忌行为"(等价于 SIC-Agents 的痛点 P1-P10)
- 课程指导约束自改进方向:**只有不降低"关键干预行为"得分的技能更新才被接受**

**第四层:反思式技能优化层(来自 GEPA 的优化引擎)**
- 输入:会话轨迹 + 来访者状态变化 + 治疗师评分
- GEPA 的反思模块分析轨迹,诊断哪些技能用得不好,提出技能文档的更新建议
- 更新建议经过两道门控:
  - **课程指导门控**:更新不能降低关键干预行为的得分(借鉴 SIC-Agents 的消融发现)
  - **留出验证门控**:更新后的技能在留出的评估会话上不能比更新前差(借鉴 SkillOpt/Recuris 的留出验证门)
- 通过两道门控后,更新建议以 diff 形式提交给治疗师审批

**第五层:治疗师审批层(来自 SIC-Agents 的人在回路设计)**
- 所有技能更新以可读 diff 形式呈现给治疗师
- 治疗师可以:接受、修改后接受、拒绝、标注原因
- 治疗师的修改和标注反馈给 GEPA 的反思模块,作为下一轮优化的上下文
- 保留完整的修改历史,支持回滚到任意版本

### 5.2 评估器设计(最关键的改造)

**这是整个系统成败的关键**。教育报告已证明"LLM 评审会偏向更长更流畅的回复,同时侵蚀关键行为"(SIC-Agents 消融)。在抑郁症治疗场景,评估器必须锚定在临床指标上。

设计方案:

| 评估维度 | 来源 | 权重 | 说明 |
|---|---|---|---|
| **来访者症状变化** | PHQ-9 / BDI-II 在两次会谈间的变化 | 30% | 最硬的指标;但变化缓慢,且受多因素影响,不能全归因于系统 |
| **治疗师对会话质量的评分** | 每次会话后治疗师打分(1-5,多维度) | 30% | 维度包括:治疗联盟、技能运用恰当性、安全风险管理、来访者参与度 |
| **关键干预行为覆盖** | 自动检测会话中是否出现当前阶段要求的关键干预行为 | 20% | 例如:第一阶段是否进行了心理教育;来访者表达无望感时是否验证了情绪 |
| **安全行为检测** | 自动检测是否触发了禁忌行为或遗漏了安全筛查 | 20% | 一票否决:如果遗漏自杀风险筛查,该轮得分归零 |

**不使用的评估方式**:
- 不用 LLM 自评打分(会偏向流畅性)
- 不用来访者满意度作为自改进信号(来访者可能偏好"安慰"而非"有效干预")
- 不用对话长度/轮数作为指标

### 5.3 技能演化的约束设计

借鉴 SIC-Agents 的消融发现和通用 RSI 报告中反复出现的"评估器被钻空子"问题,设计以下约束:

1. **红线技能不可被改写**:
   - 自杀风险评估与应对流程
   - 安全计划制定流程
   - 转介/急救触发条件
   - 这些技能由临床专家编写,标记为"锁定",自改进回路不可修改

2. **阶段约束**:
   - 每个治疗阶段有"必须包含"和"不能包含"的技能类型
   - 自改进不能把第三阶段的技能(如核心信念工作)提前到第一阶段

3. **漂移检测**:
   - 定期(每 N 次更新后)用固定的评估会话集测试技能文档
   - 如果关键干预行为得分持续下降(即使通用对话质量上升),回滚到上一个"关键行为得分不低于基线"的版本
   - 这直接来自 SIC-Agents 的消融发现:通用反馈能蒸馏出更流畅的系统,同时侵蚀关键行为

4. **更新频率限制**:
   - 技能文档不按每次会话更新,而是每 5-10 次会话汇总一次
   - 避免过度拟合单个来访者的偏好

### 5.4 与现有工作的差异

| 维度 | PsychAgent 原始设计 | 改造后的系统 |
|---|---|---|
| 自改进产物 | 技能库(文本) + 模型权重(微调) | 仅技能文档(文本),不微调权重 |
| 评估器 | PsychEval(LLM 评审 + 模拟来访者) | 临床量表 + 治疗师评分 + 关键行为检测 |
| 领域约束 | 无(通用五疗法) | CBT/BA/IPT 阶段结构 + 红线技能锁定 |
| 人在回路 | 无 | 治疗师审批所有技能更新 |
| 优化引擎 | 自研(从轨迹中抽取技能) | GEPA(反思式,Pareto 合并,高效率) |
| 安全 | 无特殊设计 | 自杀风险红线 + 漂移检测 + 回滚 |

### 5.5 落地路径建议

**不建议直接面向来访者部署**。建议的落地路径:

**Phase 0:技能库构建(无自改进)**
- 从 PsychEval 的技能库中筛选抑郁症相关技能
- 请临床心理学家审核和补充
- 按 CBT/BA/IPT 阶段组织,标注红线技能
- 产物:一份经过临床审核的初始技能文档集

**Phase 1:治疗师辅助模式(人在回路的自改进)**
- 系统辅助治疗师:在会话中实时建议可用的技能
- 会话后,GEPA 分析轨迹并提出技能文档更新建议
- 治疗师审批更新
- 用 PHQ-9 变化和治疗师评分作为评估信号
- **目标**:验证自改进回路是否能在不降低关键行为的前提下提升技能文档质量
- **规模**:5-10 名治疗师,50-100 次会话
- **参照标准**:与"无自改进的固定技能文档"做受控对比(借鉴 PAST-Bench 的"持久化开/关"设计)

**Phase 2:自助模式试点(有监督)**
- 对低风险来访者(PHQ-9 < 15,无自伤史),提供有监督的自助模式
- 治疗师定期审查会话记录和技能文档变化
- 紧急情况自动转人类
- **规模**:20-50 名来访者,随机分配到"自改进版"和"固定版"
- **主要结局**:PHQ-9 变化;**安全结局**:不良事件报告

**Phase 3:规模化(如果 Phase 2 安全且有效)**
- 才考虑更大规模的部署
- 此时的证据应该足以支持伦理委员会审查

### 5.6 实施中的已知挑战

1. **PsychAgent 的代码不完整**:仓库自述"不含完整训练资产与完整的会后技能演化流水线"。这意味着核心的技能演化模块需要重新实现。好消息是论文描述了机制,且 PsychEval 的数据和评估代码是开放的。

2. **SIC-Agents 的代码未开源**:只有基准仓库。需要根据论文描述重新实现技能文档的编辑器和课程指导模块。论文对机制的描述足够详细,且消融实验的设计可以直接复用。

3. **评估器的冷启动**:系统上线初期没有足够的"来访者症状变化"数据来训练评估器。Phase 1 的治疗师评分可以作为替代信号;关键干预行为的检测可以用规则 + LLM(但只用于检测行为是否出现,不用于评估质量)。

4. **隐私与伦理**:会话轨迹是自改进回路的"训练数据"。需要:知情同意(明确告知系统会从对话中学习)、数据最小化(技能文档只保留抽象化的技能描述,不保留原始对话)、伦理委员会审查。

5. **PsychEval 的来访者年龄构成未知**:教育报告指出"来访者年龄分布未核实"。如果 PsychEval 的来访者画像偏向年轻成人,其技能库可能不适用于老年抑郁症患者。需要核实。

## 6. 与纯用 PsychAgent/PsyEvo 的区别

如果只用 PsychAgent 作为基础,不引入 SIC-Agents 和 GEPA,会有三个问题:

1. **安全性不足**:PsychAgent 的自改进产物包含权重微调,不可检视;没有课程指导约束,优化方向可能偏离疗法框架;没有"关键行为退化检测"。SIC-Agents 的消融结论(**通用反馈提升流畅性同时侵蚀关键行为**)在这里尤为重要——抑郁症治疗中的"关键行为"可能是"在来访者提到自伤时停下共情,进入安全评估",如果自改进把这个行为优化掉了,后果不堪设想。

2. **优化效率低**:PsychAgent 的技能演化引擎是从历史轨迹中抽取技能,没有反思式的诊断与合并。GEPA 的"反思执行轨迹 → 诊断问题 → 提出更新 → Pareto 合并"的流程更高效,且已在大规模场景中验证。在心理治疗场景,训练数据(会话)稀缺且昂贵(每次会话 45-60 分钟),效率很重要。

3. **缺乏人在回路**:PsychAgent 的设计中没有治疗师审批环节。在有真实用户的抑郁症治疗场景中,这是不可接受的。

引入 SIC-Agents 和 GEPA 正是为了弥补这三个缺陷,同时保留 PsychAgent 的核心架构优势。

---

## 7. 未核实与不确定项

- PsychEval 来访者画像的年龄构成(是否覆盖抑郁症的各年龄段)
- PsychAgent 代码中已实现部分的可用性(论文与代码的差距)
- SIC-Agents 论文中"专家提示 0.85 对种子 0.75"与"完整系统 0.78"的指标口径是否一致
- GEPA 的反思模块在心理治疗轨迹(而非编程/数学任务轨迹)上的效果——目前没有任何证据
- 上述评估器设计(PHQ-9 变化 + 治疗师评分 + 关键行为检测 + 安全检测)的权重是否合理——需要临床心理学家参与设定
- 本方案的伦理审查要求——不同地区/机构的伦理委员会标准不同

## 9. 一句话总结

选 **PsychAgent**(咨询技能演化架构)+ **SIC-Agents**(可审计技能文档与课程指导)+ **GEPA**(高效优化引擎),三者分别解决"做什么"、"怎么安全"、"怎么高效"的问题。核心改造是:**放弃权重微调,只改技能文档;评估器锚定临床量表而非 LLM 自评;所有更新经治疗师审批**。
